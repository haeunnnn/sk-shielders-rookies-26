4. **Media Translation** 방법으로 수신지로 트래픽 전송

#### ARP (Address Resolution Protocol)

- IP 주소에 대응되는 MAC 주소를 조회하고 변환해주는 프로토콜
- 네트워크 계층(3계층)의 IP 주소를 데이터 링크 계층(2계층)의 MAC 주소로 매핑

**ARP 패킷 종류**
- **ARP Request**
  - 송신자가 수신자의 MAC 주소를 알기 위해 네트워크 전체에 브로드캐스트로 전송
  - 목적지 MAC: `FF:FF:FF:FF:FF:FF`
- **ARP Reply**
  - 수신자가 자신의 MAC 주소를 알려주는 응답 패킷
  - 유니캐스트 방식으로 송신자에게만 전송

**ARP Cache Table**
- IP ↔ MAC 대응 정보를 일시적으로 저장하는 테이블
- OS에 따라 일정 시간 후 만료됨
- 확인 명령어: `arp -a`

#### Media Translation (미디어 변환)

- 수행 계층: **3계층 이상 장비(Router 등)**
- 역할: 서로 다른 네트워크 간의 **프레임 헤더(L2)**를 변환
- IP 주소는 그대로 유지되지만, **MAC 주소는 경로를 거칠 때마다 변경됨**
  - 이유: 각 네트워크의 송수신 장비(NIC)가 다르기 때문
- Switch는 단순히 MAC 기반 전송, Router는 MAC 재작성 포함

#### TCP/IP Protocol Stack

``` text
┌────────────────────────────────────────────────┐
│ Application Layer                              │
│ ────────────────────────────────────────────── │

└────────────────────────────────────────────────┘
│ Transport Layer                                │
│ ────────────────────────────────────────────── │
│ TCP, UDP                                       │
│ 종단 간 연결, 흐름 제어, 오류 제어              │
└────────────────────────────────────────────────┘
│ Internet Layer                                 │
│ ────────────────────────────────────────────── │
│ IP, ICMP, IGMP, ARP                            │

└────────────────────────────────────────────────┘
│ Network Access Layer                           │
│ ────────────────────────────────────────────── │
│ Ethernet, Wi-Fi, PPP, MAC, Frame, Bits         │
│ 물리 매체, MAC 주소, 프레임 전송                │
└────────────────────────────────────────────────┘
```

### 6. TCP, UDP, IP

#### TCP Header
- 20 ~ 60 Bytes (가변 길이)

| 필드 | 설명 |
| --- | ---- |
| **Source Port / Destination Port** | 송/수신 측 포트 번호 |
| **Sequence Number** | 전송할 데이터의 시작 바이트 번호 |
| **Acknowledgment Number** | 수신 확인된 다음 바이트 번호 (Sequence Number + Data Length) |
| **Data Offset** | 헤더 길이 (4비트, 단위: 32비트 word) |
| **Flags** | 연결 관리 및 제어 비트 (SYN, ACK, FIN 등) |
| **Window Size** | 수신자가 허용 가능한 버퍼 크기 (흐름 제어용) |
| **Checksum** | 헤더 + 데이터에 대한 오류 검출 |
| **Urgent Pointer** | 긴급 데이터의 끝 위치 (URG 플래그와 함께 사용) |
| **Options** | MSS, Window Scale, Timestamps 등 확장 기능 |

#### TCP 3-way handshake

``` text
               [Client]                                  [Server]
                  |                                          |
1 Closed          |                                          |     Listen
                  |                                          |
2 SYN Sent        |  ------------ SYN (seq=x) ------------>  |     
                  |                                          |     SYN Received
                  |  <----- SYN+ACK (seq=y, ack=x+1) ------  |     
                  |                                          |
3 Established     |  ----------- ACK (ack=y+1) ----------->  |     
                  |                                          |     Established
```

1. `SYN` : 클라이언트가 서버에게 연결을 요청 (시작 시퀀스 번호 `x`)
2. `SYN + ACK` : 서버가 클라이언트의 요청을 수락하며 자신도 연결 요청 (`seq = y, ack = x + 1`)
3. `ACK` : 클라이언트가 서버의 응답을 확인 (`ack = y + 1`)

#### UDP Header
- 8 Bytes (고정 길이)

| 필드 이름 | 크기 (bit) | 설명 |
| -------- | --------- | ---- |
| Source Port Address | 16 bit | 수신지 포트 번호 |
| Destination Port Address | 16 bit | 발신지 포트 번호 |
| Checksum | 16 bit | 
| Urgent Pointer | 16 bit |

#### IP Header
- 20 ~ 60 Bytes (가변 길이)

| 필드 이름 | 크기 (bit) | 설명 |
| -------- | --------- | ---- |
| **Version** | 4 | IP 버전 (IPv4는 4) |
| **IHL (Header Length)** | 4 | IP 헤더 길이 (단위: 4바이트), 기본값 5 (20바이트) |
| **Type of Service (ToS)** | 8 | 서비스 우선순위, 지연/처리 요구도 표시 (현재는 DSCP/ECN으로 사용됨) |
| **Total Length** | 16 | IP 헤더 + 데이터 전체 길이 (최대 65,535 바이트) |
| **Identification** | 16 | 조각화된 패킷을 재조합하기 위한 식별자 |
| **Flags** | 3 | 조각화 제어 플래그 (DF: Don't Fragment, MF: More Fragment) |
| **Fragment Offset** | 13 | 조각화된 데이터의 상대 위치 |
| **Time To Live (TTL)** | 8 | 패킷 생존 시간 (라우터 통과 시 감소, 0이면 폐기) |
| **Protocol** | 8 | 상위 계층 프로토콜 식별 (TCP: 6, UDP: 17 등) |
| **Header Checksum** | 16 | IP 헤더 오류 검출용 체크섬 |
| **Source IP Address** | 32 | 발신자의 IP 주소 |
| **Destination IP Address** | 32 | 수신자의 IP 주소 |
| **Options (선택)** | 가변 | 보안, 경로 지정 등 특수 기능 (사용 안 되는 경우가 많음) |
| **Padding** | 가변 | 4바이트 정렬을 위한 채움 값 |

#### MTU(Maximum Transfer Unit)
- 한 번에 전송할 수 있는 최대 Layer 2 프레임(데이터 링크 계층)의 데이터 크기
- IP 패킷(헤더 + 데이터)은 MTU보다 클 경우 조각화(Fragmentation) 되어 전송
- MTU는 헤더를 포함한 전체 프레임 크기가 아니라, 전송 가능한 "데이터(payload)"의 최대 크기
- 기본 MTU 값 : 이더넷 기준 1500바이트 (기본값, IP 헤더 20바이트 포함 시 실제 데이터는 1480바이트)
- `DF` 비트 : Don't Fragment. 설정되면 조각화를 금지함. MTU보다 크면 라우터가 폐기하고 ICMP 오류 반환.
- MTU 설정 문제
    - MTU 설정이 잘못되면 조각화로 인한 성능 저하 발생 가능
    - 특히 VPN, GRE 터널, ICMP 차단 시 MTU 미스매치로 인해 "응답 없음", "연결 끊김" 현상 발생 가능

#### 조각화(Fragmentation)
- MTU보다 큰 IP 패킷은 조각으로 나눠 전송
- IP 헤더의 `Identification`/`Offset`/`Flags` 사용

| 항목 | TCP | UDP | IP |
| ---- | ---- | ---- | --- |
| **계층** | 전송 계층 (4계층) | 전송 계층 (4계층) | 네트워크 계층 (3계층) |
| **연결 방식** | 연결지향 (Connection-Oriented) | 비연결지향 (Connectionless) | 비연결지향 |
| **신뢰성 보장** | O (수신 확인, 재전송) | X (확인 없음, 재전송 없음) | X (IP 패킷 자체는 신뢰성 없음) |
| **흐름 제어** | O (윈도우 크기 조절) | X | X |
| **오류 제어** | O (체크섬 + 재전송) | X (체크섬만 있음, 재전송 X) | O (체크섬 있음, 재전송 X) |
| **전송 방향** | 양방향 (Full Duplex) | 단방향 또는 제한적 양방향 | 단방향 (Hop-by-hop) |
| **속도** | 느림 (신뢰성 확보로 인한 오버헤드) | 빠름 (단순 구조, 실시간 전송 적합)  | 빠름 |
| **대표 용도** | 웹(HTTP), 이메일(SMTP), 파일 전송(FTP), SSH 등 | 스트리밍, VoIP, 게임, 방송 등 | 모든 IP 기반 통신의 라우팅 및 전달 |
| **데이터 단위(PDU)** | Segment | Datagram | Packet |
| **연결 설정** | 3-Way Handshake 필요 | 없음 | 없음 |
| **단편화 여부** | 자체적으로는 하지 않음 | 자체적으로는 하지 않음 | O (MTU 초과 시 조각화) |
| **주소 정보** | 포트 번호 + IP 주소 | 포트 번호 + IP 주소 | IP 주소만 사용 |

#### L3 vs L4 단편화 비교

**3계층(IP 계층) 단편화**
- IP 계층에서 패킷이 MTU보다 크면 조각화 수행
    - `MSS > Payload`인 경우, L4에서 단편화 X → L3에서 단편화
    - `MSS < Payload`인 경우, L4에서 단편화 O
- 조각화 시 다음 필드를 사용
    - `Identification`: 조각끼리 같은 패킷임을 나타냄
    - `Fragment Offset`: 데이터 위치
    - `MF (More Fragment) Flag`: 마지막 조각 여부
- 수신 측 재조립 시 복잡 → 순서 재조합, 유실/중복 체크 필요

**4계층(TCP 계층) 단편화**
- 송신자가 TCP 전송 단위(MSS)를 고려해 미리 데이터를 나눔
- 조각화 대신 시퀀스 번호 기반으로 수신 측이 재조립
- 3계층보다 안정적이고 효율적 → 성능 및 지연 최소화
- 단, TCP에서만 가능 (UDP 등은 자체 분할 불가)

### 7. ICMP (Internet Control Message Protocol)

#### ICMP 헤더 구조

| 필드 | 설명 |
| --- | ---- |
| Type | 메시지의 종류 (예: 8 = Echo Request) |
| Code | 세부 유형 (예: 목적지 도달 불가의 이유) |
| Checksum | 오류 검출용 필드 |
| Rest of Header | 각 메시지 종류별 세부 필드 포함 |

#### Ethernet Frame 헤더 필드

| 필드 | 설명 |
| --- | ---- |
| Destination MAC | 수신 측 MAC 주소 |
| Source MAC | 송신 측 MAC 주소 |
| EtherType / Length | 상위 계층 구분 (IPv4: 0x0800 등) |

| 필드 | 설명 |
| --- | ---- |
| Hardware Type | Ethernet(=1) |
| Protocol Type | IPv4(=0x0800) |
| Operation | 1=Request, 2=Reply |
| Sender MAC/IP, Target MAC/IP 포함 | |

### 8. ARP (Address Resolution Protocol)

#### ARP 동작 절차
1. **ARP Request** : 브로드캐스트 방식으로 송신
2. 수신자가 본인 IP와 일치 시 → **ARP Reply**로 응답 (Unicast)
3. 송신자는 응답의 MAC 주소를 **ARP Cache Table**에 등록
4. 이후 동일 목적지 통신 시에는 ARP 생략 가능

#### ARP Cache Table 갱신 과정
1. 수신된 Ethernet Frame의 **MAC 주소** 확인
2. **역캡슐화** → IP 헤더 분석
3. ARP Cache Table에서 해당 IP 주소 유무 확인
4. 없으면 새로 추가
5. 필요 시 ARP Reply 전송

#### ARP 취약점
- **스푸핑 공격** 가능 (ARP Reply를 위조해 MAC 주소를 속임)
- 보안 보완 필요 → 동적 ARP 검사 (DAI), 정적 MAC 설정 등

### 10. 보안 솔루션

| 구분 | 주요 기능 | 목적 | 동작 방식 | 일반적 배치 위치 | 장점 | 단점 |
| --- | -------- | --- | -------- | -------------- | --- | --- |
| **방화벽** | 트래픽 필터링 (IP, 포트, 프로토콜 기반)      | 인가되지 않은 접근 차단 | 패킷 수준에서 허용/차단            | 외부 ↔ 내부 경계, DMZ 앞단 | 구성 및 운영이 간단, 기본적인 접근제어 제공    | 애플리케이션 계층 공격 탐지 불가            |
| **IDS** | 침입 탐지 (시그니처/이상 행위 기반 탐지)       | 의심스러운 트래픽 탐지  | 비활성 모드(모니터링 전용)          | 내부망 또는 DMZ         | 탐지 정확도 높음, 네트워크 가시성 확보       | 차단 기능 없음 (탐지 전용), 오탐 가능성 있음   |
| **IPS** | 침입 방지 (IDS + 실시간 차단)           | 공격 차단         | 인라인 처리 (패킷 검사 후 차단 가능)   | 방화벽과 함께 배치         | 실시간 차단 가능, 자동 대응             | 성능 저하 가능, 잘못 차단 시 서비스 영향      |
| **WAF** | 웹 애플리케이션 보호 (SQLi, XSS 등 방지)   | 웹 기반 공격 차단    | HTTP/HTTPS 트래픽 분석 및 필터링  | 웹 서버 앞단 (DMZ 등)    | 웹 취약점 대응, OWASP Top 10 방어 가능 | 비웹 트래픽 보호 불가, 튜닝 필요           |
| **NAC** | 네트워크 접속 제어 (인증, 상태 점검)         | 비인가 단말 차단     | 접속 시 인증/검사 후 허용          | 내부망 입구 (스위치, AP 등) | 내부 보안 강화, BYOD 환경 대응         | 초기 구축 복잡, 관리 정책 수립 필요         |
| **VPN** | 암호화된 통신 터널 제공                  | 안전한 원격 접속     | 터널링 및 암호화 (IPSec, SSL 등) | 외부 사용자 ↔ 내부망 사이    | 데이터 보안성 확보, 외부 접속 가능         | 설정 오류 시 취약, 성능 저하 가능          |
| **UTM** | 통합 보안 솔루션 (방화벽+IPS+AV 등 복합 기능) | 보안 관리 통합      | 다양한 기능 모듈 통합             | 게이트웨이 위치           | 관리 편의성, 비용 절감                | 단일 장애점(SPOF), 고성능 환경에선 부적합 가능 |

### 11. 네트워크 공격

| 공격 유형 | 공격 기법 설명 | 주요 대상 | 특징 | 대표 피해 사례 | 방어 방법 |
| ------- | ------------- | -------- | --- | ------------ | ------- |
| **DoS/DDoS**     | 대량의 트래픽으로 서버 과부하 유발      | 서버, 네트워크 장비   | 서비스 마비, 단순하지만 강력함              | 웹 서버 마비, DNS 서버 중단 | 트래픽 필터링, WAF, CDN, 공격자 IP 차단 등  |
| **ARP Spoofing** | 가짜 MAC 주소를 ARP 응답으로 전송   | 동일 네트워크 내 PC  | Man-in-the-Middle(MITM)로 악용 가능 | 통신 가로채기, 세션 탈취     | 정적 ARP 설정, 스위치 보안 설정, ARP 검사 도입 |
| **DNS Spoofing** | 위조된 DNS 응답을 피해자에게 먼저 전달  | 클라이언트, DNS 서버 | 사용자를 가짜 사이트로 유도                | 피싱, 악성코드 사이트로 유도   | DNSSEC, 신뢰할 수 있는 DNS 사용, 패킷 감시  |
| **IP Spoofing**  | 출발지 IP를 위조해 신뢰받는 사용자로 위장 | 서버, 클라이언트     | 소스 IP 위조로 방화벽 우회 가능            | DDoS 증폭 공격에 악용     | ingress 필터링, 인증 절차 강화           |
| **MITM**         | 송수신자 사이에서 통신 가로채기        | 사용자 ↔ 서버 간 통신 | 데이터 도청, 변조 가능                  | 로그인 정보 탈취, 세션 하이재킹 | HTTPS 사용, VPN, 인증서 검증           |
| **포트 스캐닝**       | 열려있는 포트를 스캔하여 취약점 탐색     | 서버, 네트워크 장비   | 사전 정찰 단계에서 활용                  | 특정 포트 대상 공격        | 포트 차단, IDS 탐지, 포트 접근 로그 분석      |
| **세션 하이재킹**      | 세션 ID를 탈취하거나 가로채 세션 탈취   | 사용자 세션        | 로그인 유지 중 공격자가 세션 탈취            | 사용자로 위장한 악의적 행위    | 세션 만료 관리, HTTPS, 쿠키 보안 설정       |
| **스니핑**          | 네트워크를 통과하는 패킷 감청         | 패킷 기반 통신      | 민감 정보(비밀번호 등) 노출 가능            | 이메일, 비밀번호 유출       | 암호화(HTTPS, VPN), 스위치 환경 구성      |
| **피싱**           | 사용자에게 가짜 사이트/이메일 제공      | 사용자           | 사회공학 기반, 사람 심리 이용              | 금융 정보 탈취, 계정 탈취    | 사용자 교육, 이메일 필터링, 다중 인증          |
| **악성코드 전파**      | 트로이 목마, 웜, 바이러스 등을 통한 감염 | 모든 시스템        | 감염 시도 자동 확산 가능                 | 랜섬웨어 감염, 시스템 마비    | 백신 설치, 다운로드 경로 통제, 보안 업데이트      |
