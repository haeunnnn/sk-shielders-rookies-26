## 🧠 주요 개념 정리

### 1. 배경

#### 딥러닝의 초기 한계

- 고정된 입력 크기만 처리 가능
- 이미지나 텍스트와 같은 복잡한 구조 데이터 처리에 부적합
- 비선형/복잡한 패턴 학습 부족
- 과적합, 기울기 소멸, 연산량 증가 등의 문제

#### 심층 신경망 (DNN)

- 다수의 은닉층을 통해 표현력 강화
- 비선형 관계 학습 가능
- Representation Learning 자동 수행
- 다양한 도메인 문제에 활용 가능

### 2. CNN (합성곱 신경망)

- **이미지 데이터**의 공간적 구조와 특징 학습에 최적화된 딥러닝 구조

#### 특징
- 지역 연결(Local Connectivity)
- 가중치 공유(Weight Sharing)
- 공간 불변성(Spatial Invariance)

#### 적용 분야
- 이미지 분류, 객체 탐지, 얼굴 인식, 의료 영상 분석 등

#### 주요 구성 요소
1. **Convolution Layer(합성곱 층)**: 필터를 사용해 이미지의 특정 패턴을 추출  
2. **Activation Function(활성화 함순)**: 음수 제거, 비선형성 추가  
3. **Pooling Layer(풀링 층)**: 데이터 크기 축소 및 과적합 방지  
4. **Fully Connected Layer(완결 연결 층)**: 추출된 특징으로 최종 분류 수행

#### CNN 동작 방식

| 단계 | 설명 |
|------|------|
| 입력 | 이미지 (ex. MNIST: 28×28, RGB: 224×224×3 등) |
| 합성곱 층 | 작은 필터가 특징을 추출 (ex. 선, 모서리) |
| 활성화 함수 | ReLU 사용 – 음수 제거 및 비선형성 확보 |
| 풀링 층 | MaxPooling 등으로 데이터 차원 축소 |
| 완전 연결 층 | 특징을 기반으로 클래스 확률 출력 |
| 출력층 | Softmax 등으로 최종 확률 계산 |

#### 예시 흐름
1. 고양이 이미지 입력
2. 필터가 귀, 눈 등 특징 추출
3. ReLU로 양수 값 유지
4. Max Pooling으로 특징 유지한 채 크기 축소
5. FC Layer에서 "고양이일 확률 90%" 출력

### 3. RNN (순환 신경망)

- **시간적 순서/문맥** 정보가 중요한 데이터를 위한 신경망 구조

#### 특징
- 이전 상태(hidden state)를 현재 입력과 함께 활용
- 반복 구조를 통해 시퀀스 데이터를 순차적으로 처리
- 텍스트, 음성, 시계열 등 시간 의존성 높은 분야에 적합

#### 한계와 개선
- 기본 RNN은 긴 시퀀스에서 **기울기 소멸** 발생 → 학습 어려움  
→ **LSTM**(Long Short-Term Memory), **GRU**(Gated Recurrent Unit)로 개선

#### 적용 분야
- 자연어 처리 (NLP)
- 음성 인식
- 시계열 예측
- 기계 번역, 텍스트 생성

### 1. OpenAI와 API 개요

- OpenAI는 GPT 시리즈를 포함한 다양한 AI 모델을 개발한 기업
- GPT-4는 뛰어난 추론력과 다양한 과업 처리 능력을 가진 최신 언어 모델
- API를 통해 다양한 GPT 모델을 호출할 수 있으며, 2023년 6월부터 Function Calling 기능이 추가됨

### 2. Chat Completions API 구조

- 대화는 메시지 리스트로 구성되며 각 메시지에는 역할(role)이 명시됨
  - **system**: 모델에게 지침을 주는 시스템 메시지
  - **user**: 사용자 입력
  - **assistant**: 모델이 생성한 응답
- 역할의 구분은 맥락 유지에 필수적이며, system 메시지를 통해 응답 톤 및 스타일 설정 가능

### 3. 메시지 우선순위 (input 설정)

| developer | user | assistant |
|-----------|------|-----------|
| 시스템 규칙 및 로직 | 사용자 질문 및 요청 | 모델이 생성한 응답 |

- developer 메시지는 함수 정의와 같고, user 메시지는 그 함수의 인자처럼 작동
- 프롬프트 재사용 기능을 통해 대시보드에서 설정한 템플릿을 API에서 호출 가능

### 4. Function Calling

#### 등장 배경

- 기존 GPT 응답은 텍스트 출력만 가능
- 구조화된 데이터 반환, 외부 API 호출 등의 처리가 어려웠음
- Function Calling은 JSON 형태로 외부 시스템과 직접 연동 가능하도록 개선

#### 동작 흐름

1. 사용자 메시지와 호출 가능한 함수 목록을 모델에 전달
2. 모델이 함수 호출이 필요하다고 판단 시 호출 요청 반환
3. 애플리케이션이 실제 함수를 실행하고 결과를 모델에 전달
4. 모델이 최종 응답 생성

#### 활용 효과

- 자연어를 코드 실행/데이터 호출로 직접 연결
- 룰 엔진 없이 신뢰성 높은 자동화 가능
- 별도 파인튜닝 없이도 기능 확장 가능
- 모델은 요청만 생성하고 실제 실행은 애플리케이션이 처리

### 5. 도구(Tools) 사용 개요

- 도구는 Function Calling 외에도 웹 검색, 파일 검색 등 다양한 기능 포함
- API 요청 시 `tools` 배열과 `tool_choice` 매개변수를 통해 구성
- 도구 사용 여부는 프롬프트 내용과 설정에 따라 자동 또는 명시적으로 제어 가능

#### 주요 도구

- **함수 호출**: 사용자 정의 함수 호출
- **웹 검색**: 최신 정보 검색 후 응답 생성
- **파일 검색**: 업로드된 문서에서 의미 기반 정보 검색
- **이미지 생성**, **코드 인터프리터**, **컴퓨터 사용** 등
