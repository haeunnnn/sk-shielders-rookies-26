## 🧠 보안관제의 이해 정리

### 1. 보안관제의 개념과 중요성

#### 개념 설명
보안관제란 정보통신망 및 정보시스템에서 발생하는 사이버 공격 및 위협 이벤트를 **24시간 365일 모니터링 → 탐지 → 분석 → 대응**하는 활동.

#### 관련 예시
- LG U+ 해킹 사례(2023) : AI 기반 감시체계 부재로 피해 발생 → 보안관제 체계 필요성 강조.

#### 보안관제 목표 (CIA 보장)
- **기밀성**: 비인가자 정보 유출 방지
- **무결성**: 데이터 변조·삭제 방지
- **가용성**: 정상 접근·사용 보장

#### 보안관제 주요 활동

| 활동 | 설명 | 예시 |
| --- | ---- | --- |
| 탐지 | 공격 시도·보안 위협 실시간 탐지 | 해킹, 웜, 트로이목마, 스니핑 |
| 분석 | 이벤트·로그·증거 기반 공격자·방법·피해 규모 파악 | 공격 시간·경로 분석 |
| 대응 | 정상 운영 복구, 기술지원, 사고보고 | 공격도구 역분석, 재발 방지 |

#### 보안관제 기본 원칙
- 무중단성 (24/7 가동)
- 전문성 (전문 인력·시설 필요)
- 정보공유 (확산 방지 위해 공유)

#### 주의사항
- 인권·사생활 침해 가능 → 관계법령 준수 필요

### 2. 국가 사이버안보 수행체계

#### 개념 설명
대통령·국가안보실 중심으로 국가정보원, 국방부, 과학기술정보통신부 등이 분야별 수행.

#### 관련 예시
- 국가사이버위기경보 : 관심(Blue), 주의(Yellow), 경계(Orange), 심각(Red) 4단계

#### 하위 개념

- **사이버 위기경보 단계**

| 단계 | 특징 |
| --- | ----- |
| 정상 | 위험 없음, 일상적 운영 |
| 관심 | 저위험 웜·바이러스 탐지 |
| 주의 | 공격 시도 증가, 유입 우려 |
| 경계 | 다수 기관 침해사고 확산 |
| 심각 | 전국적 피해, 국가 차원 대응 필요 |

- **주요 기관 역할**
    - 국가정보원 : 국가·공공
    - 국방부 : 국방 영역
    - 과기정통부 : 민간 영역

### 3. 우리나라의 보안관제 법·제도와 전문기업

#### 개념 설명
법령 기반으로 공공/국방/민간 영역별 보안관제 체계 구축 + 전문기업 지정 제도.

#### 관련 법령
- 국가·공공 : 사이버안보 업무규정, 국가사이버안전관리규정
- 국방 : 국방정보화법 → 국방정보보호대응체계 구축
- 민간 : 정보통신망법 → KISA 설립

#### 보안관제 전문기업 지정 제도

| 심사 기준 | 세부 요건 |
| -------- | ------- |
| 인력 | 15명 이상(고급 3, 중급 6) |
| 자본 | 20억 이상 |
| 수행능력 | 실적·전문성·신뢰도 평가 70점 이상 |

#### 주요 지정 기업 예시
- 안랩, 이글루시큐리티, SK쉴더스, 삼성SDS, LG CNS, 금융보안원 등

### 4. 보안운영센터(SOC)와 정보공유·분석센터(ISAC)

#### SOC(Security Operations Center)
- 보안관제센터라고도 함.
- 보안관제 + 침해사고 분석 + 취약점 진단 + 대응 수행.
- **국가 SOC** : 국가사이버안보센터 (국정원)
- **국방 SOC** : 국방사이버지휘통제센터 (합참/사이버작전사)
- **민간 SOC** : KISA 침해사고대응센터

#### ISAC (Information Sharing & Analysis Center)
- 분야별 공동 대응 체계.
- 장점: 개별 대응보다 효율적, 실시간 정보공유 가능.
- 주요 ISAC : 정보통신, 금융, 의료, 지자체, 방산

## 🧠 보안관제 거버넌스와 방법론 정리
> “보안관제를 어떻게 조직적으로 운영할지(거버넌스) → 어떤 방식으로 수행할지(유형·조직) → 어떤 절차로 할지(방법론) → 어떤 기준을 따를지(프레임워크)”

### 1. 보안관제 거버넌스의 이해

#### 개념 설명
거버넌스란 조직이 목표 달성을 위해 의사결정·관리·통제하는 체계. 보안관제 거버넌스는 보안관제 의사결정 구조와 운영을 의미.

#### 관련 예시
- ESG 경영에서 G(Governance), 정보보호 GRC(Governance·Risk·Compliance)

#### 하위 개념
- **필요성**
    - **위험 관리**: 사이버보안 위험 식별·평가·대응 기반
    - **일관된 정책**: 프로세스/정책 체계화
    - **책임·투명성**: 역할 분담, 대응 신뢰성 확보
    - **법·규제 준수**: 법적 요구사항 충족
- **수행 방식과 영향**
    - 24/7 보안관제는 이상적이지만 인력·비용 부담 → 조직 규모·자원에 맞는 수행 방식 선택 필요

### 2. 보안관제 유형과 보안운영 조직

- **유형 분류**

| 구분 | 설명 | 특징 |
| --- | --- | ---- |
| 자체(인하우스) | 자체 시설·인력으로 수행 | 기밀성·맞춤 대응 ↑, 비용·인력 부담 ↑ |
| 외주(아웃소싱) | 전문업체 활용 | 비용 효율 ↑, 데이터 유출·맞춤화 ↓ |

- **외주 방식**
    - **파견형**: 시설은 내부, 인력은 외부 파견
    - **원격형**: 외부 시설과 인력 모두 활용
- **조직 구성 (SOC)**
    - **CISO**: 최고 정보보호 책임자
    - **SOC 센터장**: 운영 관리
    - **보안관제팀**: 24시간 모니터링
    - **침해사고 조사팀**: 사고 원인 규명
    - **악성코드 분석팀**: 샘플 분석·포렌식
    - **취약점 진단/모의해킹팀**: 취약점 식별
    - **기술지원/운영팀**: 시스템 유지·운영

### 3. 보안관제 방법론과 프로세스

#### 주요 활동
- 기본: 탐지 → 분석 → 대응
- 확장: **예방 → 탐지 → 분석 → 대응 → 보고 → 정보수집·분석·공유 + 기술지원·운영**

#### 확장된 활동 세부
- **예방**: 자산 식별, 취약점 진단, 모의해킹, 보안 패치
- **탐지**: 위협 이벤트, 장애 이벤트, 관리 이벤트 탐지
- **분석**: 초기 분석, 침해사고 조사, 악성코드 분석
- **대응**: 상황전파, 인터뷰, 차단·격리, 복구, 정책개발
- **보고**: 조직 내 보고, 기관 신고, 공지, CTI 공유
- **정보수집/분석/공유**: 내부·외부 위협 헌팅, CTI 공유
- **기술지원·운영**: 도구·인프라 관리, 시스템 유지

#### 프로세스 흐름

`관제 → 조사 → 분석 → (이관 필요 시) 이관 → 종결`

### 4. 보안관제 관련 프레임워크

#### 필요성
표준 프레임워크를 기반으로 보안관제 방법론 개발·활용 (보안관제 전문기업 지정 요건 포함)

#### 주요 프레임워크

1. **NIST CSF**
- v1.x: Identify, Protect, Detect, Respond, Recover
- v2.0: + Govern(거버넌스) 추가
- 조직 전체 보안 프로세스 구조화에 활용

2. **MITRE ATT&CK**
- 공격자 관점 지식 기반 (전술·기술·절차, TTP)
- 공격자 행동 예측 및 탐지·대응 전략 개발

3. **MITRE D3FEND**
- 방어자 관점 지식 기반
- 방어 기술 선택·구현 지침 제공, 방어 전략 강화

## 🧠 보안관제시스템과 정보보호시스템 정리
> “보안관제시스템의 발전(1세대→AI) → 정보보호시스템 종류와 인증 → 로그 관리 → ESM·SIEM 비교 → 가시화/시각화 기법”

### 1. 보안관제시스템의 이해

#### 개념 설명
보안관제 업무를 지원하는 시스템으로 **수집 → 분석 → 가시화/시각화** 기능을 통합 제공.
내부 위협 모니터링, 컴플라이언스 준수 여부 모니터링에도 활용.

#### 관련 예시
보안관제사는 개별 시스템(방화벽, IDS 등)을 각각 보지 않고 **통합된 화면**에서 확인 가능 → 업무 효율 ↑

#### 세대 구분

| 세대 | 특징 | 한계/발전 |
| --- | ---- | ------- |
| 1세대 단위보안관제 | 개별 장비/시스템 직접 모니터링 | 규모·복잡성 증가 시 한계 |
| 2세대 통합보안관제 | ESM 활용, 로그 통합 수집/분석 | APT·미지 위협 탐지 한계 |
| 3세대 빅데이터보안관제 | SIEM 기반, 대용량 로그 분석/시각화 | 이상행위 탐지 가능 |
| 4세대 인공지능보안관제 | **SIEM + SOAR**, AI 기반 이상탐지·자동화 대응 | 능동적 대응 가능 |

- **효용 사례**
    - 한국과학기술정보연구원(KISTI) : 사이버 공격 실시간 추적·가시화 시스템

### 2. 정보보호시스템의 이해

#### 개념 설명
정보 접근통제, 사이버공격 탐지·차단, 로그 기록을 수행하는 어플라이언스 또는 소프트웨어. (네트워크 경계 보호 + 호스트 보호)

#### 관련 예시
- 부산 조선기자재 업체 랜섬웨어 피해 → 뒤늦게 방화벽 도입

#### 네트워크 정보보호시스템
- 방화벽(FW), IDS, IPS
- NAC (내부 장치 접근통제)
- WAF (웹 방화벽, SQL Injection·XSS 방어)
- UTM (방화벽+IDPS+WAF 통합 장비)
- WIPS (무선 침입 방지)
- NDR (모든 트래픽 저장·재현·분석)

#### 호스트 정보보호시스템
- A/V (안티바이러스)
- 호스트 방화벽
- DLP (자료유출방지: USB/프린터 통제, 워터마크)
- DRM (디지털저작권관리: 파일 암호화·복호화 승인 필요)
- EDR (Endpoint Detection & Response: 모든 이벤트 모니터링, 저장 공간 부담)

#### 인증·평가 제도

| 제도 | 주관 | 설명 |
| --- | ----- | -- |
| CC 평가·인증 | 과기정통부 | 국제 CC 기준 적용, 국내용 별도 운영 |
| 성능평가     | 과기정통부 | 성능 위주 평가 (트래픽 처리량 등)   |
| 보안 기능 시험 | 국가정보원 | 국가 보안 요구 충족 여부 확인      |
| 보안적합성 검증 | 국가정보원 | 국가·공공·국방 분야 도입 시 검증    |
| 암호모듈 검증  | 국가정보원 | 상용 암호모듈 안전성 검증         |

### 3. 정보보호 로그

#### 개념 설명
시스템 이벤트 기록(항공기 블랙박스와 유사). 성능, 오류, 경고, 보안 이벤트 포함.

#### 활용 예시
- 침해사고 흔적 확인
- 장애 원인 분석
- 법적 증거 확보

#### Syslog
- 로그 표준 (RFC 3164 → RFC 5424)
- 다양한 장치 로그 통합/상호운용 가능

#### 로그 보관
- 별도 로그 서버 필요 (손실 대비, 최소 6개월 이상 보관 권장)
- 위·변조/삭제 방지 필요

#### 자산별 로그
- 네트워크 장비: Syslog 채택, 저장 제한 → 외부 서버 전송
- 호스트(Windows): 이벤트 뷰어, 정책 기반 로그 관리
- 호스트(POSIX): /var/log 경로에 저장, 분산 저장 → 삭제 어렵

### 4. ESM과 SIEM

#### ESM (Enterprise Security Management)
- 초기 통합보안관제 시스템
- 기능: 로그 수집, 통합 분석, 장비 설정 관리, 모니터링
- 한계: 관계형 DB 기반 → 대용량 데이터 처리 한계, 단순 통계 수준 분석

#### SIEM (Security Information and Event Management)
- **빅데이터** 기반 → 대규모 로그 신속 분석 가능
- 기능: 데이터 통합, 연관분석, 알림, 대시보드
- 장점: APT, 미지 위협, 이상 행위 탐지 가능

### 5. 보안관제 가시화·시각화

#### 가시화 vs 시각화
- **가시화(Visibility)**: 단순히 “보여주는 것” (표·리스트 수준)
- **시각화(Visualization)**: 직관적으로 이해할 수 있도록 차트·그래프·맵·애니메이션 활용

#### 효용성
- APT·미지 위협 탐지에 유용
- 실시간 대량 데이터 속에서 의미 있는 정보 선별

#### 대시보드
- 전체 현황을 직관적으로 제공
- 유형
    - 외부 공격 중심
    - 내부 위협 중심
    - 자산 상태 중심
- 최근: 위젯 기반 템플릿 → 커스터마이징 가능


## 🧠 보안관제 프레임워크 정리
> “NIST CSF (거버넌스·위험관리 표준) → MITRE ATT&CK (공격자 관점) → MITRE D3FEND (방어자 관점)”

### 1. NIST 사이버보안 프레임워크(CSF)

#### 개념 설명
미국 NIST가 개발한 사이버보안 위험 관리 표준·지침·모범 사례 제공 프레임워크.
보안관제 전체 프로세스를 구조화하는 데 활용 가능.

#### 관련 예시
- 오바마 행정명령(2013) 기반으로 주요 기반시설 보호 위해 도입.
- 국내 보안관제 기업(이글루시큐리티)도 NIST CSF 1.1 기반 방법론 활용.

#### 버전별 발전

| 버전             | 특징                           |
| -------------- | ---------------------------- |
| CSF 1.0 (2014) | 최초 버전, 5대 기능(식별·보호·탐지·대응·복구) |
| CSF 1.1 (2018) | 가장 널리 쓰임, 세부 지침 정제·개선        |
| CSF 2.0 (2024) | 6대 기능(식별·보호·탐지·대응·복구 + 거버넌스) |

#### 구성 요소
- Core: 기능(Functions), 범주(Categories), 하위 범주(Subcategories), 참조정보(References)
- Implementation Tiers: 위험관리 수준 (불완전 → 위험 인식 → 재현 가능 → 적합)
- Profiles: 현재 상태 vs 목표 상태를 정리한 맞춤 로드맵

### 2. MITRE ATT&CK

#### 개념 설명
사이버 공격자의 전술(Tactics), 기술(Techniques), 절차(Procedures, TTPs) 지식 기반 프레임워크.
공격자 관점 이해·예측 및 탐지·대응 전략 수립에 활용.

#### 관련 예시
- 한국수력원자력 해킹, Stuxnet 사례 도식화

#### 구성 요소
- Matrices: 전술-기술 관계 시각화 (Enterprise, Mobile, ICS 버전)
- Tactics: 공격 목표 (예: 정찰, 권한상승, 지속성, 방어회피)
- Techniques: 전술 달성 위한 구체적 방법
- Mitigations: 대응책/예방 기법
- Groups: 공격 단체/해킹조직 정보 (사용 기술·소프트웨어 포함)
- Software: 공격도구 및 코드 목록화

#### Matrix 예시 (Enterprise 주요 Tactics)
- 정찰 → 초기 접근 → 실행 → 권한상승 → 내부 확산 → 명령&제어 → 유출 → 임팩트

### 3. MITRE D3FEND

#### 개념 설명
MITRE ATT&CK를 보완하는 방어자 관점 프레임워크.
공격 전술·기술에 대응하는 구체적 방어 전략·기술 제공.

#### 관련 예시
- 사이버공격 대응에서 공격자 행동(ATT&CK) ↔ 방어자 대응(D3FEND) 매핑

#### 5대 전술

| 전술           | 설명                    |
| ------------ | --------------------- |
| 강화 (Harden)  | 취약점 패치·업데이트, 자산 보호    |
| 탐지 (Detect)  | 로그·트래픽·행위 기반 탐지       |
| 격리 (Isolate) | 침해 호스트 분리, IP/DNS 필터링 |
| 기만 (Deceive) | 허니팟/허니넷, 공격자 유인       |
| 퇴거 (Evict)   | 손상된 계정·프로세스 제거        |

#### 디지털 아티팩트 (Digital Artifact)
- 공격 흔적·증거 → 방어 전략 강화
- Digital Artifact Ontology: ATT&CK ↔ D3FEND 간 매핑 구조

## 🧠 침해사고 대응 정리
> CERT 조직의 역할, 대응 절차(사전대응~보고), 주요 사고 유형별 특징과 대응책, 보안관제 문서화(티켓, 보고서, 전파문 등)의 필요성을 강조.

### 1. 침해사고의 이해

#### 개념 설명
침해사고(Computer Security Incident)는 정보시스템이 공격·침해되어 정상 서비스 불능, 데이터 손실·유출, 변조 등이 발생한 사건.
이를 대응하기 위해 CERT(Computer Emergency Response Team) 이 운영됨.

#### 관련 예시
- 1988년 모리스 웜 사건 → 미 국방부 DARPA가 카네기멜런대학에 최초 CERT 설립.

#### CERT 구성원
- 시스템 운영 전문가
- 대외 언론·외부기관 대응 전문가
- 법률팀 (법적 절차·책임 처리)
- 인사팀 (조직 내 권리·책임 관리)

### 2. 침해사고 대응 절차

#### 개념 설명
침해사고 대응은 사전대응 → 사고탐지 → 대응 → 제거 및 복구 → 후속조치 및 보고 단계.

#### 관련 예시
- CERT 팀이 등급별 상황에 따라 보고·차단·수사기관 협조 수행.

#### 사전 대응(등급 분류)

| 등급  | 상황                               | 조치                        |
| --- | -------------------------------- | ------------------------- |
| 1등급 | DDoS, 중요 파일 삭제, 트로이목마 실행 등 긴급 상황 | 즉시 보고, 긴급 시 네트워크 차단/전원 차단 |
| 2등급 | 비인가 명령 실행, 숨김 파일, 계정 임의 추가       | IP 추적, 소속 네트워크 조사, 협조 요청  |
| 3등급 | 취약점 스캐닝, 불법 접근 시도, 비정상 패킷 증가     | 내부/외부 통보, 필요 시 수사기관 요청    |

#### 사고 탐지
- 확인 사항: 발생 시점, 보고자, 공격 범위·규모, 피해 내용
- 도구: IDS, IPS, MRTG, NMS

#### 대응(3단계)
1. 단기 대응: 감염 시스템 차단
2. 백업·증거 확보: 포렌식 이미지 생성
3. 시스템 복구: 백도어 제거, 패스워드 초기화, 보안 패치

#### 제거 및 복구
- 모든 침해 흔적 확인 후 조치
- 복구 과정에서 보안 도구 강화, 로그 모니터링
- 랜섬웨어 대응: 체계적 백업 필수

#### 후속 조치 및 보고
- 보고서 작성(발생 일지, 원인, 초기 대응, 복구 현황, 교훈/개선책 포함)

### 3. 침해사고 유형별 대응

#### 서비스 거부(DoS/DDoS)
- 수법: 대역폭 초과, TCP 자원 고갈, 웹 서버/DB 부하 공격
- 대응: ISP 협조, QoS 정책, 싱크홀, IPS로 트래픽 차단

#### 해킹메일 유포
- 수법: 첨부파일형 악성코드, 자동감염형, 피싱형
- 대응: 스팸 차단, IPS 탐지 규칙, 안티바이러스 도입, 사용자 교육

#### 웹 응용프로그램 해킹
- 수법: 웹 변조, 악성코드 유포지 활용, 명령제어 경유지, 개인정보 절취
- 대응: 보안공학 적용, 취약점 진단/모의침투, WAF/IPS 정책 적용

#### 악성코드 감염
- 유형: 웜, 바이러스, 트로이목마, 스파이웨어, 랜섬웨어
- 대응: IPS 탐지, 안티바이러스, C2 통신 차단

#### 비인가 접근 시도
- 특징: 포트스캔, 디렉토리 구조 탐색 등 사전 활동
- 대응: 과도한 차단은 지양, 지나친 활동 시 IP 차단

### 4. 보안관제 문서 산출물 작성

#### 개념 설명
보안관제 업무 산출물은 문서화된 정보(documented information) 로 유지되어야 하며, ISO/IEC 27001 등 국제 표준과 법적 규제 준수를 위해 필요.

#### 관련 예시
- 보안관제 기업 윈스: 자체 보안관제시스템 기반으로 티켓/보고서 작성.

#### 주요 유형

| 유형    | 설명                                         |
| ----- | ------------------------------------------ |
| 티켓 처리 | 침해사고 이벤트 발생 시 생성, 이관·기술지원·종결까지 관리          |
| 전파문   | 상황전파문, 상황해제문, 보안권고문, 사이버위기경보 발령문           |
| 보고서   | 일일/주간/월간 보고서, 사고 대응 보고서, CTI 보고서, 성과분석 보고서 |
| 통계    | 보안 이벤트 집계·분석 문서                            |

#### 중요성
- 이해관계자와의 소통 도구
- 경영진 의사결정 지원
- 감사증적 및 법정 증거로 활용 가능

## ❓ 궁금한 점

- **'4세대 AI 보안관제'에서, 현재 국내외 보안관제 현장에서 AI 기술은 어느 수준까지 도입되어 있고, 구체적으로 어떤 역할을 수행하고 있나? 악성코드 분석 및 이상 행위 탐지 외에 또 다른 활용 사례는?**
    - 현재 AI 기술은 보안관제 현장에서 단순 탐지를 넘어 복합적인 위협 분석 및 대응 자동화에 이르기까지 폭넓게 활용되고 있다.
    - 위협 예측 및 우선순위 지정: AI는 방대한 양의 과거 침해사고 데이터와 위협 인텔리전스(Threat Intelligence)를 학습하여, 현재 시스템에 가장 큰 위협이 될 수 있는 공격 유형을 예측하고, 탐지된 이벤트의 심각도를 평가하여 관제 요원이 어떤 이벤트부터 우선적으로 분석하고 대응해야 할지 알려준다. 이를 통해 중요한 위협을 놓치지 않게 된다.
    - 오탐(False Positive) 감소: 기존의 규칙 기반 시스템은 오탐이 많아 관제 요원의 피로도를 높였으나, AI는 정상 행위와 비정상 행위를 더 정교하게 구분하여 오탐을 줄여준다. 이는 관제 요원이 실제로 중요한 위협에 집중할 수 있도록 돕는다.
    - 침해사고 대응 및 복구 자동화: SOAR(Security Orchestration, Automation, and Response) 솔루션과 결합된 AI는 특정 유형의 위협(예: 악성코드 감염)이 탐지되면, 격리, 차단, 패치 적용 등 초기 대응 절차를 자동으로 수행한다. 이를 통해 신속한 대응이 가능하며, 24시간 내내 사람이 개입하기 어려운 상황에서도 대응 공백을 최소화한다.

- **생성형 AI를 활용할 경우, 침해사고 대응 보고서나 보안관제 통계 보고서 같은 문서 산출물을 얼마나 자동화할 수 있으며, 이 자동화가 가져올 수 있는 장점과 단점은 무엇인가?**
    - 생성형 AI는 보안관제 문서 산출물의 상당 부분을 자동화할 수 있으며, 특히 정형화된 보고서 작성에 큰 효율을 가져올 수 있다.
    - 자동화 수준
        - 보고서 초안 자동 생성: 침해사고 대응 과정에서 수집된 로그, 분석 데이터, 대응 절차 등을 입력하면, 생성형 AI가 이를 기반으로 사고 개요, 영향 범위, 대응 현황, 재발 방지 대책 등을 포함한 보고서 초안을 자동으로 작성해 준다.
        - 통계 보고서 요약 및 인사이트 추출: 매일, 매주 생성되는 방대한 통계 데이터를 분석하여 주요 지표(예: 공격 유형별 발생 빈도, 특정 시스템에 대한 공격 시도 증가율)를 요약하고, 이를 바탕으로 경영진이 이해하기 쉬운 핵심 인사이트를 도출해 준다.
    - 자동화의 장점
        - 시간 절약 및 효율성 증대: 보고서 작성에 소요되는 반복적인 시간을 줄여, 관제 요원이 분석 및 대응과 같은 핵심 업무에 더 집중할 수 있게 된다.
        - 일관성 유지: AI는 정해진 형식과 템플릿에 따라 보고서를 작성하므로, 작성자에 관계없이 보고서의 품질과 일관성을 유지할 수 있다.
        - 실시간 보고: 사고가 발생하고 데이터가 업데이트되는 즉시 보고서를 생성할 수 있어, 신속한 의사결정을 지원한다.
    - 자동화의 단점
        - 내용의 정확성 및 신뢰성 문제: 생성형 AI가 때때로 환각(Hallucination) 현상으로 부정확하거나 사실과 다른 내용을 포함할 수 있어, 최종 보고서 제출 전 반드시 전문가의 검토가 필요하다.
        - 창의성 및 맥락 이해 부족: AI는 데이터 기반으로만 작성하므로, 사고 발생의 복합적인 배경이나 미묘한 정황(예: 비공식적인 협업 내용, 현장 담당자의 비정형적 진술) 등을 반영하는 데 한계가 있다.
        - 기밀 정보 유출 위험: 내부 기밀 정보나 민감한 침해사고 데이터를 AI 모델에 입력할 경우, 보안 및 개인정보보호 측면에서 정보 유출의 위험이 발생할 수 있다.
