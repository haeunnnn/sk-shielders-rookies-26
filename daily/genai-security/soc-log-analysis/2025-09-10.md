## 🧠 네트워크 보호 정리

### 1. 네트워크 보호의 필요성

#### 개념 설명
사이버 공격은 정보자산(서버, DB, 네트워크 장비 등)을 대상으로 하며, 피해 발생 전에 탐지·차단하는 것이 중요.
이를 위해 보안관제시스템이 운영됨 (통합적으로 수집, 분석, 시각화).
- **관련 예시** : 중국 해킹그룹의 국내 학술기관 해킹 사례 (MBC 보도, 2023).

#### 보안관제시스템
- **기능**: 로그 수집, 분석, 가시화/시각화
- **효과**: 개별 보안 장비를 일일이 볼 필요 없이 중앙 통합 관리 가능.

#### 정보보호시스템
- 방화벽(FW), IDS/IPS, NAC, A/V 등

| 구분    | 역할            | 예시          |
| ----- | ------------- | ----------- |
| 탐지    | 침입 시도 식별      | IDS, NDR    |
| 차단    | 비인가 접근 방지     | 방화벽, IPS    |
| 관리    | 이벤트 통합, 로그 분석 | SIEM        |
| 보안 준수 | 규정·법규 확인      | 컴플라이언스 모니터링 |

- 정보통신망 정의 : 「지능정보화 기본법」, 「전자정부법」 등에서 법적 근거 제공.

### 2. OSI 참조 모형 (OSI 7계층)

#### 개념 설명
ISO에서 제정한 네트워크 국제 표준 모델, 총 7계층.
실제로는 TCP/IP 모델로 구현.
- **관련 예시** : 데이터 송수신 과정에서 캡슐화/역캡슐화 발생.

#### 7계층 구조

| 계층      | 주요 기능                | 단위   |
| ------- | -------------------- | ---- |
| 7 응용    | 응용 서비스 제공            | 메시지  |
| 6 표현    | 암호화/압축/부호화           | 데이터  |
| 5 세션    | 세션 생성/종료/복구          | 데이터  |
| 4 전송    | 흐름제어, 오류제어 (TCP/UDP) | 세그먼트 |
| 3 네트워크  | 논리 주소 (IP)           | 패킷   |
| 2 데이터링크 | 물리 주소 (MAC)          | 프레임  |
| 1 물리    | 전기/광학 신호             | 비트   |

#### 주요 장비
라우터(3계층), 스위치(2~4계층), 허브(1계층), 리피터(1계층), 무선 AP(2계층), 모뎀(1계층).

### 3. 주요 네트워크 공격 기법

#### 개념 설명
네트워크 취약성을 이용해 시스템 장애, 정보 유출, 권한 탈취 등을 유발하는 공격.
- **관련 예시** : Nmap 포트 스캐닝, ARP 스푸핑, DDoS 공격.

#### Scanning (스캐닝)
- 활성 호스트 탐색 (Ping, ARPing)
- 포트 스캐닝 (TCP Connect, SYN Stealth, FIN, XMAS, UDP)
- 취약점 스캐닝 (Nmap –script vuln)

#### Sniffing & Spoofing (스니핑 & 스푸핑)
- 트래픽 도청(스니핑), 주소 위조(ARP 스푸핑, Redirect)
- 스위치 재밍 → 허브처럼 동작하게 만들어 스니핑 가능.

#### DoS / DDoS
- **DoS**: SYN Flooding, Connection Flooding, DNS Flooding, Slowloris 등.
- **DDoS**: 다수의 좀비 PC를 통한 대규모 서비스 거부 공격.

| 공격 기법    | 특징       | 대표 기법                  |
| -------- | -------- | ---------------------- |
| Scanning | 대상 정보 수집 | 포트 스캐닝, 취약점 스캔         |
| Sniffing | 패킷 도청    | 프로미스큐어스 모드             |
| Spoofing | 패킷 위조    | ARP 스푸핑, ICMP Redirect |
| DoS      | 단일 공격원   | SYN Flood, Slowloris   |
| DDoS     | 다수 분산 공격 | Botnet, C\&C 기반        |

## 🧠 방화벽(침입차단시스템) 정리

### 1. 정보보호시스템의 이해

#### 개념 설명
**정보보호시스템**: 사이버 공격/침해 시도를 탐지·차단하고 이벤트를 기록하는 하드웨어 또는 소프트웨어.
네트워크 경계 보호, 내부 통신 통제, 호스트 단위 보호 등 목적 다양.
- **관련 예시** : 부산 조선기자재 업체 랜섬웨어 피해 사례 → 이후 방화벽 설치로 보안 강화.

#### 네트워크 정보보호시스템
방화벽(FW), IDS/IPS, NAC, WAF, UTM, WIPS, NDR

#### 호스트 정보보호시스템
A/V(안티바이러스), 호스트 방화벽, DLP, DRM, EDR

| 구분      | 기능          | 예시                                 |
| ------- | ----------- | ---------------------------------- |
| 네트워크 보호 | 외부 침입 탐지/차단 | 방화벽, IPS, NAC, WAF, UTM, WIPS, NDR |
| 호스트 보호  | 내부 위협 탐지/차단 | 안티바이러스, 호스트 방화벽, DLP, DRM, EDR     |


- **NAC**: 등록되지 않은 장치 차단, 내부 보안 정책 준수 확인.
- **WAF**: SQL Injection, XSS 등 웹 해킹 방어.
- **UTM**: 방화벽+IDS/IPS+WAF 통합 장비.
- **NDR/EDR**: 모든 트래픽·이벤트 장기 보관 및 분석, 개인정보 이슈 존재.

### 2. 정보보호시스템 인증·평가 제도

#### 개념 설명
정보보호시스템은 국가안보와 직결 → 객관적 보안성 평가 필수.
- 우리나라: 과기정통부와 국정원이 주도.
- **관련 예시** : CC 인증(국제/국내용), 성능평가, 보안기능 시험.

#### 주요 제도
- CC 평가·인증 (국제 공통평가기준, CCRA 협정)
- 정보보호제품 성능평가 (성능 중심)
- 보안 기능 시험 (국정원, 국가용 보안 요구사항 만족 여부)
- 보안적합성 검증 (국가·공공·군 도입 제품 검증)
- 암호모듈 검증 (상용 암호 모듈의 안전성 검증)

| 제도       | 담당 기관      | 특징                 |
| -------- | ---------- | ------------------ |
| CC 평가·인증 | 과기정통부      | 국제/국내용 분리, 신뢰성 보증  |
| 성능평가     | 과기정통부·KISA | 처리량, 성능 검증         |
| 보안 기능 시험 | 국정원        | 국내 보안 요구사항 준수      |
| 보안적합성 검증 | 국정원, 국방부   | 공공·군 도입 적합성        |
| 암호모듈 검증  | 국정원        | 비밀 아님, 상용 암호 모듈 검증 |

### 3. 방화벽 (침입차단시스템)

#### 개념 설명
네트워크 간 전송되는 패킷을 규칙에 따라 허용/차단 → 내부 자산 보호.
국가 공식 용어: 침입차단시스템.
- **관련 예시** : 외부에서 웹 서버(80, 443 포트)만 허용, 나머지는 차단.

#### 방화벽 기능
- **패킷 필터링**: IP/Port 기반 허용/차단.
- **상태기반 패킷 검사**: TCP 연결 상태 기반 허용/차단.

#### 방화벽 정책 방식
- 화이트리스트(기본 차단, 일부 허용)
- 블랙리스트(기본 허용, 일부 차단)

| 구분     | 특징            | 장단점          |
| ------ | ------------- | ------------ |
| 화이트리스트 | 기본 차단, 허용만 등록 | 보안 강화, 관리 부담 |
| 블랙리스트  | 기본 허용, 차단만 등록 | 관리 용이, 보안 취약 |


#### 차단 규칙 주의사항
- All Any 규칙 금지, 과도한 허용 지양
- 테스트 규칙은 종료 시 삭제
- 중복/미사용 규칙 제거

## 🧠 IDPS(침입탐지시스템) 정리

### 1. IDPS의 이해

#### 개념 설명
- **IDS (Intrusion Detection System)**: 네트워크 패킷 수집·분석 → 침해 탐지, 탐지 전용 (사후 대응).
- **IPS (Intrusion Prevention System)**: 패킷 수집·분석 → 침해 탐지 + 차단, 실시간 대응 가능.
- IDPS는 IDS+IPS를 통칭, 방화벽이 보지 못하는 응용 계층 본문 데이터까지 확인 가능.
- **관련 예시** : 빗썸 해킹 메일 사례 – 방화벽만으로는 막기 어려운 악성코드 감염 → IDPS 필요.

#### 하위 개념
- **IDS 설치 위치**: TAP/미러링 모드 (트래픽 복제, 네트워크 영향 ↓, 차단 불가).
- **IPS 설치 위치**: 인라인 모드 (트래픽 경유, 실시간 차단 가능, 장애 대비 이중화 필요).

#### 주요 탐지 기법
- **오용 탐지**: 알려진 패턴 탐지 (빠르지만 새로운 공격 탐지 불가).
- **이상 탐지**: 정상 패턴과 다른 행위 탐지 (신종 공격 탐지 가능, 오탐↑).
- **상태 전이 탐지**: 공격 시나리오 기반 단계별 분석 (정밀하지만 제작 난이도↑).

| 구분 | IDS            | IPS         |
| -- | -------------- | ----------- |
| 목적 | 실시간 탐지 (사후 대응) | 실시간 탐지 + 차단 |
| 설치 | 미러링 모드         | 인라인 모드      |
| 장점 | 네트워크 영향 최소     | 즉각적 차단 가능   |
| 단점 | 차단 불가          | 성능 저하/오탐 가능 |

- 책임 추적성 & 알림: 실시간 표시·로그, 공격 유형별 분석 제공.

### 2. 정규표현식과 기본 문법

#### 개념 설명
- 문자열에서 특정 패턴을 정의해 탐지/검색하는 식.
- IDPS 규칙에서 널리 사용되는 것은 PCRE (Perl Compatible Regular Expression).
- **관련 예시** : SQL Injection 탐지 – `' OR 1=1` 패턴을 정규표현식으로 탐지 가능.

#### 기본 문법
- **리터럴**: `apple` → 그대로 매칭
- **메타문자**: `.`, `^`, `$`, `[]`, `|`, `()`
- **수량 한정자**: `*`, `+`, `?`, `{n,m}`
- **탐색**: `(?= )` 전방탐색, `(?<= )` 후방탐색
- **패턴변경자**: `i`(대소문자 무시), `g`(전체 검색) 등

| 문법 요소  | 설명       | 예시                 |
| ------ | -------- | ------------------ |
| 리터럴    | 그대로 매칭   | `/data/`           |
| 메타문자   | 특수 기능    | `\d`(숫자), `\s`(공백) |
| 수량 한정자 | 개수 범위    | `a+` (1개 이상 a)     |
| 탐색     | 위치 기준 검색 | `?=abc`            |
| 패턴변경자  | 옵션       | `/abc/i` (대소문자 무시) |

- **활용 예**: 이메일 `/[a-z0-9._%+-]+@[a-z0-9.-]+\.[a-z]{2,}/g`
- **활용 예**: 날짜 `/\d{4}-\d{2}-\d{2}/g`

### 3. IDPS 정책 · 규칙 구성

#### 개념 설명
IDPS는 **블랙리스트** 방식: 규칙에 없는 건 기본 허용, 등록된 패턴만 탐지/차단.
Snort 규칙 형식(`Snort Rule`)을 기반으로 작성됨.
- **관련 예시** : SQL Injection 탐지 규칙

``` snort
alert tcp any any -> 192.168.0.31 [80,443] 
(msg: "SQL Injection - OR"; pcre: "/'\s*OR\s*1=1\s*;?\s*\#/i"; sid:1000001;)
```

#### 규칙 구성 요소
- **동작(Action)**: alert, log, pass, drop, reject, sdrop
- **프로토콜**: TCP, UDP, ICMP, IP
- **IP/Port**: any, 대역표기(/24), 부정(!), 다중([])
- **방향**: `->` (단방향), `<>` (양방향)
- **내용(Content)**: msg, sid, rev, content, nocase, flags, pcre, threshold 등

| 요소        | 설명         | 예시                            |
| --------- | ---------- | ----------------------------- |
| Action    | 수행 동작      | alert, drop                   |
| Protocol  | 통신 프로토콜    | TCP, UDP                      |
| IP        | 출발지/목적지 주소 | any, 192.168.1.0/24           |
| Port      | 포트 번호      | 80, \[25,110,143]             |
| Direction | 트래픽 방향     | ->, <>                        |
| Content   | 탐지 세부 옵션   | content:"SQL", pcre:"/regex/" |

#### 규칙 예시
- LDAP Injection 탐지
- Malware C2 통신 탐지 (Mal0Day 문자열 포함 시 차단)

## ❓ 궁금한 점

- **어떤 상황에서 화이트리스트를 적용하고, 어떤 상황에서 블랙리스트를 적용하는 것이 가장 효율적인가?**
    - 방화벽의 화이트리스트와 블랙리스트 정책은 조직의 보안 목표와 네트워크 환경에 따라 상호 보완적으로 활용하는 것이 효과적이다.
    - **화이트리스트 (기본 차단, 허용만 등록)**
        - 적용 상황: 보안이 최우선이고, 접근이 엄격하게 통제되어야 하는 핵심 시스템이나 **제어 시스템(ICS)**에 적합하다. 예를 들어, 외부에 공개되지 않는 내부망의 데이터베이스 서버나 관리자 전용 서버는 특정 IP 대역이나 정해진 포트만 허용하는 화이트리스트 정책을 적용하여 불필요한 접근을 원천적으로 차단한다.
        - 장점: 강력한 보안을 제공하며, 알려지지 않은 모든 위협을 효과적으로 방어할 수 있다.
        - 단점: 정책 설정 및 관리가 복잡하며, 새로운 서비스나 사용자가 추가될 때마다 규칙을 업데이트해야 하는 관리 부담이 크다.

    - **블랙리스트 (기본 허용, 차단만 등록)**
        - 적용 상황: 다양한 사용자 및 외부 서비스와의 통신이 필수적인 **대외 서비스(웹 서버, 이메일 서버)**에 적합하다. 예를 들어, 일반 사용자의 웹사이트 접속은 허용하되, 특정 국가의 IP나 알려진 악성 IP, 혹은 특정 포트 스캐닝 시도를 차단하는 데 사용한다.
        - 장점: 정책 관리가 비교적 용이하며, 일반적인 서비스 운영에 지장을 주지 않는다.
        - 단점: 알려지지 않은 새로운 공격이나 IP 우회 공격에는 취약할 수 있다.
    
- **IDS는 미러링 모드로, IPS는 인라인 모드로 설치한다고 나와 있어요. 그럼 이 둘을 함께 운영하는 환경에서는 트래픽이 어떤 방식으로 처리되나요? 상호 보완적인 관계가 있는지 궁금합니다.**
    - IDS와 IPS를 함께 운영하는 것은 '심층 방어(Defense in Depth)' 전략의 핵심이다. 두 시스템은 각자의 강점을 활용해 서로의 약점을 보완하는 역할을 한다.
    - **트래픽 처리 방식**
        1. 네트워크로 유입되는 모든 트래픽은 먼저 IPS를 통과한다.
        2. IPS는 인라인 모드로 동작하면서 사전에 정의된 규칙에 따라 악성 트래픽을 즉시 **차단(drop)**하거나 **거부(reject)**한다.
        3. 동시에, 동일한 트래픽의 복사본이 스위치의 미러링 포트를 통해 IDS로 전달된다.
        4. IDS는 이 복사된 트래픽을 분석하여, IPS가 차단하지 못한 새로운 공격 시도나 이상 행위를 탐지하고 관제 시스템에 **경보(alert)**를 발생시킨다.
        5. IDS의 경보를 통해 관제 요원은 IPS 정책을 업데이트하거나, 수동으로 트래픽을 차단하는 등 후속 조치를 취할 수 있다.

    - **상호 보완 관계**
        - IPS: 알려진 공격에 대한 즉각적인 방어를 담당하며, 네트워크의 최전방에서 일차적인 위협을 막아낸다.
        - IDS: IPS가 놓칠 수 있는 새로운 공격이나 비정상적인 행위를 '미러링'된 트래픽으로 분석하여 탐지함으로써, 관제 요원에게 위협에 대한 가시성을 제공하고 IPS 규칙을 개선하는 데 필요한 정보를 제공한다.

- **보안관제 현장에서 흔히 사용되는 정규표현식 패턴에는 어떤 것들이 있으며, 이런 패턴을 직접 작성하거나 수정할 때 가장 자주 발생하는 문제점은 무엇인가요?**
    - 정규표현식은 IDPS 규칙에서 특정 패턴을 정의하여 오용 탐지를 수행하는 데 필수적이다. 하지만 복잡한 패턴은 작성 및 관리 시 여러 문제를 야기할 수 있다.
    - **자주 사용되는 패턴**
        - **SQL Injection 탐지**: `/\s*'\s*(OR|AND)\s*(\d+)=(\d+)\s*/i`와 같이 `' OR 1=1`과 같은 SQL 명령어를 포함하는 패턴을 탐지한다.
        - **XSS(Cross-site Scripting) 탐지**: `<script>`나 `<img>` 태그를 활용한 악성 스크립트 삽입을 탐지한다. 예: /<script>.*<\/script>/i
        - **LDAP Injection 탐지**: `'*')(uid=*`와 같은 LDAP 질의문을 탐지한다. 예: `/\(\s*\|\s*\(.*\)\s*\)\s*$/`
        - **명령어 실행(Command Injection) 탐지**: `|`, `;`, `&&`, `||`와 같은 기호를 포함하여 OS 명령어를 실행하려는 시도를 탐지한다.

    - **작성 및 수정 시 발생하는 문제점**
        - **과도한 오탐 (False Positive)**: 공격 패턴을 너무 광범위하게 정의하면 정상적인 트래픽까지 악성으로 오인하여 차단/탐지할 수 있다. 예를 들어, script라는 단어가 포함된 정상 게시물을 XSS 공격으로 탐지하는 경우가 발생한다.
        - **미탐 (False Negative)**: 공격자가 패턴을 우회하기 위해 다양한 변형 기법(URL 인코딩, 공백 삽입 등)을 사용하면, 정교하지 못한 정규표현식은 이를 탐지하지 못하고 놓치게 된다.
        - **성능 저하**: 복잡하고 비효율적인 정규표현식은 IDPS 시스템의 CPU 리소스를 과도하게 소모하여 전체적인 패킷 처리 성능을 저하시킬 수 있다.
        - **유지보수의 어려움**: 규칙이 복잡해질수록 패턴의 의도를 파악하고 수정하는 데 어려움이 따른다.
