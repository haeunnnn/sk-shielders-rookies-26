## 🧠 호스트 보호 정리

### 1. 호스트 보호의 필요성

#### 개념 설명
- **호스트**: 네트워크에 연결된 모든 컴퓨팅 장치(서버·단말기·IoT 기기·가상 머신 포함).
- 사이버 공격의 최종 표적은 호스트 → 네트워크 보호 실패 시 2차 필터 역할 수행.
- 침해사고 발생 시 신속히 격리 및 원인 규명 지원.
- **관련 예시** : 북한 해킹조직(히든 코브라) 악성코드 변종 사례 – 원격 명령 실행, 자료 절취 등.

#### 하위 개념
- **물리 호스트**: 서버(웹/DBMS/NAS), 단말기(PC, 스마트폰), 특정목적 기기(의료기기, 자동차), 센서/스위치(IoT).
- **가상 호스트**: 가상화 기반 VM.
- 호스트 보호 중요성: 네트워크 방어 실패 시 호스트 보안이 마지막 보루.

| 구분     | 예시             | 특징                  |
| ------ | -------------- | ------------------- |
| 물리 호스트 | 서버, PC, IoT 기기 | 하드웨어+소프트웨어 구성       |
| 가상 호스트 | VM             | 물리 자원 공유, 가상화 기술 활용 |

### 2. CPU와 기억장치, 운영체제

#### 개념 설명
- **컴퓨터 = 하드웨어(물리) + 소프트웨어(논리)**.
- **OS**: 하드웨어 제어·자원 관리·사용자-응용 간 인터페이스 제공.
- **관련 예시** : Windows, Linux, Unix, Android, iOS 등.

#### 하드웨어 구성요소
- **CPU**: 연산/제어
- **기억장치**: ROM, RAM, HDD, SSD
- **입력장치**: 키보드, 마우스
- **출력장치**: 모니터, 프린터

#### 소프트웨어 종류
- 시스템 소프트웨어(OS, 컴파일러 등)
- 응용 소프트웨어(워드, 게임, 전용 앱 등)

#### 운영체제 구조
- **커널**: 자원 관리
- **드라이버**: 하드웨어 제어
- **시스템 호출**: 커널↔사용자 환경 인터페이스(API, COM)
- **사용자 환경**: GUI, CLI

| 구분      | 역할        | 예시                 |
| ------- | --------- | ------------------ |
| 하드웨어    | 연산·저장·입출력 | CPU, RAM, HDD, 모니터 |
| 소프트웨어   | 제어·관리·응용  | OS, 워드프로세서         |
| 운영체제 요소 | 자원 관리·통신  | 커널, 드라이버, 시스템콜     |

### 3. 시스템 취약점과 익스플로잇

#### 개념 설명
- **취약점(Vulnerability)**: 시스템/소프트웨어의 보안 약점.
- **익스플로잇(Exploit)**: 취약점을 이용해 의도된 동작 실행(권한 상승, 정보 유출 등).
- **CVE**: 공개된 보안 결함 목록.
- **CVSS**: 취약점 심각도 평가 지표.
- **CWE**: 소프트웨어/하드웨어 보안 약점 분류체계.
- **관련 예시** : 디렉토리 리스팅 취약점, 웹쉘 업로드, 악성코드 통신.

#### 취약점 분석 방법
- **정적 분석**: 실행 없이 코드/파일 구조 분석 (IDA, Ghidra).
- **동적 분석**: 실행 후 행위·메모리 추적 (GDB, pwndbg).

#### 대표 취약점
- **Buffer Overflow**: 입력값 검증 부족 → 메모리 침범
- **Out-of-Boundary**: 배열 범위 벗어난 접근
- **Off-By-One**: 경계 조건 실수로 1칸 초과 접근

| 취약점 유형          | 특징           | 결과            |
| --------------- | ------------ | ------------- |
| Buffer Overflow | 버퍼 크기 초과 입력  | Return 주소 조작  |
| Out-of-Boundary | 배열 범위 벗어난 접근 | 다른 변수 값 노출    |
| Off-By-One      | 경계 조건 오류     | 메모리 손상, 예외 발생 |

- Exploit 절차: 취약점 탐색 → 분석 → Exploit 코드 제작 → 실행 → 정보 탈취/추가 공격.

## 🧠 안티 바이러스 정리

### 1. 바이러스와 악성코드

#### 개념 설명
- **컴퓨터 바이러스**: 자기 자신을 복제·삽입해 확산하는 프로그램. 세대별로 진화 (1세대 원시형 → 5세대 매크로).
- **악성코드(Malware)**: 바이러스뿐만 아니라 악의적 기능을 수행하는 모든 실행 가능한 프로그램.
- **관련 예시**
    - 2003년 슬래머 웜으로 인한 인터넷 대란.
    - 2017년 워너크라이 랜섬웨어 대규모 피해.

#### 바이러스 세대 구분
- 1세대: 원시형(부트/파일 바이러스)
- 2세대: 암호형(코드 암호화)
- 3세대: 은폐형(잠복기 후 발현)
- 4세대: 다형성(코드 지속 변형)
- 5세대: 매크로(Office 매크로 기반)

#### 악성코드 종류
- **웜**: 자체 실행, 네트워크 확산.
- **트로이목마**: 정상 프로그램 위장, 백도어 생성.
- **스파이웨어**: 정보 절취(키로거, 원격제어).
- **애드웨어**: 광고 팝업, 성능 저하.
- **랜섬웨어**: 파일 암호화, 금전 요구.
- **루트킷**: 커널 모드에서 동작, 탐지 회피

| 구분    | 특징           | 대표 사례          |
| ----- | ------------ | -------------- |
| 바이러스  | 자기 복제·삽입     | 브레인, CIH       |
| 웜     | 자체 실행·확산     | 슬래머, 블래스터      |
| 트로이목마 | 위장 프로그램, 백도어 | 2013년 320사이버테러 |
| 스파이웨어 | 정보 절취        | 국가정보원 RCS      |
| 애드웨어  | 광고, 성능 저하    | 무료 소프트웨어 번들    |
| 랜섬웨어  | 암호화·금전 요구    | 크립토락커, 워너크라이   |
| 루트킷   | 커널 모드 동작     | 고난도, 탐지 회피     |

### 2. 안티 바이러스의 이해

#### 개념 설명
- 컴퓨터 바이러스와 악성코드를 탐지·방어하는 호스트 기반 보안 시스템.
- 한국에서는 "백신(Vaccine)" 용어가 보통명사처럼 사용됨.

**관련 예시**
- 2022년 무료 백신 ‘알약’ 오류로 PC 먹통 사태 발생.

#### 설치 위치
- **커널 모드**: 드라이버, 강력한 권한 필요(루트킷 탐지, 자가보호).
- **사용자 모드**: UI 제공, 설정 변경.

#### 주요 기능
- **진단 기능**: 패턴 기반 탐지, 휴리스틱 탐지, 루트킷 탐지
- **실시간 감시**: 운영체제 행위 모니터링
- **자가 보호**: 강제 종료/삭제 방지
- **치료**: 감염 이전으로 복구

| 기능       | 설명                  |
| -------- | ------------------- |
| 패턴 기반 탐지 | 고유 패턴(문자열, 해시 등) 비교 |
| 휴리스틱 탐지  | 구조 규칙 기반, 미지/변종 탐지  |
| 루트킷 탐지   | 커널 드라이버/이벤트 분석      |
| 실시간 감시   | 운영체제 행위 모니터링        |
| 자가 보호    | 종료·삭제 방지            |
| 치료       | 감염 파일 복구·삭제         |

### 3. 바이러스/악성코드 탐지 원리

#### 개념 설명
- 패턴(시그니처) 기반 탐지 원리에 따라 감염 여부 확인.
- OS 설정값, 네트워크 포트, 실행 프로세스 확인도 활용.
- **관련 예시** : EICAR 테스트 파일 – 가짜 악성코드로 탐지 성능 검증.

#### 탐지 방식
- **고정길이 검사**: 파일 앞/뒤 일부만 확인.
- **가변길이 검사**: 파일 전체 확인.
- **해시값 검사**: 파일 자체 해시 대조.

| 탐지 방법   | 특징       | 장단점         |
| ------- | -------- | ----------- |
| 고정길이 검사 | 파일 일부 검사 | 속도↑, 정확도↓   |
| 가변길이 검사 | 전체 내용 검사 | 속도↓, 정확도↑   |
| 해시값 검사  | 해시 비교    | 속도↑, 관리 부담↑ |

## 🧠 사이버위협정보(CTI) 정리

### 1. 정보와 CTI

#### 개념 설명
- **자료(Data)**: 평가되지 않은 단순 사실.
- **첩보(Information)**: 의도적으로 수집됐지만 아직 분석되지 않은 자료.
- **정보(Intelligence)**: 분석·검증·평가되어 의사결정에 활용 가능한 지식.
- **CTI(Cyber Threat Intelligence)**: 사이버 위협을 완화하기 위해 수집·분석·가공된 지식.
- **관련 예시** : 북한의 암호화폐 탈취 사건(액시 인피니티) → CTI로 자금 세탁 과정 추적.

#### CTI 정의
- **협의**: 기술정보(IP, 도메인, 악성코드 샘플, 취약점).
- **광의**: 해커 조직, 동향 등 비기술 정보까지 포함.

#### 사이버 킬 체인
- **공격 절차: 정찰 → 무기화 → 유포 → 악용/권한탈취 → 설치 → 명령/제어 → 목적달성**
- **방어 모델: 탐지, 거부, 교란, 약화, 기만, 파괴**

| 구분               | 설명           | 예시                |
| ---------------- | ------------ | ----------------- |
| 자료(Data)         | 가공되지 않은 사실   | 로그 원본             |
| 첩보(Information)  | 의도적 수집, 미분석  | 위협 IP 목록          |
| 정보(Intelligence) | 분석·검증된 지식    | APT 그룹 프로파일       |
| CTI              | 사이버 위협 대응 지식 | STIX/TAXII 형식 IOC |

### 2. 내부 위협 헌팅

#### 개념 설명
- 조직 내부 자산을 대상으로 위협을 직접 탐색하는 활동.
- 알려지지 않은 위협(제로데이, 신종 악성코드 등)을 조기에 식별.
- **관련 예시** : 트로이목마로 유포된 악성코드가 내부 PC에 잠복 → 헌팅을 통해 발견.

#### 위협 헌팅 기법
- **호스트 기반**: IoC(Indicator of Compromise) 수집 (프로세스, 파일, 레지스트리, 네트워크 이벤트).
- **통신채널 기반**: 백도어 통신 탐지(암호화, 분할 전송, 정상 데이터 위장).

- 활용 도구: Sysmon, IOC Editor/Finder, EDR 솔루션.

| 구분      | 주요 항목                               | 특징        |
| ------- | ----------------------------------- | --------- |
| 호스트 기반  | 프로세스, 서비스, 파일, 레지스트리, DNS, 네트워크 이벤트 | 침해 흔적 추적  |
| 통신채널 기반 | 비정상 통신, 암호화된 데이터, 프로토콜 오용           | 은닉된 채널 탐지 |

### 3. 외부 위협 헌팅

#### 개념 설명
- 공개 출처(OSINT), 다크웹, 전문 정보시장에서 위협을 탐색.
- 조직에 아직 유입되지 않은 위협을 사전 인지하여 대응 가능.

**관련 예시**
- Shodan으로 노출된 CCTV 관리자 페이지 탐색.
- 다크웹에서 유출된 계정 정보 탐지.

#### 정보 출처
- **OSINT**: 인터넷/언론/공시 등 합법적 공개 정보.
- **HUMINT**: 사람을 통한 정보.
- **TECHINT**: 기술 수단(도·감청, 암호해독).

#### 외부 위협 헌팅 기법
- 인터넷 검색엔진 기반 (Google, Shodan, VirusTotal).
- 허니넷 기반 (공격자 유인).
- 사용자 행위 모사 기반 (의도적 감염 유도).
- 다크웹 헌팅 (유출 정보, 취약점, 악성코드).

| 기법      | 특징            | 예시                 |
| ------- | ------------- | ------------------ |
| 검색엔진 기반 | 축적 DB 활용      | Shodan으로 IoT 노출 탐색 |
| 허니넷 기반  | 공격자 유인·기만     | 공격 패턴 수집           |
| 행위 모사   | 가상 호스트로 감염 유도 | 악성코드 분석            |
| 다크웹 헌팅  | 익명성 영역 추적     | 계정/DB 유출 탐지        |

### 4. CTI 공유

#### 개념 설명
- CTI는 조직 내부뿐 아니라 국가·민간 차원에서 공유 필요.
- 표준 형식을 통해 상호 호환 가능해야 자동화 대응 가능.
- **관련 예시** : 국가정보원의 NCTI/KCTI, KISA의 C-TAS, VirusTotal, 샌즈랩 CTX.

#### 주요 표준
- **CVE (취약점 식별)**
- **IODEF (침해사고 교환 형식)**
- **CPE (플랫폼 열거)**
- STIX (위협 표현), TAXII (전송), MAEC (악성코드 속성), CybOX (운영 객체), MMDEF (악성코드 메타데이터)

#### CTI 순환주기

`기획 → 수집 → 분석 → 생산 → 공유`

| 표준    | 역할         |
| ----- | ---------- |
| CVE   | 취약점 식별 규격  |
| IODEF | 침해사고 정보교환  |
| STIX  | 위협정보 표현    |
| TAXII | 위협정보 전송    |
| MAEC  | 악성코드 속성    |
| CybOX | 사이버 운영 객체  |
| MMDEF | 악성코드 메타데이터 |

## 🧠 인공지능 보안관제와 생성형 인공지능 정리

### 1. 인공지능과 머신러닝의 이해

#### 개념 설명
- **인공지능(AI)**: 컴퓨터로 구현한 지능, 학습·문제해결·범용성 보유.
- **머신러닝(ML)**: 프로그래밍 없이 데이터 기반 학습으로 스스로 규칙 생성.
- 딥러닝·생성형 AI(LLM, GAN, VAE)로 발전.
- **관련 예시** : ChatGPT, 이미지 인식, 이상 행위 탐지.

#### 머신러닝 프로세스
- 데이터 수집 → 학습데이터 라벨링 → 전처리 → 피처 추출 → 모델 학습/평가/개선.

#### 보안 데이터 활용
- **지도학습**: 이벤트, 알림(Alert)
- **비지도학습**: 로그, 원시 데이터

| 단계       | 내용              | 보안 적용      |
| -------- | --------------- | ---------- |
| 데이터 수집   | IPS, WAF, TMS 등 | 보안 이벤트 수집  |
| 라벨링      | 정상/오탐/정탐 구분     | 공격 여부 표시   |
| 전처리      | 불필요 데이터 제거      | 데이터 정제     |
| 피처 추출    | 특징값 도출          | URL, 패킷 길이 |
| 모델 학습/평가 | 알고리즘 적용, 피드백 반영 | 침입 탐지 모델   |

### 2. SOAR와 XDR

#### 개념 설명
- **SOAR**: 보안 오케스트레이션·자동화·대응 플랫폼. (SIEM 기반, 플레이북 활용)
- **XDR**: 확장된 탐지·대응. 네트워크(NDR), 엔드포인트(EDR), 사용자행위(UEBA) 통합.
- **관련 예시** : Gartner SOC Visibility Triad (SIEM/UEBA + NDR + EDR).


#### SOAR 구성요소
- **SOA (워크플로우 자동화)**
- **SIRP (사고 대응 표준화)**
- **TIP (위협정보 플랫폼)**

#### XDR 구성요소
- **NDR**: 네트워크 위협 탐지·대응
- **EDR**: 단말 위협 탐지·대응
- **UEBA**: 사용자 이상 행위 분석

| 구분 | SOAR           | XDR              |
| -- | -------------- | ---------------- |
| 초점 | 자동화·표준화        | 확장된 탐지·대응        |
| 요소 | SOA, SIRP, TIP | NDR, EDR, UEBA   |
| 장점 | 대응속도 향상, 비용절감  | 위협 가시성 확보, 통합 대응 |

### 3. 머신러닝의 보안관제 적용

#### 개념 설명
- AI는 오탐 줄이고 정탐을 높여 보안관제 효율화.
- 이벤트 자동 분류·재식별·대응 등 적용 사례 존재.

**관련 예시**
- WAF 이벤트 자동 분석, DDoS 이벤트 분류, 이상 URL 탐지.

#### 사례
- **Payload 분석**: IDS/WAF 이벤트 정·오탐 구분.
- **URL 분석**: 신종 악성 URL 탐지.
- **이벤트 분류**: 공격 유형별 자동 분류.

- **적용 조건**: 충분한 학습 데이터, CTI 활용, SIEM·SOAR와 연계.

| 적용 영역      | 학습 데이터      | 효과       |
| ---------- | ----------- | -------- |
| Payload 분석 | IDS/WAF 이벤트 | 오탐 감소    |
| URL 분석     | Web 로그      | 신종 공격 탐지 |
| 이벤트 분류     | 다중 이벤트      | 자동 분석/분류 |

### 4. 이상행위 탐지를 위한 보안 데이터 수집·분석

#### 개념 설명
- **탐지 방식**: 오용탐지(서명 기반), 이상탐지(행위 기반).
- 이상탐지는 AI·ML과 결합해 제로데이 탐지 가능.
- **관련 예시** : Snort Rule (CVE 탐지), UEBA 기반 이상행위 탐지.

#### 하위 개념
- **데이터셋 구축**: 정상 행위(로그인, 파일 업로드) vs 비정상 행위(SQL Injection, Brute Force).
- **분석 절차**: 데이터 추출 → 전처리 → 모델 학습 → 평가 (Confusion Matrix, Precision, Recall, F1).
- CSIC 2010 데이터셋: 웹 공격/정상 요청 포함, 보안 연구에 활용.

| 구분 | 오용탐지      | 이상탐지      |
| -- | --------- | --------- |
| 기준 | 공격 시그니처   | 정상 행위 패턴  |
| 장점 | 낮은 오탐, 빠름 | 신종 공격 탐지  |
| 단점 | 신종 공격 미탐  | 높은 오탐     |
| 예시 | Snort, AV | UEBA, 딥러닝 |

### 5. 생성형 인공지능과 보안 위험

#### 개념 설명

## ❓ 궁금한 점

- **AI 모델의 성능을 좌우하는 피처 추출(Feature Extraction)은 보안관제 분야에서 어떤 데이터를 활용하여 이루어지며, 이 과정에서 도메인 지식이 어떻게 활용되나?**
    - 보안관제 분야에서 효과적인 피처 추출은 단순히 기술적 데이터를 나열하는 것을 넘어, 보안 전문가의 경험과 지식인 도메인 지식이 결합될 때 그 가치가 극대화된다.
    - **주요 데이터 및 피처 예시**
        - 네트워크 트래픽 데이터: 패킷의 크기(길이), 출발지/목적지 IP 및 포트 번호, 프로토콜 종류(TCP, UDP 등), 통신 시간, 연결 횟수 등이 주요 피처가 된다. 예를 들어, 짧은 시간에 특정 포트로 수많은 연결 시도가 이루어지는 경우, 이는 포트 스캐닝(Port Scanning) 공격의 중요한 피처가 될 수 있다.
        - 로그 데이터: 로그인 시도 실패 횟수, 접속 시간대, 사용자 계정, 시스템 이벤트 코드, 오류 메시지 등이 피처로 활용된다. 평소와 다른 시간대에 발생한 로그인 시도 실패는 무차별 대입 공격(Brute Force Attack)의 피처가 될 수 있다.
        - 호스트(Endpoint) 데이터: 파일의 해시값, 파일 생성 시간, 프로세스명, 레지스트리 변경 내역 등이 중요한 피처이다. 악성코드가 시스템에 설치될 때 생성되는 특정 파일 해시값이나 비정상적인 프로세스 동작은 악성 행위를 탐지하는 데 필수적인 피처가 된다.

    - **도메인 지식의 활용**
        - 데이터의 의미 부여: "패킷 길이 0" 이라는 단순한 데이터에 "TCP 3-Way Handshake가 정상적으로 완료되지 않아 악성 트래픽일 가능성이 높다"는 의미를 부여하는 것은 도메인 지식에서 비롯된다.
        - 이상 행위 정의: '정상적인 시간대에 관리자 계정으로 접속', '평소 사용하지 않던 포트를 통해 외부와 통신'과 같은 비정상적인 행위의 기준을 설정하는 것은 보안 전문가의 경험에 기반한다.
        - 피처 가중치 부여: DDoS 공격 탐지 시 '패킷 크기'보다 '초당 패킷 전송량'에 더 높은 가중치를 부여하는 것 또한 도메인 지식을 통해 이루어진다. 이를 통해 AI 모델은 공격의 핵심적인 특징에 더 집중하여 학습하게 된다.

- **다크웹 헌팅을 할 때 법적으로나 윤리적으로 어떤 점을 주의해야 하나? 민간 기업의 보안관제팀이 다크웹에서 정보를 수집할 때 지켜야 할 가이드라인이 있나?**
    - 다크웹 헌팅은 잠재적인 위협을 선제적으로 파악하는 데 유용하지만, 불법 정보에 접근하고 유출된 개인정보를 다룰 수 있다는 점에서 민감한 활동이다. 민간 기업의 보안관제팀은 다음의 법적, 윤리적 가이드라인을 엄격히 준수해야 한다.
    - **법적 주의사항**
        - 불법 정보 접근 금지: 아동 성착취물, 마약 등 명백한 불법 정보에 접근하거나 이를 다운로드하는 행위는 법적 처벌 대상이 된다. 헌팅의 목적이 위협 정보 수집에 있더라도, 이러한 불법 콘텐츠를 발견할 경우 즉시 활동을 중단하고 수사기관에 신고해야 한다.
        - 개인정보보호법 준수: 유출된 개인정보를 발견했을 경우, 해당 정보를 무단으로 수집하거나 이용하거나 제3자에게 제공해서는 안 된다. 이와 같은 정보는 열람 후 즉시 삭제하고, 정보 유출 사고 대응 절차에 따라 처리해야 한다.
        - 사이버 보안 관련 법규 준수: 기업은 '정보통신망 이용촉진 및 정보보호 등에 관한 법률' 등 관련 법규를 준수해야 하며, 헌팅 활동이 법적 범위를 벗어나지 않도록 사전에 법률팀과 협의해야 한다.

    - **윤리적 가이드라인**
        - 수집 목적의 명확화: 헌팅의 목적은 오직 '위협 정보 수집'에 한정되어야 한다. 호기심이나 다른 목적으로 다크웹을 탐색해서는 안 된다.
        - 전문성 및 교육: 다크웹 헌팅은 고도의 기술과 윤리 의식을 필요로 합니다. 헌팅을 수행하는 팀원은 관련 교육을 이수하고, 잠재적인 위험에 대해 충분히 인지하고 있어야 한다.
        - 투명한 보고: 헌팅 과정에서 수집된 정보와 활동 내역은 명확하게 문서화하고, 경영진이나 책임자에게 투명하게 보고해야 한다.

- **난독화(Obfuscation) 기법을 사용한 악성코드 분석 시, 정적 분석과 동적 분석은 각각 어떤 역할을 하며, 실무에서 이 두 기법을 어떻게 함께 사용하나?**
    - 난독화된 악성코드는 코드를 알아보기 어렵게 만들어 정적 분석을 회피한다. 따라서, 정적 분석과 동적 분석을 결합하여 악성코드의 숨겨진 행위를 파헤치는 것이 일반적이다.
    - **정적 분석의 역할**
        - 초기 정보 수집: 악성코드를 실행하지 않고 파일의 헤더 정보, 문자열, 함수 목록 등을 분석하여 악성코드의 종류나 목적을 유추한다. 난독화된 코드라도 일부 원본 문자열(예: URL, 파일명)이 남아 있을 수 있어 힌트를 얻을 수 있다.
        - 악성코드 구조 파악: 난독화된 코드가 어떤 방식으로 패킹되었는지, 어떤 섹션에 악성 코드가 숨겨져 있는지 전체적인 구조를 파악하는 데 유용하다.

    - **동적 분석의 역할**
        - 난독화 해제(Deobfuscation): 난독화된 악성코드는 특정 시점에 스스로 코드를 복호화하여 실행합니다. 동적 분석은 이 실행 순간을 포착하여 복호화된 원본 코드를 메모리에서 추출할 수 있게 한다.
        - 실제 행위 관찰: 샌드박스(Sandbox) 같은 가상 환경에서 악성코드를 실행하여, 시스템 호출, 파일 생성/삭제, 레지스트리 변경, 네트워크 통신 등 악성 행위를 직접 관찰하고 기록한다.

    - **실무적 활용 시나리오**
        1. 정적 분석으로 시작: 먼저 악성코드 파일을 정적 분석 도구(예: IDA Pro)로 열어 패킹 여부를 확인하고, 파일 내에서 의미 있는 문자열이나 함수를 찾아 초기 단서를 확보한다.
        2. 동적 분석으로 난독화 해제: 악성코드를 동적 분석 환경(예: Cuckoo Sandbox)에서 실행시킨다. 이 과정에서 악성코드가 스스로를 복호화하는 순간을 메모리 덤프(Memory Dump) 기능으로 포착한다.
        3. 다시 정적 분석으로 전환: 동적 분석을 통해 얻은 복호화된 원본 코드를 다시 정적 분석 도구로 가져와 분석한다. 이 원본 코드에는 악성 행위의 핵심 로직(예: C2 서버 IP, 명령)이 명확하게 드러나 있어, 분석이 훨씬 용이해진다.
