## 🧠 주요 개념 정리

### 오전 워밍업: 실습 피드백과 포트폴리오 작성
포트폴리오는 단순한 기술 목록이 아니라, **자신의 역량을 보여주는 하나의 이야기**이다. 학습한 내용처럼, **가설 설정부터 결과 시각화까지 논리적인 흐름**을 담는 것이 중요할 것이다.
- **가설, 검증, 효과** : '어떤 문제를 해결하고자 했는지'에 대한 가설을 세우고, 그 가설을 '어떻게 증명했는지'를 보여준다. 그리고 그 결과가 '어떤 의미가 있는지'까지 명확히 제시해야 한다. 예를 들어, "AI를 활용하여 보안 취약점을 진단하면 더 효율적일 것"이라는 가설을 세우고, 이를 실습을 통해 "실제로 탐지율이 높아지는 것을 검증"했으며, "궁극적으로 회사의 의사결정에 도움이 될 수 있음"을 보여주는 방식.
- **역할, 문제점, 해소** : 프로젝트 과정에서 **자신이 맡은 역할**을 구체적으로 설명하고, 프로젝트 진행 중 마주쳤던 **문제점**과 그 문제를 **어떻게 해결했는지**를 서술하면, 문제 해결 능력과 협업 능력을 어필할 수 있다.
- **시각화** : **Gradio, Streamlit, Canvas** 등 무료 호스팅 도구를 활용해 프로젝트 결과물을 시각적으로 보여주면, 상대방의 이해를 돕고 포트폴리오의 완성도를 높일 수 있다.

#### 1. 웹 모의해킹 및 최신 공격 동향
최신 웹 공격 동향은 중소기업의 보안 취약성을 파고드는 방향으로 진화하고 있다. 이는 단순히 기술적인 문제가 아니라, **보안 예산, 인력, 시스템의 부재**와 같은 현실적인 문제에서 기인한다.
- **중소기업 공격 집중/피해** : 대기업, 공공기관에 비해 보안 투자가 미흡한 중소기업은 해커들의 주요 타깃이 된다. 이는 **대기업과의 협업, 납품 관계(공급망)**를 통해 대기업 시스템으로 침투하기 위한 시발점이 되기도 한다. 이와 같이 공격자가 보안이 약한 협력사를 통해 주요 타깃에 접근하는 공격을 **공급망 공격(Supply Chain Attack)**이라고 한다.
- **공격 비중과 심각도**
    - **SQL 인젝션**처럼 **공격 비중이 높은 공격**은 기술적인 난이도가 낮고, 보안 수준이 낮은 다수의 중소기업을 대상으로 쉽게 성공할 수 있다는 것을 의미한다. 이를 감기처럼 확산은 쉽지만, 심각도는 높은(99%) 공격이라고 표현할 수 있다.
    - 반면, **공격 비중이 낮은 공격**은 고도의 해킹 기술을 요구하며, 발생 빈도는 낮지만 성공 시 파급력이 커서 마치 암처럼 치명적인 피해를 줄 수 있다.
- **SQL 인젝션 공격**
    - **개념** : 악의적인 SQL 구문을 웹 페이지의 입력 폼에 삽입하여 데이터베이스를 조작하는 공격이다.
    - **사례** : 여기어때, 뽐뿌 해킹 사건처럼, SQL 인젝션은 관리자 계정 탈취나 대량의 개인정보 유출로 이어져 치명적인 피해를 준다. 이는 웹과 연결된 DB가 외부에서도 접근 가능한 환경에서 DB 질의에 대한 **입력값 검증 절차가 미흡했기 때문**에 발생했다.
- **DDoS(디도스) 공격**
    - **개념** : 다수의 PC 또는 IoT 기기를 감염시켜 특정 서버에 대량의 트래픽을 집중적으로 보내어 시스템을 마비시키는 공격이다.
    - **특징** : DDoS는 탐지 및 우회만 가능하며, 완벽한 방어가 어렵다. 따라서 **DDoS 대피소**와 같은 전문 서비스를 통해 공격 트래픽을 분산, 완화시키는 것이 일반적이다.
    - **IoT 기기 활용** : CCTV 등 저전력, 소형화된 **IoT 기기가 좀비 PC로 활용**되는 경우가 늘고 있다. 이들 기기는 패치/업데이트가 어렵고, 보안 기능이 취약하여 DDoS 공격에 악용되기 쉽다. 이러한 IoT 기기를 활용한 봇넷의 대표적인 사례가 **미라이 봇넷(Mirai Botnet)**이다.
    - **개인 영상정보 보호** : CCTV, 드론 등 영상정보 처리 기기가 늘어나면서 **개인 영상정보 보호**에 대한 중요성이 커지고 있다. 개인정보보호위원회에서 관련 안내서를 제공하고 있다.
- **파밍 공격**
    - **개념** : 악성코드를 통해 사용자를 **정상 사이트와 똑같이 생긴 가짜 사이트**로 유도하여 금융 정보 등을 탈취하는 공격이다.
    - **공격 유형**
        - **피싱(Phishing)** : 전화나 이메일로 사기성 정보를 보내는 방식
        - **스미싱(Smishing)** : SMS(문자)를 이용한 사기
        - **메모리 해킹** : 메모리에서 실행되는 금융 앱의 기능을 후킹하여 정보를 탈취하는 공격
    - **유포 방식** : 웹하드 프로그램, 보안이 취약한 웹사이트, **업데이트 서버, 공유 폴더(NAS) 서버 등**을 통해 악성코드를 유포한다. 특히 **AD 서버(Active Directory Server)**와 같은 핵심 인프라가 해커들의 주요 표적이 된다.
    - **공급망 공격과의 연관성** : 보안 소프트웨어, 금융 시스템 등 **SW 업데이트 체계의 취약점**을 노려 악성코드를 유포하는 것 또한 공급망 공격의 일종이다.
- **DBD(Drive by Download) 공격**
    - **개념** : 사용자가 웹사이트에 방문하는 것만으로도 악성코드가 자동으로 다운로드되어 감염되는 공격이다.
    - **워터링홀(Watering Hole) 공격** : 특정 집단이 자주 방문하는 웹사이트를 미리 감염시켜놓고, 해당 집단이 접속하면 악성코드를 유포하는 방식이다.

### 2. 웹 해킹 및 취약점 기준

#### 웹 해킹의 발전 배경과 OWASP
- **웹 해킹 발전 배경** : 인터넷이 시작되면서 **웹(WEB)을 통해 데이터베이스(DB)가 외부와 연결**되기 시작했고, 이에 따라 웹을 통한 해킹(웹 해킹)이 가능해졌다.
- **OWASP (Open Web Application Security Project)** : 웹 보안 취약점을 연구하고 정보를 공유하는 비영리 단체이다.
    - **OWASP Top 10** : 웹 애플리케이션에서 가장 흔하고 치명적인 **10대 보안 취약점 목록**을 발표한다. 이 목록은 웹 해킹 공격의 주요 지표이자, 웹 보안 전문가들의 필수 참고 자료이다.
- **제로 데이 vs. 올드 데이 공격**
    - **제로 데이(Zero-Day) 공격** : 아직 패치가 공개되지 않은 취약점을 이용한 공격.
    - **패치(올드 데이) 공격** : 패치가 공개되었지만, 보안 관리 소홀로 패치되지 않은 시스템을 대상으로 하는 공격. 대부분의 해킹 공격은 패치가 공개된 후 **6개월~1년의 시간** 동안 패치되지 않은 시스템을 노리는 `올드 데이` 공격에 해당한다.

#### CWE/SANS Top 25
- **CWE (Common Weakness Enumeration)** : 소프트웨어의 취약점 유형을 분류하고 식별하는 목록
- **SANS Top 25** : SANS 기관에서 선정한 소프트웨어 개발 시 가장 위험한 25가지 취약점 목록

#### 웹 취약점 진단 기준
웹 취약점 진단은 다양한 기준에 따라 수행된다. 국가/기관별로 중요한 정보 자산의 취약점을 평가하기 위한 기준이 마련되어 있다.
- **KISA(한국인터넷진흥원)** : SW 개발 보안 가이드
- **국정원** : 홈페이지 8대 취약점
- **과기정통부** : 주요정보통신기반시설 기술적 취약점 분석평가
- **금융보안원** : 전자금융기반시설 기술적 취약점 분석평가 기준

#### 모의침투테스트 (Penetration Testing)
- **개념** : 합법적인 방법으로 시스템에 침투를 시도하여 보안 취약점을 발견하고 보고하는 테스트이다.
- **분류**
    - **블랙 박스 테스트(Black Box Test)** : 외부에서 공격자가 아는 정보가 전혀 없는 상태에서 진행
    - **화이트 박스 테스트(White Box Test)** : 내부 정보(소스 코드, 아키텍처 등)를 모두 아는 상태에서 진행
    - **그레이 박스 테스트(Grey Box Test)** : 일부 정보만 알고 진행
- **고려사항** : 단순히 기술적인 취약점뿐만 아니라, **사회공학적 공격**이나 **사용자의 보안 의식**과 같은 인적 요인도 고려해야 한다.

#### 버그헌팅과 모의해킹

- **버그 (Bug)** : 개발자의 실수로 발생하는 오류
- **퍼징(Fuzzing)** : 시스템에 무작위의 데이터를 입력하여 비정상적인 동작을 유발하고 취약점을 찾는 기법
- **버그 헌팅(Bug Hunting)** : **개발자의 실수(Bug)**를 찾아내는 데 초점을 맞춘 활동
- **모의 해킹(Penetration Testing)** : **전체 시스템의 보안 취약점**을 실제 공격자의 시나리오에 따라 종합적으로 점검하는 활동
    - **모의 해킹 과정** : 논문 작성과 유사하게, **가설 수립 -> 검증 -> 보고서 작성 -> 재현**의 체계적인 과정을 거친다

### 3. 웹 애플리케이션 취약점: 위험 분석 기준
보안 취약점을 발견하면, 그 위험도를 정확하게 분석해야 효과적인 대응이 가능하다.

#### OWASP Top 10 2013 vs 2017
- **새롭게 선정된 취약점 (2017)**
    - **A4: XML External Entity(XML 외부 개체)** : XML 파서의 취약점을 이용해 외부 엔티티 파일을 참조하여 민감 정보를 유출하는 공격.
    - **A8: Insecure Deserialization(안전하지 않은 역직렬화)** : 데이터 직렬화/역직렬화 과정의 취약점을 이용해 악성 객체를 삽입하는 공격.
    - **A10: Insufficient Logging & Monitoring(불충분한 로깅 및 모니터링)** : 공격 발생 시 로그 기록이 불충분하여 침해사고 분석이 어려운 경우.

#### 위험 분석 기준
- **위협 요인**
    - **위협원** : 위협을 야기하는 주체(개인, 그룹, 국가 등).
    - **공격 벡터** : 공격을 실행하는 방법.
    - **보안 취약점** : 잠재적인 결함.
- **영향 요인**
    - **보안 통제** : 보안 취약점 대응 방안.
    - **기술적 영향** : 시스템 자산과 기능에 미치는 영향.
    - **비즈니스 영향** : 조직의 사업적 손실.
- **위험 등급** : 공격 가능성과 영향도를 종합하여 등급을 매긴다.
    - **공격 가능성** : 쉬울수록 위험.
    - **취약점 확산 정도** : 광범위할수록 위험.
    - **취약점 탐지 정도** : 탐지가 쉬워 널리 알려진 취약점일수록 공격자의 표적이 될 가능성이 높아 위험.
    - **기술적/비즈니스 영향** : 영향이 클수록 위험.

### 4. 웹 해킹 과정 분석
웹 해킹은 공격자가 특정 목표를 가지고 체계적으로 접근하는 일련의 과정이다. 이 과정을 분석하면 방어자는 공격자의 의도를 파악하고 효과적으로 대응할 수 있다.

#### 1. 공격 대상 선정
- **해킹 과정의 시작** : 공격자는 무작위로 공격하는 것이 아니라, 먼저 **공격 표면(Attack Surface)**을 식별한다. 공격 표면은 시스템이 외부에 노출되어 공격자가 접근할 수 있는 모든 부분을 의미한다. 이를 매트릭스 형태로 정리하고, 공격 성공률이 높을 것으로 예상되는 취약점부터 하나씩 시도한다.
- **일반적인 공격 대상** : 방문자가 많은 웹사이트는 공격 성공 시 얻을 수 있는 정보(개인정보, 고객 데이터 등)의 양이 많기 때문에 해커의 주요 표적이 된다. 또한, 이러한 웹사이트의 다운로드는 악성코드를 유포하는 통로로도 사용될 수 있다.

#### 2. 정보 수집
- **정보 수집의 중요성** : 해킹의 성공은 공격 대상에 대해 얼마나 많은 정보를 확보했는지에 따라 크게 달라진다.
- **구글 해킹** : **구글(Google)이나 쇼단(Shodan) 같은 검색 엔진**을 활용하여 공격 대상의 숨겨진 정보를 찾아내는 기법이다. 예를 들어, `site:example.com filetype:pdf`와 같은 구문을 사용하면 `example.com` 도메인 내에 있는 모든 PDF 파일을 검색할 수 있다. 이는 외부에 공개되면 안 되는 중요한 문서나 설정 파일을 찾아내는 데 악용될 수 있다.
- **자동화 도구**
    - **Nmap (Network Mapper)** : 공격 대상 서버의 **열려있는 포트, 운영체제, 서비스 버전 등**을 스캔하여 정보를 수집하는 도구이다. 이를 통해 공격자는 어떤 서비스에 취약점이 있을지 예측할 수 있다.
    - **Advanced Port Scanner** : Nmap과 유사하게 포트를 스캔하여 네트워크 상태를 파악하는 도구이다.

#### 3. 취약점 분석
- **CVE (Common Vulnerabilities and Exposures)** : 전 세계적으로 알려진 보안 취약점 목록이다. 정보 수집 단계에서 파악한 서비스 버전 등을 CVE 데이터베이스와 비교하여, **공격 대상에 존재하는 알려진 취약점**을 찾아내는 과정이다. 이는 해커들이 가장 먼저 시도하는 방법 중 하나이다.

#### 4. 공격
- **무차별 대입 공격 (Brute-Force)** : Brutus, Bruter와 같은 도구를 사용해 모든 가능한 비밀번호 조합을 시도하여 계정을 탈취하는 공격이다. 최근에는 `크리덴셜 스터핑` 공격이 더 많이 사용된다.
- **DoS 공격 (Denial of Service)** : 단일 시스템으로 서버에 과도한 트래픽을 보내어 서비스를 마비시키는 공격이다. DDoS(분산 서비스 거부)는 여러 시스템을 이용해 공격하는 방식이다.
- **웹쉘(Web Shell)** : 공격자가 웹 서버에 악성 스크립트를 업로드하여 **서버를 원격으로 제어**하는 백도어 프로그램이다. **C99Shell, Phpspy** 등이 대표적인 웹쉘입니다. 웹쉘은 서버의 파일 시스템을 탐색하고, 파일을 업로드/삭제하며, 명령어를 실행하는 등의 기능을 제공한다.
- **클라우드 환경에서의 공격** : 클라우드에서는 **Azure 랜딩존(Landing Zone)**이나 **AWS Control Tower**와 같은 클라우드 거버넌스 도구를 사용하여 보안을 강화한다. 하지만 이러한 설정에 허점이 있거나, 웹 애플리케이션에 웹쉘이 설치될 경우 클라우드 인프라 전체가 위협에 노출될 수 있다.

#### 5. 백도어 은닉
- **백도어(Backdoor)** : 정상적인 인증 절차를 우회하여 시스템에 접근할 수 있도록 의도적으로 만들어진 '숨겨진 문'이다. 개발자가 테스트나 관리 편의를 위해 만들기도 하지만, 해커가 침투 후 장기적인 접근을 위해 심어놓기도 한다.
    - **백도어의 종류**
        - **로컬 백도어** : 시스템에 직접 접근해야만 사용할 수 있는 백도어.
        - **시스템 설정 변경 백도어** : `계정 추가, 권한 상승` 등 시스템 설정을 변경하여 접근 권한을 유지하는 백도어.
        - **원격 백도어** : 네트워크를 통해 외부에서 시스템에 접근할 수 있는 백도어.
        - **원격 GUI 백도어** : 원격 데스크톱과 같이 GUI 환경으로 시스템을 조작할 수 있는 백도어.
- **키보드 스트로킹 (Keylogging)** : 사용자가 키보드에 입력하는 모든 내용을 가로채는 해킹 기법이다. `패스워드 크래킹`은 백도어를 통해 획득한 정보나 `키보드 스트로킹`으로 수집한 정보를 분석하여 비밀번호를 알아내는 것을 의미한다.

### 실습 주제 2: 공급망 보안 관련 실습 (Log4j 구성요소 관리)
1. 환경 설정 : Windows PowerShell을 이용하여 Java 8을 설치하고, 실습을 위한 작업 디렉터리를 생성
2. 취약한 환경 구축 : 원격 코드 실행 취약점(CVE-2021-44228)이 있는 Log4j 2.14.1 버전 라이브러리를 다운로드. 이 라이브러리를 사용하는 간단한 자바 애플리케이션을 직접 작성하여 취약한 환경을 만들었음.
3. 취약점 확인 : 작성된 애플리케이션을 실행하고, **Log4j 취약점 스캐너(알약 스캐너)**를 사용하여 취약한 라이브러리가 존재함을 확인
4. 보안 패치 : 취약점을 해결하기 위해 Log4j 2.20.0 버전의 안전한 라이브러리를 다운로드
5. 패치 확인 : 패치된 라이브러리를 사용하여 애플리케이션을 다시 실행하고, 스캐너를 재실행하여 취약점이 더 이상 탐지되지 않음을 확인하여 패치가 성공적으로 적용되었음을 검증

결론적으로, 이 실습을 통해 **'오래되고 취약한 구성요소를 사용하면 보안 문제가 발생할 수 있으며, 최신 버전으로 업데이트하는 것이 중요하다'**는 점을 체험할 수 있었다.
