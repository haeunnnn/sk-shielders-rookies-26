## 🧠 주요 개념 정리

### OT: 진로 탐색 및 현실 인식

#### 직(職)과 업(業)의 분리
'**직**'은 특정 직무나 역할을 의미하고, '**업**'은 개인이 추구하는 가치나 전문성을 의미한다. 예를 들어, '정보보안 전문가'라는 직을 가졌다고 해서 모두 같은 일을 하는 것이 아니다. 어떤 전문 분야(웹 취약점 분석, 악성코드 분석, 보안 컨설팅 등)에 집중할 것인지, 어떤 가치(사회 공헌, 기술 혁신 등)를 추구할 것인지 고민하는 것이라고 볼 수 있다. 이렇게 직과 업을 분리해서 생각하면, 단순히 직무를 넘어선 개인의 커리어 목표를 명확히 할 수 있다.

#### 신입으로서 갈 수 있는 곳과 전공자로서 가고 싶은 곳
정보보안 분야는 진입 장벽이 높은 편이다. 신입이라면 당장 가고 싶은 대기업 보안 팀이나 유명 컨설팅 펌에 바로 입사하기 어려울 수 있다. 하지만 중소기업의 보안 운영팀, 보안 솔루션 개발사, 또는 보안 관제 업무 등 실질적으로 경험을 쌓을 수 있는 곳을 고려하며 현실적인 목표를 세우는 것이 중요할 것이다. 동시에, 궁극적으로 어떤 전문성을 갖춘 전문가가 되고 싶은지에 대한 장기적인 비전을 갖는다면, 현재의 노력이 미래의 목표와 연결될 것이다.

### 오전 워밍업: 스마트홈 보안 취약점
- 위험성 : 스마트 도어록, 차량 제어 시스템, 스마트 난방 시스템 등은 인터넷에 연결되어 원격 제어가 가능하다. 만약 이러한 기기들의 인증 절차나 통신 프로토콜에 취약점이 있다면, 외부의 악의적인 공격자가 해당 취약점을 이용해 코드를 변경하거나 명령을 전송하여 무단으로 기기를 제어할 수 있다. 이는 단순히 불편함을 넘어 사생활 침해, 재산 피해, 심지어 생명까지 위협할 수 있는 심각한 문제로 이어질 수 있다.
- 사례 : 과거 스마트 도어록의 비밀번호 유출 취약점, 스마트홈 허브의 무단 접근 취약점 등이 보고된 바 있다. 이러한 취약점은 해커가 집을 비운 사이 도어록을 열거나, 난방 시스템을 과열시켜 화재를 유발하는 등의 실제 피해로 이어질 수 있다.
- 대응 : 스마트홈 기기 제조사는 보안을 최우선으로 고려하여 제품을 설계하고, 주기적인 보안 업데이트를 제공해야 한다. 사용자 또한 기본 비밀번호를 변경하고, 최신 펌웨어 업데이트를 유지하며, 불필요한 원격 제어 기능을 비활성화하는 등의 노력이 필요하다.

### 1. 인터넷
인터넷은 정보 공유의 혁명을 가져왔지만, 보안 관점에서는 그 자체로 거대한 **공격 표면(Attack Surface)** 이 될 수 있다.

- **편의성 vs 보안성**
    - 인터넷은 전 세계의 컴퓨터와 사람들을 연결하여 정보 교환, 협업, 엔터테인먼트 등 무한한 가능성을 제공한다. 하지만 이 연결성 때문에 한 곳의 취약점이 전체 네트워크에 영향을 미칠 수 있으며, 악의적인 공격자가 쉽게 접근할 수 있는 통로를 제공한다. 이것이 바로 인터넷의 **양면성**이다.
- **클라우드/제3자 서비스의 위험요소 모니터링 확장 - 금융보안원 사례**
    - 클라우드 컴퓨팅과 다양한 제3자(Third-Party) 서비스(SaaS, PaaS 등)의 확산은 기업의 IT 환경을 더욱 복잡하게 만들고 있다. 기존의 온프레미스(사내 구축형) 시스템과는 달리, 클라우드 환경에서는 데이터가 외부에 존재하고 다양한 서비스 제공자의 인프라를 사용하게 되는데 이로 인해 **보안 책임의 분산(Shared Responsibility Model)** 이 발생하고, **공격 표면이 넓어진다.** 
    - 금융보안원이 클라우드 및 제3자 서비스까지 모니터링 기술을 확대하는 이유는, 이러한 새로운 환경에서 발생할 수 있는 보안 위험요소를 조기에 식별하고 대응하기 위함이다. 이는 기업이 사용하는 외부 서비스의 보안 취약점이 곧 자신의 보안 취약점으로 이어질 수 있음을 인식하고, 이를 관리해야 한다는 의미이다.
- **Surface Web / Deep Web / Dark Web**
    - **Surface Web (표층 웹)** : 구글, 네이버 등 일반적인 검색 엔진으로 접근하고 검색할 수 있는 웹 페이지들을 의미한다. 우리가 일상적으로 사용하는 대부분의 웹사이트가 여기에 해당한다.
    - **Deep Web (심층 웹)** : 일반 검색 엔진으로는 검색되지 않지만, 특정 조건(로그인, 데이터베이스 쿼리 등)을 통해 접근할 수 있는 웹 페이지들이다. 온라인 뱅킹, 웹 메일, 클라우드 저장소, 유료 스트리밍 서비스 등이 대표적이다. 불법적인 내용보다는 **개인 정보나 제한된 정보**가 많다.
    - **Dark Web (다크 웹)**: 특정 소프트웨어(예: Tor 브라우저)를 통해서만 접근할 수 있는 익명화된 네트워크이다. 주로 불법적인 활동(마약 거래, 불법 무기 판매, 개인 정보 유출, 해킹 도구 거래 등)에 사용되지만, 언론의 자유가 억압된 국가의 시민들이 익명으로 정보를 교환하는 등 긍정적인 용도로도 사용되기도 한다.
    - **보안 대응책**
        - **다크웹 유출 정보 찾기 서비스** : **개인 정보 유출은 심각한 위협**이며, 유출된 정보는 다크웹 등에서 불법적으로 거래될 수 있다. 행정안전부의 '털린 내 정보 찾기' 서비스는 사용자에게 자신의 개인 정보가 다크웹에 유출되었는지 확인할 수 있도록 돕는 서비스이다. 이는 유출 사실을 인지하고 추가적인 피해를 막기 위한 첫걸음이 된다.
- **ASM (Attack Surface Management, 공격 표면 관리)** : 공격 표면은 해커가 시스템에 접근하거나 공격할 수 있는 모든 잠재적인 진입점을 의미한다. 웹 애플리케이션, 네트워크 포트, API, 클라우드 설정, 심지어 직원의 모바일 기기까지 포함될 수 있다. ASM은 기업의 **공격 표면을 지속적으로 식별, 분석, 모니터링하여 줄이는 활동**이다. 공격자가 악용할 수 있는 지점을 최소화하여 보안 위협을 낮추는 것이 목표이다.
- **제로 트러스트 보안** : '아무것도 신뢰하지 않고, 모든 것을 검증하라(Never Trust, Always Verify)'는 원칙을 기반으로 한다.
    - **기존 보안 모델의 한계** : 전통적인 보안 모델은 내부 네트워크를 '신뢰 구역'으로 간주하고 외부에 방어벽을 구축했다. 하지만 클라우드 전환, 원격 근무 확산, 서드파티 서비스 이용 등으로 인해 **내부와 외부의 경계가 모호**해지면서, 경계 기반 보안만으로는 충분하지 않게 되었다. 내부자가 악의적인 행동을 하거나, 외부 공격자가 한 번 침투하면 내부 네트워크에서 자유롭게 이동할 수 있는 문제가 발생했다.
    - **제로 트러스트의 필요성** : 제로 트러스트는 사용자, 기기, 애플리케이션, 데이터 등 **모든 접근 시도에 대해 지속적으로 인증하고 권한을 부여**한다. 즉, 내부에 있든 외부에 있든 상관없이 모든 주체와 통신을 의심하고 검증함으로써, **단일 침해 지점(Single Point of Failure)을 최소화**하고 공격자가 네트워크 내에서 횡적으로 이동하는 것을 어렵게 만든다. SKT와 같은 대기업이 제로 트러스트를 도입하는 것은 복잡해지는 IT 환경에서 더욱 강력하고 유연한 보안 체계를 구축하기 위함이다.

#### 망분리
망분리는 네트워크를 물리적 또는 논리적으로 분리하여 보안을 강화하는 방법이다.
- **목적**
    - **내부 정보 유출 차단** : 업무망(내부망)에 중요 정보를 보관하고, 인터넷망(외부망)과의 직접적인 연결을 차단하여 내부 정보가 외부로 유출되는 것을 방지한다.
    - **외부 악성코드 유입 차단** : 인터넷망을 통해 유입될 수 있는 악성코드나 해킹 공격이 업무망으로 전파되는 것을 막는다.
- **종류**
    - **물리적 망분리** : 인터넷이 가능한 PC와 업무용 PC를 아예 별도의 물리적 장비로 분리하는 방식이다. 가장 강력한 보안을 제공하지만, 비용이 많이 들고 사용자 불편이 크다는 단점이 있다.
    - **논리적 망분리** : 하나의 PC에서 가상화 기술 등을 이용해 논리적으로 인터넷망과 업무망을 분리하는 방식이다. 물리적 망분리보다는 비용이 적게 들고 유연성이 높지만, 가상화 환경 자체의 취약점에 노출될 가능성이 있다.
- **엔드포인트 보안 강화**: 망분리 환경에서 인터넷망 PC는 외부망에 연결되어 있어 악성코드 감염 위험이 높으므로, 백신, EDR(Endpoint Detection and Response) 등 엔드포인트 보안 솔루션을 통해 지속적으로 감시하고 위협에 대응해야 한다.
- **망분리 완화의 딜레마**
    - **문제점** : 망분리는 보안을 강화하지만, 업무의 효율성을 크게 저해한다. 인터넷이 불가능한 업무망 PC에서는 최신 기술(ChatGPT, AWS, 클라우드 기반 데이터 분석 라이브러리, API, SaaS 등)을 활용하기 어렵다. 이는 기업의 혁신과 성장 동력을 훼손할 수 있다.
    - **해결책** : 이러한 문제 때문에 최근에는 망분리 정책을 완화하려는 시도가 있다. 하지만 망분리가 완화되면 그만큼 **보안 위협에 노출될 가능성이 커지므로, 완화되는 정도에 비례하여 다른 보안 통제(예: 제로 트러스트, 강력한 인증, 접근 제어 등)를 강화**해야 한다. 즉, '편의성'과 '보안성' 사이에서 균형점을 찾아야 하는 것이다.

#### 인공지능이 주는 장점과 단점 (정보보호 관점)
AI는 4차 산업혁명의 핵심 동력이며, 정보보호 분야에도 큰 영향을 미친다.
- **AI의 역할** : 인공지능은 단순히 데이터를 처리하는 것을 넘어, **초지능화된 결과물(초지능화된 분석, 예측, 자동화 등)** 을 만들어낸다. BI(Business Intelligence)가 과거 데이터를 분석하여 비즈니스 의사결정을 돕는다면, AI는 더 나아가 **미래를 예측하고, 복잡한 비정형 데이터를 처리하며, 사람의 의사결정을 자동화 또는 보조**한다.
- **정보보호 환경의 변화 촉진**
    - **데이터의 폭증 및 다양화** : AI 시스템은 방대한 양의 정형, 비정형, 반정형 데이터를 필요로 하며, 이는 **관리해야 할 정보의 양과 복잡성**을 기하급수적으로 늘린다. 민감한 데이터의 유출 위험이 커지고, 데이터 무결성 확보가 더욱 중요해진다.
    - **고속 데이터 처리 및 실시간 응답** : DevSecOps(Development, Security, Operations)와 같이 개발-보안-운영이 유기적으로 통합되어 빠른 속도로 소프트웨어를 개발하고 배포하는 환경에서는, 보안 역시 **실시간으로 위협을 감지하고 대응**해야 한다. 전통적인 보안 방식으로는 이러한 속도를 따라잡기 어렵다.
    - **분산 병렬 트랜잭션 및 API 기반 서비스** : 마이크로서비스 아키텍처, 분산 시스템, 클라우드 환경에서는 데이터 처리 및 트랜잭션이 여러 시스템에 걸쳐 분산되고 병렬적으로 이루어진다. 또한, 서비스 간의 연동은 대부분 API(Application Programming Interface)를 통해 이루어진다. 이는 **API 보안, 클라우드 보안, 그리고 분산 환경에서의 인증 및 권한 관리**를 매우 중요하게 만든다. 클라우드는 그 자체가 수많은 API의 집합체이므로, API 취약점은 전체 시스템의 보안을 위협할 수 있다.
- **높은 투자 비용** : 이러한 변화에 대응하기 위해서는 AI 기반 보안 솔루션 도입, 전문 인력 양성, 지속적인 시스템 개선 등에 **많은 비용과 자원 투자**가 필요하다.

#### 인터넷의 공평성
"인터넷은 누구에게나 공평하다"는 말은, 인터넷에 연결된 모든 장치가 차별 없이 접근될 수 있다는 점에서 사실이다. 하지만 이는 동시에 **보안에 대한 무관심이 큰 위협으로 다가올 수 있음**을 의미한다.
- **Shodan (쇼단)** : 일반적인 검색 엔진이 웹 페이지의 텍스트 콘텐츠를 검색한다면, 쇼단은 **인터넷에 연결된 장치(서버, 라우터, IoT 기기, CCTV 등)의 배너(banner) 정보**를 검색하는 엔진이다. 배너 정보에는 장치의 종류, 버전, 개방된 포트, 서비스 정보 등이 포함된다.
    - **그레이햇의 특징** : 쇼단은 단순히 정보를 수집하는 도구이며, 그 자체로는 선하거나 악하지 않다. 이는 **그레이햇 해커(White Hat과 Black Hat의 중간)의 특징**을 가진다고 볼 수 있다. 보안 연구자, 대학원생, 벤더들은 쇼단을 활용하여 전 세계 네트워크의 취약점을 분석하고, 보안 연구를 수행하며, 새로운 위협 동향을 파악한다. 즉, 긍정적인 보안 강화 목적으로 사용될 수 있다.
    - **블랙햇의 오용** : 그러나 악의적인 해커(블랙햇)들은 쇼단을 이용해 쉽게 공격 대상을 식별하고, 특정 취약점을 가진 장치들을 찾아내 공격에 활용한다. 예를 들어, **디폴트 비밀번호가 설정된 CCTV, 외부에 노출된 데이터베이스 서버, 오래된 버전의 웹 서버** 등을 쇼단으로 찾아낸 후, 무차별 대입 공격(Brute Forcing)이나 알려진 취약점을 이용한 공격을 시도할 수 있다.
- **무법지대 가능성** : 인터넷에 연결된 수많은 장치들이 제대로 관리되지 않고 정보가 무분별하게 공개된다면, 이는 곧 해커에게 **무방비 상태의 공격 표면**을 제공하는 것과 같다. 이는 인터넷을 잠재적인 '무법지대'로 만들 위험을 내포한다.
- **실제 공격 사례** : 쇼단을 이용한 공격은 실제 디도스(DDoS) 공격의 좀비 PC 양산, 악성코드 배포, 관리되지 않는 웹 서버 스캐닝, 스마트홈 기기에 대한 무차별 대입 공격 등으로 이어질 수 있다.

#### 인터넷 기본 서비스
**Telnet**
- **Default vs Hardening** : Telnet은 원격 접속을 위한 초기 프로토콜 중 하나이다.
    - **Default** : Telnet의 기본 설정은 보안에 매우 취약하다. 데이터가 암호화되지 않은 **평문(Plaintext)으로 전송**되어, 사용자 ID, 비밀번호 등 민감한 정보가 중간에 가로채기될 위험이 높다.
    - **Hardening** : '하드닝'은 시스템이나 애플리케이션의 **보안 설정을 강화**하는 과정을 의미한다. Telnet과 같은 취약한 서비스는 사용하지 않거나, 반드시 필요한 경우에만 최소한의 보안 설정(예: 특정 IP에서만 접속 허용, 복잡한 비밀번호 사용 등)을 적용해야 한다. 일반적으로는 **암호화된 SSH(Secure Shell)를 사용하는 것이 권장**된다.
- **수행 주체**
    - **직접 수행** : 기업이나 기관의 보안 담당자가 시스템 및 네트워크 장비의 보안 설정을 직접 관리하고 강화한다.
    - **간접 체크** : 보안 컨설턴트, 취약점 진단 전문가, 모의 해킹 전문가는 기업의 시스템에 대해 보안 취약점을 점검하고, 미흡한 부분을 보고하여 개선을 유도한다.
- **주요정보통신기반 시설 기술적 취약점 분석 및 평가 해설서** : KISA(한국인터넷진흥원)에서 제공하는 이러한 가이드라인은 국내 주요 정보통신 기반 시설의 보안 취약점을 분석하고 평가하는 데 필요한 기술적 기준과 방법을 제시한다. 기업들은 이 해설서를 참고하여 자체 시스템의 보안을 강화해야 한다.
- **Third-Party 고려** : VPN(Virtual Private Network)이나 다른 보안 솔루션을 도입할 때, 해당 솔루션 자체의 보안 취약점이 없는지, 그리고 서비스 제공업체(Third-Party)의 보안 수준이 충분한지 반드시 검토해야 한다.

**전자메일**
이메일은 여전히 주요 소통 수단이지만, 피싱, 스팸, 악성코드 유포의 주요 통로이기도 하다.
- **메일 서버 아키텍처** : 이메일 시스템은 크게 **송신용(SMTP) 서버와 수신용(POP3/IMAP) 서버**로 구성된다. 기업에서는 보통 그룹웨어(더존, Salesforce, SAP 등)를 통해 이메일을 포함한 다양한 협업 기능을 제공하는데, 이러한 그룹웨어는 사용자 수가 많고 중요한 정보가 오가는 만큼, **주요 보안 취약점 진단 대상**이 된다.
- **스팸 대응 (KISA 불법스팸대응센터)** : KISA는 불법 스팸을 차단하고 스팸 관련 민원을 처리하여 건전한 인터넷 환경을 조성하는 역할을 한다.
- **이메일 서버 보안 인증 메커니즘 (SPF, DKIM, DMARC)** : 이메일은 발신자 정보를 쉽게 위조할 수 있기 때문에, 스팸 및 피싱 공격에 취약하다. 이를 방지하기 위해 다음과 같은 표준 보안 인증 메커니즘이 사용된다.
    - **SPF (Sender Policy Framework)** : 특정 도메인에서 이메일을 보낼 수 있는 권한이 있는 메일 서버의 IP 주소를 지정한다. 수신 서버는 SPF 레코드를 확인하여 발신 메일 서버의 IP가 해당 도메인의 승인된 IP인지 검증한다.
    - **DKIM (DomainKeys Identified Mail)** : 발신자가 이메일에 디지털 서명을 추가하여, 수신자가 이메일 내용이 전송 중에 위변조되지 않았음을 확인할 수 있도록 한다.
    - **DMARC (Domain-based Message Authentication, Reporting & Conformance)** : SPF와 DKIM을 통합하여 이메일 인증 정책을 강화한다. 인증에 실패한 이메일에 대해 수신 서버가 어떻게 처리할지(거부, 격리, 허용) 정책을 명시하고, 발신자에게 인증 실패 보고서를 전송하여 이메일 보안을 개선할 수 있도록 돕는다.
- **메일은 불법 스팸과의 싸움** : 이러한 보안 인증 메커니즘에도 불구하고, 이메일은 여전히 대량의 스팸과 정교한 피싱 공격의 대상이 된다. 따라서 사용자들은 항상 의심스러운 메일을 주의하고, 기업은 지속적으로 이메일 보안 시스템을 강화해야 한다.

### 오후 워밍업: 망분리 완화 금융 '갈라파고스 규제'의 변화
망분리는 한때 강력한 보안 통제 수단이었지만, **급변하는 IT 환경과 기술 트렌드** 앞에서 그 효용성과 효율성에 대한 재검토가 이루어지고 있다. '갈라파고스 규제'는 특정 지역이나 국가에서만 적용되는 고립된 규제를 의미하는데, 한국의 강력한 망분리 규제가 이에 비유되기도 했다.
- **생성형 AI 및 클라우드(SaaS) 도입** : 생성형 AI와 클라우드 기반 SaaS(Software as a Service)는 현재 IT 혁신의 핵심 동력이다.
    - **생성형 AI** : 방대한 데이터를 학습하고 실시간으로 추론해야 하므로, 인터넷 연결과 클라우드 컴퓨팅 자원이 필수적이다. 망분리 환경에서는 이러한 AI 서비스를 업무에 활용하기가 매우 어렵다.
    - **클라우드(SaaS)** : Salesforce, Microsoft 365, Google Workspace 등 수많은 SaaS 서비스는 인터넷을 통해 제공된다. 망분리는 SaaS 사용을 원천적으로 차단하여 기업의 생산성과 유연성을 저해한다.
    - **클라우드 보안 / 생성형 AI 보안** : 망분리 완화는 클라우드 및 생성형 AI 사용을 허용하는 대신, 이들 환경에 특화된 새로운 보안 체계를 요구한다. 이는 **클라우드 설정 오류 방지, API 보안, 데이터 암호화, 접근 제어 강화, AI 모델의 오용 및 악용 방지** 등을 포함한다.
- **개인신용정보 처리 시 가명화(가명 처리) 요구**
    - **개인정보보호법 (데이터 3법 개정)** : 2020년 개정된 데이터 3법(개인정보보호법, 정보통신망법, 신용정보법)의 핵심 중 하나는 **가명 정보 활용 특례 규정**이다.
    - **가명 처리** : 개인정보의 일부를 삭제하거나 대체하여 특정 개인을 알아볼 수 없도록 하는 조치이다. 이렇게 가명 처리된 정보는 **정보 주체의 동의 없이도 과학적 연구, 통계 작성, 공익적 기록 보존 등을 목적으로 활용**할 수 있게 된다.
    - **개인정보 가명 처리 보안** : 가명 처리된 정보라도 재식별될 위험이 있으므로, 추가 정보와의 결합 방지, 안전한 저장 및 관리, 접근 통제 강화 등 **높은 수준의 보안 조치**가 요구된다. 이는 데이터 활용과 개인 정보 보호라는 두 가지 목표를 동시에 달성하기 위한 중요한 변화이다.
- **연구 개발 산출물의 물리적 망분리 예외 처리** : R&D 분야에서는 최신 기술과 데이터에 접근해야 하는 필요성이 크다. 따라서 특정 연구 개발 서버망에 대해서는 물리적 망분리 환경에서도 인터넷 연결을 예외적으로 허용하여, 생성형 AI 서비스에 데이터를 업로드하고 활용할 수 있도록 하는 정책적 변화가 나타나고 있다. 이는 **특정 목적에 한해 보안 위험을 관리하면서 유연성을 확보**하려는 시도이다.
- **모바일을 활용한 SaaS 접근/활용 (모바일 보안)**
    - 스마트폰, 태블릿 등 모바일 기기를 통한 업무 환경이 확산되면서, 이제는 모바일 기기에서도 SaaS 서비스에 접근하고 활용하는 것이 일반화되고 있다.
    - **보안솔루션 모바일 접근** : 이러한 모바일 환경에서의 보안을 강화하기 위해, MDM(Mobile Device Management), MAM(Mobile Application Management)과 같은 **모바일 보안 솔루션이 중요**해진다. 이를 통해 모바일 기기의 보안 설정 강제, 악성 앱 차단, 중요 데이터 유출 방지 등이 가능하다.
- **업무 환경의 복잡성 증가 및 CNAPP**
    - **다양한 접근 환경** : 현재 기업의 업무 환경은 더 이상 단순한 PC 기반이 아니고 **노트북, 데스크탑, 모바일 기기, 태블릿, 가상 머신(VM), 컨테이너** 등 다양한 형태의 기기와 환경에서 업무가 이루어진다.
    - **CNAPP (Cloud Native Application Protection Platform)** : 이러한 복잡한 클라우드 네이티브 환경(컨테이너, 서버리스, 마이크로서비스 등)에서 애플리케이션의 보안을 **통합적으로 관리**하기 위한 플랫폼이다. CNAPP은 코드부터 런타임 환경까지 전체 개발 수명 주기(SDLC)에 걸쳐 보안 취약점 관리, 클라우드 설정 오류 감지, 위협 탐지 및 대응 등 다양한 보안 기능을 제공하여, 분산된 업무 환경의 보안을 한데 묶어 효율적으로 관리할 수 있게 한다.

**FTP (File Transfer Protocol)와 악성코드**
파일 전송은 일상적인 작업이지만, 이 과정에서 악성코드가 유포될 수 있다.
- **파일 악성코드**
    - **정의** : 사용자가 **특정 파일(.exe, .scr, .lnk, .hta, .py, .ps1 등 실행 가능한 확장자)** 을 직접 실행했을 때 감염되는 형태의 악성코드이다. 흔히 이메일 첨부 파일이나 다운로드된 파일 형태로 유포된다.
    - **정적/동적 분석**
        - **정적 분석** : 악성코드를 실행하지 않고, 코드 자체를 분석하여 악성 행위를 예측하는 방법 (예: 문자열 분석, API 호출 목록 확인, 실행 파일 구조 분석)
        - **동적 분석** : 악성코드를 통제된 가상 환경(샌드박스)에서 **실제로 실행**시켜 그 행위를 관찰하고 분석하는 방법 (예: 파일 생성/삭제, 레지스트리 변경, 네트워크 통신 확인)
- **파일리스 악성코드 (Fileless Malware)**
    - **정의** : 이름처럼 **파일 형태로 디스크에 저장되지 않고** 메모리에서 직접 실행되거나, 합법적인 시스템 도구(PowerShell, WMIC, CMD 등)를 악용하여 동작하는 악성코드이다. 전통적인 파일 기반의 백신 솔루션으로는 탐지하기 어렵다.
    - **공격 방식**
        1. **오피스 파일 활용** : 사용자에게 **매크로가 포함된 오피스 파일(.xlsx, .pptx, .hwpx 등)**을 열도록 유도한다.
        2. **외부 파일(OLE) 참조 및 실행** : 매크로, 프로시저, ActiveX 등이 작동하여 외부의 악성 코드를 참조하거나, **.dll 파일 등 합법적인 라이브러리를 악용하여 악성 코드를 메모리에 로드**한다.
        3. **오피스 파일 삭제** : 악성코드가 메모리에서 동작을 시작하면, 유포에 사용된 오피스 파일을 삭제하여 흔적을 지운다.
        4. **쉘코드 실행** : 최종적으로 PowerShell, WMIC(Windows Management Instrumentation Command-line), CMD 등 **운영체제 내장 도구**를 이용하여 추가적인 악성 행위(정보 탈취, 원격 제어 등)를 수행한다.
    - **생성형 AI와의 연관성** : 생성형 AI는 이러한 파일리스 악성코드 생성 및 변형에 활용될 수 있다. 예를 들어, 탐지를 우회하는 새로운 매크로 코드 생성, 합법적인 도구를 악용하는 쉘코드 작성, 또는 사용자를 속이는 정교한 피싱 문서 제작 등에 AI가 사용될 위험이 있다.

**Q. 국가 기반망 구축이 지금까지 보안의 업권 형성에 영향을 준다?**
- 그렇다. 매우 큰 영향을 미쳤다. **각 국가 기반망의 특성과 규제가 해당 분야의 보안 산업 생태계와 전문가의 전문성 형성에 직접적인 영향**을 주었다.
- **망의 종류 및 특성**
    - **공공망** : 공공기관, 공기업, 공공서비스 관련 기관이 사용하는 망으로, **정보 공개, 대국민 서비스, 규제 준수**가 중요하다.
    - **정부행정망** : 입법, 사법, 행정부 등 국가의 주요 기능을 수행하는 망으로, **최고 수준의 기밀성과 무결성, 가용성**이 요구된다. (예: 정부24)
    - **금융망** : 은행, 증권, 보험 등 금융 서비스 제공 기관이 사용하는 망으로, **개인 정보 보호, 자산 보호, 거래의 신뢰성, 실시간 대응**이 절대적으로 중요하다. 금융 당국의 강력한 규제를 받는다.
    - **민간망** : 제조, 엔터테인먼트, 물류, 유통 등 다양한 사기업이 사용하는 망으로, **기업의 비즈니스 연속성, 지적 재산 보호, 고객 데이터 보호** 등이 주요 관심사이다. 규제보다는 자율적인 보안 강화가 주를 이룬다.
    - **국방망** : 군사 작전 및 국방 관련 정보를 다루는 망으로, **최고 수준의 기밀 유지, 외부 침투 방지, 전시에 대비한 가용성**이 최우선이다. (예: 사이버 사령부)
    - **국정원망** : 국가 정보 및 안보 관련 정보를 다루는 망으로, **극도의 기밀성과 은밀성, 정보 수집 및 분석 능력 보호**가 핵심이다.
- **업권 형성 및 전문성** : 각 망은 고유의 규제, 법규, 기술적 요구사항을 가진다. 이에 따라 각 망을 전문적으로 다루는 보안 기업(보안 솔루션 개발사, 컨설팅 회사, 관제 서비스 제공사 등)과 보안 전문가들이 성장하게 된다.
    - 예를 들어, 금융망 보안 전문가는 금융 관련 법규(전자금융감독규정 등)에 대한 이해와 금융 시스템의 특성(대량 트랜잭션, 계정계/정보계 등)에 대한 깊은 지식을 갖추게 된다.
    - 따라서 **'전문성은 업(해당 분야의 비즈니스 및 규제)에 대한 전문성과 보안에 대한 전문성이 합쳐지면서 나온다'**는 말은 매우 중요하다. 한 분야에서 쌓은 업에 대한 이해는 다른 분야로 이직 시 큰 장벽이 될 수 있다. 예를 들어 금융 보안 전문가는 제조업 보안으로 옮겨갈 때 해당 산업의 도메인 지식과 특수성을 다시 배워야 하는 경우가 많다.

### 2. 인터넷 프로토콜

#### IP와 DNS
- **IP (Internet Protocol)** : 인터넷에 연결된 모든 기기에 부여되는 고유한 주소
    - **공인 IP (Public IP)** : 인터넷상에서 직접 통신이 가능한 전 세계적으로 유일한 IP 주소이다. 외부에 공개되어 있다.
    - **사설 IP (Private IP)** : 특정 내부 네트워크(인트라넷) 내에서만 사용되는 IP 주소이다. 외부 인터넷에서는 직접 접근할 수 없다. (예: 192.168.x.x, 10.x.x.x 등)
- **NAT (Network Address Translation)**
    - 사설 IP를 사용하는 내부 네트워크의 기기들이 외부 인터넷(공인 IP)과 통신할 수 있도록, **사설 IP와 공인 IP를 변환(매핑)해주는 기술**이다. 이를 통해 소수의 공인 IP로 수많은 사설 IP 기기들이 인터넷을 사용할 수 있게 된다. (IP 주소 고갈 문제 해결 및 내부 네트워크 보호)
- **DNS (Domain Name System)**
    - 인터넷의 '전화번호부' 또는 '주소록'과 같이 사람들이 기억하기 쉬운 **도메인 이름(URL, 예: `www.naver.com`)을 컴퓨터가 이해하는 IP 주소로 변환(매핑)해주는 시스템**이다.
- **DNS의 재귀적 호출 구조 방식** : 사용자가 URL을 입력하면, DNS 서버들은 협력하여 해당 URL에 맞는 IP 주소를 찾아준다.
    1. **로컬 호스트 (hosts 파일)** : 사용자의 컴퓨터에 있는 `hosts` 파일은 가장 먼저 참조된다. 여기에 특정 URL에 대한 IP 주소를 직접 지정할 수 있다.
        - **보안 취약점** : **'DNS 포이즈닝(Poisoning)'이나 '파밍(Pharming)' 공격**에 악용될 수 있다. 해커가 `hosts` 파일을 변조하여 사용자가 정상적인 웹사이트 주소를 입력해도, 악성 사이트로 연결되도록 유도할 수 있다.
        - **대응** : `hosts` 파일에 대한 **쓰기 권한을 제한**하여 악의적인 변조를 막아야 한다.
    2. **내부 DNS 서버** : 회사나 ISP(인터넷 서비스 제공자)에서 운영하는 DNS 서버이다. 로컬 `hosts` 파일에 없으면 내부 DNS 서버에 질의한다.
        - **보안 필요성** : 내부 DNS 서버의 A 레코드(도메인-IP 매핑 정보) 값이 변조되지 않도록 **쓰기 제한, 보안 DNS 서버 도입** 등 강력한 보안 조치가 필요하다.
    3. **외부 DNS 서버**
        - **(3-1) `. (Root Domain)`** : ICANN (Internet Corporation for Assigned Names and Numbers)이 관리하는 최상위 루트 도메인 서버이다. 전 세계 모든 도메인 질의의 시작점이다.
        - **(3-2) `.com (Top-Level Domain, TLD)`** : ISP 등에서 관리하는 최상위 도메인 서버이다. `naver.com`의 `.com` 부분을 담당한다.
        - **(3-3) `naver.com`** : 도메인 주소 판매업자(등록기관)를 통해 등록된 실제 도메인 서버이다.
    - **오남용, 파밍, 피싱 접근 유도 방지** : DNS는 인터넷의 핵심 기반이므로, DNS에 대한 공격(DNS 스푸핑, 캐시 포이즈닝 등)은 사용자를 가짜 웹사이트로 유도하여 개인 정보를 탈취하거나 악성 코드를 유포하는 데 사용될 수 있다. 따라서 DNS 서버와 클라이언트 모두에서 **DNSSEC(DNS Security Extensions)** 와 같은 보안 강화 기술을 적용하여 무결성을 확보해야 한다.

#### HTTP
웹 브라우저와 웹 서버 간에 데이터를 주고받는 데 사용되는 프로토콜이다.
- **HTTP (Hypertext Transfer Protocol)** : 데이터를 암호화하지 않은 **평문(Plaintext)** 으로 주고받는다. 주로 내부 네트워크에서 사용되거나, 보안이 중요하지 않은 정보 전달에 사용될 수 있다.
- **HTTPS (HTTP Secure)** : HTTP에 **SSL/TLS 암호화 계층을 추가**한 프로토콜이다. 데이터가 암호화되어 전송되므로, 중간에 가로채기되더라도 내용을 알 수 없어 보안성이 높다. 주로 외부 인터넷 통신에 사용된다.
- **평문 통신 지양 및 암호화 통신 권장** : 민감한 정보(로그인 정보, 결제 정보 등)는 반드시 HTTPS를 통해 암호화되어 전송되어야 한다.
- **SSL Proxy (SSL 복호화)**
    - **문제점** : 최근에는 악성코드 유포자들이 HTTPS를 사용하여 암호화된 트래픽 내에 악성코드를 숨겨 유포하는 사례가 늘고 있다. 암호화된 트래픽은 일반적인 보안 솔루션이 내용을 들여다볼 수 없어 탐지가 어렵다.
    - **해결책** : **SSL Proxy (또는 SSL/TLS Inspection, SSL/TLS Offloading)**는 이러한 문제를 해결하기 위해 도입된다.
        - `외부 === HTTPS(암호문) === SSL Proxy === HTTP(평문) === 보안 솔루션 === HTTP(평문) === 내부`
        - SSL Proxy는 사용자(클라이언트)와 웹 서버(외부) 간의 **SSL 핸드셰이크 과정에 개입**하여, 암호화된 트래픽을 일단 **복호화(평문으로 전환)** 한다.
        - 복호화된 평문 트래픽을 방화벽, IPS(침입방지시스템), DLP(데이터 유출 방지) 등 **다른 보안 솔루션에 전달**하여 악성코드 유입 여부, 내부 정보 유출 시도 등을 **검사(Inspection)** 할 수 있도록 한다.
        - 검사가 끝나면 다시 암호화하여 목적지로 전송한다. 이는 보안을 강화하지만, 성능 저하와 프라이버시 침해 논란이 있을 수 있다.
- **Q. 클라우드 보안에서 SSL Proxy는 어떻게 지원될까?**
    - **A. 로드 밸런서(Load Balancer, LB) 단에서 지원된다.** 클라우드 환경에서는 여러 서버에 트래픽을 분산시켜 안정적인 서비스를 제공하는 로드 밸런서가 핵심 인프라이다.
    - **AWS ELB (Elastic Load Balancing)** : AWS의 로드 밸런싱 서비스에는 여러 종류가 있다.
        - **L7 LB (Application Load Balancer, ALB)** : HTTP/HTTPS 트래픽과 같은 애플리케이션 계층(OSI 7계층의 7계층)에서 동작하는 로드 밸런서이다. ALB는 **TLS Termination 기능**을 제공한다. 이는 클라이언트로부터 HTTPS 요청을 받아 ALB가 SSL/TLS 암호화를 **복호화**하고, 백엔드 서버(내부)로는 HTTP(평문)로 요청을 전달하거나, 다시 HTTPS로 암호화하여 전달할 수 있다. 이를 통해 백엔드 서버는 암호화 부담을 줄이고, ALB 단에서 보안 검사 또는 라우팅 규칙 적용이 가능해진다.

#### 암호: 국가별 규제와 표준
암호화는 데이터를 보호하는 핵심 기술이며, 국가별로 사용 가능한 알고리즘에 대한 규제가 있을 수 있다.
**Q. 대한민국에서 사용 가능한 암호 알고리즘의 종류 및 버전, 암호 강도는 정해져 있나?**
- **A. 그렇다, 국가정보원과 한국인터넷진흥원(KISA)에서 가이드라인을 제시하고 있다.** 특히 **국가 정보통신망 및 주요 정보통신 기반 시설 등에서는 국가에서 정한 특정 암호 알고리즘만 사용**하도록 강제하는 경우가 많다. KISA는 암호 이용 활성화를 위한 지침과 권장 알고리즘을 발표하여 민간 부문의 안전한 암호 사용을 독려한다.
- **암호 알고리즘 종류**
    - **대칭키 암호 알고리즘** : 암호화와 복호화에 같은 키를 사용한다. (예: SEED, LEA, HIGHT, ARIA, AES)
    - **공개키 암호 알고리즘** : 암호화에 공개키, 복호화에 개인키를 사용하는 방식이다. (예: RSA, ECC)
    - **일방향 암호 알고리즘 (해시 함수)** : 원본 데이터를 고정된 길이의 값으로 변환하며, 원본 데이터를 유추할 수 없도록 한다. 주로 데이터 무결성 검증, 비밀번호 저장 등에 사용된다. (예: SHA-256, SHA-384, SHA-512)
- **암호 강도 (Bits)** : 암호화에 사용되는 키의 길이를 의미하며, 길이가 길수록 더 강력한 보안을 제공한다. (예: ARIA-128/192/256, AES-128/192/256)
- **예시**: `SHA384withECDSA`, `SHA256withRSA` 등은 특정 해시 알고리즘(SHA-384, SHA-256)과 공개키 암호 알고리즘(ECDSA, RSA)을 결합하여 사용하는 방식이다.

| 구분 | 공공기관 | 민간부문 (법인, 단체, 개인) |
| --- | ------- | ------------------------ |
| 대칭키 암호 알고리즘 | SEED, LEA, HIGHT, ARIA | SEED, HIGHT, ARIA-128/192/256, AES-128/192/256, Camelia-128/192/256 등 |
| 공개키 암호 알고리즘 (메시지 암복호화) | RSAES-OAEP | RSA, RSAES-OAEP 등 |
| 일방향 암호 알고리즘 | SHA-224/256/384/512 | SHA-224/256/384/512, Whirlpool 등 |

**Q. 클라우드 보안이나 인공지능도 다 마찬가지 인가?**
- **A. 아니다.** 클라우드 보안, 인공지능 보안, 그리고 기타 IT 서비스의 보안은 **적용되는 규제, 국제 표준, 글로벌 협약 등이 각기 다르다.**
- **컨설팅 및 취약점 진단 시 중요성** : 보안 컨설턴트나 취약점 진단 전문가는 특정 시스템에 대해 진단을 수행할 때, **해당 시스템이 어떤 산업군에 속하고, 어떤 규제(예: 금융보안규정, 개인정보보호법, 의료법 등) 또는 국제 표준(ISO 27001, SOC 2 등)의 적용을 받는지 먼저 분석**해야 한다. 그에 따라 준수해야 할 암호화 표준이나 보안 통제 사항들이 달라지기 때문이다. 이는 보안 전문가가 단순히 기술적 지식뿐 아니라 법규 및 산업 지식을 함께 갖춰야 하는 이유이기도 하다.

#### 우리나라 보안 인식
우리나라의 보안 인식은 과거 강력한 규제와 공인인증서 중심으로 형성되어져 왔다.
- **과거의 '불편함'**
    - **ActiveX 기반의 보안 플러그인** : 과거 국내 웹 환경에서는 공인인증서, 키보드 보안, 방화벽 등 다양한 보안 기능을 위해 수많은 ActiveX 플러그인을 설치해야 했다. 이는 **잦은 충돌, 특정 브라우저(IE)에만 최적화, 해외 이용자의 접근 제한(공인인증서 발급 불가)** 등의 불편함을 야기하며, 보안을 '불편한 것'으로 인식하게 만들었다.
    - **금융실명제법** : 금융 거래 시 실명 확인을 의무화하는 법으로, 해외 거주 외국인의 경우 국내 금융 서비스 이용에 제약이 많았다. (PayPal 등 해외 간편결제 서비스와 대비)
- **전자서명법 개정 및 웹 표준화**
    - **이용자 보호를 위한 법적 강제** : 과거에는 이용자 보호를 위해 법으로 특정 보안 기술(공인인증서, 액티브X 등)의 사용을 강제했었다.
    - **변화** : 전자서명법 개정으로 **공인인증서의 독점적 지위가 폐지**되고, **액티브X 대신 HTML5 기반의 웹 표준 환경**으로 전환되면서 웹 보안 환경이 크게 개선되었다. 이는 사용자 경험을 향상시키고, 크로스 브라우징 및 모바일 환경에서의 접근성을 높였다.
    - **과거 액티브X의 문제점** : 실제로 금융 회사에서 설치를 요구했던 ActiveX 기반 보안 프로그램들이 북한 해커 그룹의 악성코드 유포 경로로 악용된 사례가 다수 있었다. 이는 특정 기술에 대한 의존이 오히려 새로운 취약점을 낳을 수 있음을 보여준다.
- **현재의 변화**
    - **ActiveX -> Non ActiveX** : 이제 대부분의 웹 서비스는 HTML5 기반으로 전환되어 ActiveX 설치 없이 이용 가능하다.
    - **웹 표준 환경에서의 애플리케이션 개발** : 웹 표준 환경에서는 웹 앱, 하이브리드 앱, 네이티브 앱 등 다양한 형태로 애플리케이션을 개발하며 보안을 고려한다.
    - **PC 보안 -> 모바일 보안으로 확장** : PC 중심의 보안에서 이제는 스마트폰, 태블릿 등 **모바일 기기에서의 보안(MAM - Mobile Application Management 등)** 이 매우 중요해졌다.
    - **선택적 보안, 자율형 보안, 개방형으로 변화** : 과거의 강제적이고 폐쇄적인 보안 환경에서 벗어나, **사용자가 선택하고 기업이 자율적으로 보안 수준을 결정하며, 개방적인 생태계**를 지향하는 방향으로 변화하고 있다.
    - **대체 인증 수단의 폭발적 증가** : 공인인증서 외에 **간편결제, 생체인증(지문, 얼굴), 카카오 인증, 블록체인 기반 인증, 브라우저 인증** 등 사용자 편의성을 높인 다양한 인증 방식이 등장하고 있다.
    - **사물인터넷(IoT) 보안** : 스마트홈, 자율주행차(인카페이먼트), 키오스크 등 사물인터넷 기기가 확산되면서, 이들 기기의 **펌웨어 보안, 통신 보안, 데이터 보호, 물리적 보안** 등이 새로운 보안 과제로 떠오르고 있다.

### 3. OSI 7 Layer -> 3계층으로 요약 정리: 보안 관점에서의 이해
OSI 7 계층 모델은 네트워크 통신 과정을 7단계로 나눈 표준 모델로, 복잡한 네트워크 통신을 표준화하고, 각 계층의 역할과 책임을 명확히 하여 **네트워크/보안 제품 개발 시 오류를 줄이고, 문제 발생 시 원인을 쉽게 파악하여 개선**할 수 있도록 일종의 '그라운드 룰(암묵적 규칙)'을 제공하기 위해 만들어졌다.

#### 1. 브라우저 계층 (L5~L7: 세션, 표현, 애플리케이션 계층)
- **특징** : **데이터 자체의 논리적 처리**가 이루어지는 영역이다. 사용자가 직접 상호작용하는 부분이기도 하다.
- **주요 정보** : **데이터 내용, URL, 압축, 암호화, 표현 방식** 등.
- **보안 관점**
    - **SSL 복호화** : HTTPS 트래픽의 내용을 검사하기 위한 SSL Proxy
    - **개인정보보호** : 데이터 유출/노출 방지 (DLP), 개인정보의 암호화 및 비식별화
    - **메일 보안** : 스팸 필터링, 피싱 방지, 이메일 인증(SPF, DKIM, DMARC)
    - **악성코드 유포/경유지 차단** : 웹 필터링, 안티바이러스, EDR (Endpoint Detection and Response)
    - **다크웹 필터링/조회** : 다크웹을 통한 정보 유출 모니터링 및 접근 차단
    - **생성형 AI/SaaS 보안** : AI 모델 보안, 클라우드 환경에서의 데이터 및 접근 제어, SaaS 서비스의 보안 설정 관리 (CNAPP 포함)
    - **최신 트렌드** : 클라우드 보안, 인공지능 보안, 비대면 인증, 생체 인증, 블록체인 보안(CBDC 등)과 밀접하게 관련됨

#### 2. 네트워크 계층 (L2~L4: 데이터 링크, 네트워크, 전송 계층)
- **특징** : **패킷의 전송, 경로 제어, 흐름 설정** 등 네트워크 인프라 자체의 동작과 관련된 영역이다.
- **주요 정보** : **패킷, IP 주소, 포트 번호, MAC 주소** 등
- **보안 관점**
    - **방화벽** : IP 주소, 포트 번호 등을 기반으로 트래픽을 허용하거나 차단
    - **보안 DNS** : DNS 쿼리를 검사하여 악성 사이트 접속을 차단
    - **망연계/망분리** : 네트워크를 물리적/논리적으로 분리하거나 연결하는 보안 기술
    - **보안 게이트웨이/프록시** : 외부와 내부 네트워크 사이에서 보안 정책을 강제하고 트래픽을 제어
    - **로그 통합/보안 분석 (SIEM)** : 네트워크 장비에서 발생하는 로그를 수집, 분석하여 보안 위협을 탐지
    - **기업의 레거시 보안** : 전통적인 네트워크 장비와 인프라 보안
    - **네트워크 속도(OTT) 보안** : 대량의 트래픽을 처리하면서도 보안을 유지하는 기술 (DDoS 방어)
    - **로드 밸런싱(부하 분산)** : 여러 서버에 트래픽을 분산하여 가용성과 성능을 확보하는 동시에 보안 기능(SSL Termination 등)을 제공

#### 3. 하드웨어 계층 (L1: 물리 계층)
- **특징** : **물리적인 전기 신호, 케이블, 하드웨어 연결** 등 가장 기본적인 물리적 인프라를 다루는 영역이다.
- **주요 정보** : **전기 신호, 감쇄/증폭, 케이블, MAC 주소** 등
- **보안 관점**
    - **UPS (무정전 전원 공급 장치)** : 전력 공급 안정성을 확보하여 시스템 가동을 유지
    - **화재, 담벼락, 창문, 항온항습, 경비원** : 데이터센터나 서버실에 대한 **물리적 접근 제어 및 환경 관리**. 해킹만큼이나 물리적 침입, 화재, 온습도 문제는 시스템 가용성에 치명적임.
    - **블루투스 보안** : 근거리 무선 통신(블루투스) 기기의 취약점 관리
    - **매체 제어** : USB, 외장하드 등 이동식 저장 매체를 통한 데이터 유출/유입 통제
    - **AD (Active Directory) 보안** : 사용자 인증 및 권한 관리를 담당하는 핵심 인프라에 대한 보안 (접근 제어, 계정 관리 등)
    - **자산 관리** : 기업 내 모든 하드웨어 및 소프트웨어 자산을 식별하고 관리하여 보안 취약점을 파악
    - **클라우드 인프라 보안 (하드웨어)** : 클라우드 서비스 제공업체(CSP)가 제공하는 물리적 인프라(서버, 스토리지 등)의 보안. 클라우드 사용자는 CSP가 제공하는 물리적 보안을 신뢰하지만, 자신의 가상 자원(VM, 컨테이너 등)에 대한 보안은 사용자의 책임임.

### 실습 주제 1: SSL Server Test (Qualys SSL Labs)를 통한 SSL/TLS 설정 분석
- **목표**: 자신의 웹사이트나 특정 웹사이트의 SSL/TLS 설정이 안전한지, 어떤 취약점이 있는지 점검하고 개선 방안을 파악하는 데 유용하다.
- SSL Server Test 웹사이트 접속 - https://www.ssllabs.com/ssltest
- 테스트할 도메인 입력
- 테스트 진행 및 결과 확인
    - SSL Labs는 입력된 도메인의 웹 서버에 연결하여 SSL/TLS 구성을 분석
- 테스트가 완료되면, 해당 서버의 SSL/TLS 설정에 대한 종합적인 보고서가 표시된다.
- 보고서 분석 및 주요 용어 학습 : 테스트 결과 페이지에서 다음 섹션들을 주의 깊게 살펴보며 SSL 기술 메커니즘의 주요 용어를 학습한다.
- **보안 인증서 vs 보안 서버 - 전자서명법**
    - **보안 인증서 (SSL/TLS 인증서)** : 웹사이트의 신원을 **증명**하고, 사용자-웹사이트 간 **통신을 암호화하기 위한 공개키를 포함**하는 디지털 파일이다. CA(인증기관)에서 발행한다.
    - **보안 서버** : 보안 인증서가 설치되어 있고, SSL/TLS 프로토콜을 사용하여 클라이언트와 **암호화된 통신을 할 수 있도록 설정된 웹 서버**를 의미한다. 즉, HTTPS 주소를 사용하는 웹사이트이다. 전자서명법은 이러한 전자적 서명과 관련된 법적 효력을 규정한다.
- **PKI (Public Key Infrastructure) 공개키 기반 구조**
    - **개념** : 공개키 암호화 방식(공개키-개인키 쌍)을 기반으로, **인증기관(CA)이 웹사이트의 신원을 확인하고 해당 웹사이트의 공개키에 서명하여 인증서를 발급**하는 보안 구조이다.
    - **동작 방식** : 사용자가 HTTPS 웹사이트에 접속하면, 웹 서버는 자신의 보안 인증서를 클라이언트에게 보낸다. 클라이언트는 인증서 내의 CA 서명을 통해 해당 웹사이트가 신뢰할 수 있는 곳인지 확인하고, 인증서 내의 공개키를 사용하여 암호화된 통신을 시작한다.
    - **보안 인증서 관리 프로그램**: 이러한 인증서의 발급, 폐기, 갱신 등을 관리하는 시스템이 필요하다.
- **TLS 1.3 이상 권장**
    - **TLS (Transport Layer Security)**는 SSL(Secure Sockets Layer)의 후속 버전이다. SSL 3.0 이후 TLS 1.0, 1.1, 1.2, 그리고 현재 **TLS 1.3**이 사용되고 있다.
    - **권장 이유** : TLS 1.3은 이전 버전에 비해 **보안이 훨씬 강화**되었다 (취약한 암호화 알고리즘 제거). 또한, **핸드셰이크 과정을 최적화하여 연결 설정 시간을 단축하고 전반적인 성능을 개선**했다. 따라서 보안과 성능 모두를 위해 최신 버전의 TLS를 사용하는 것이 강력히 권장된다.

## ❓ 궁금한 점

- **제로 트러스트 아키텍처 도입 시, 기존 레거시 시스템(오래된 시스템)과의 호환성 및 통합 문제는 어떻게 해결할 수 있을까?**
    - 제로 트러스트는 '아무것도 신뢰하지 않고, 모든 것을 검증한다(Never Trust, Always Verify)'는 원칙을 따르지만, 기존 레거시 시스템과 통합하는 데는 어려움이 있습니다. 다음 전략들로 해결할 수 있다.
        - **점진적 접근 및 우선순위 설정** : 한 번에 모두 바꾸기보다 가장 중요한 시스템부터 제로 트러스트를 적용하고 점차 확장한다.
        - **마이크로 세분화** : 네트워크를 작은 구역으로 나누고, 각 구역 간 접근을 엄격히 통제한다. 레거시 시스템 주변에 가상 경계를 만들어 침해 확산을 막는다.
        - **API 게이트웨이 활용** : 레거시 시스템으로 직접 접근하는 대신, API 게이트웨이를 통해 모든 통신을 중개하여 인증, 권한 부여 등 보안 정책을 적용한다. 레거시 시스템 변경 없이 보안을 강화하는 방법이다.
        - **IAM 시스템 강화** : 기존 ID 및 접근 관리(IAM) 시스템을 다중 인증(MFA) 및 컨텍스트 기반 접근 제어와 통합하여, 모든 접근 시도를 지속적으로 검증한다.
        - **세션 브로커/원격 접근 솔루션** : 레거시 시스템에 직접 접근하는 것을 막고, 보안이 강화된 세션 브로커를 통해 제한된 세션만 허용한다.
        - **보안 모니터링 및 로깅 강화** : 레거시 시스템의 모든 보안 이벤트를 중앙 SIEM으로 수집하고 분석하여 비정상 행위를 탐지하고 대응한다.

- **망분리 완화가 데이터 거버넌스 및 규제 준수(예: 개인정보보호법, 금융권 규제)에 미치는 영향은 무엇이며, 이를 위해 어떤 새로운 관리 체계가 요구될까?**
    - 망분리 완화는 효율성을 높이지만, 데이터 유출 위험을 증가시키고 규제 준수를 복잡하게 만든다.
    - **주요 영향**
        - **데이터 흐름 복잡성 증가** : 데이터가 여러 환경(클라우드, SaaS)으로 이동하며 관리와 추적이 어려워진다.
        - **보안 책임 모호** : 공동 책임 모델에서 CSP와 기업 간 책임 경계가 불분명해질 수 있다.
        - **내부 데이터 유출 경로 증가** : 인터넷망 접근 허용으로 내부자에 의한 유출 위험이 커진다.
        - **규제 준수 복잡성** : 다양한 서비스와 규제(개인정보보호법, 금융권 규제)를 동시에 고려해야 한다.
    - **요구되는 새로운 관리 체계**
        - **데이터 분류 및 식별 강화** : 모든 데이터를 중요도에 따라 분류하고 태깅하여 관리한다.
        - **지능형 DLP 및 데이터 암호화** : 클라우드, SaaS를 포함한 모든 접점에서 데이터 유출을 감시/차단하고, 데이터 암호화를 강제한다.
        - **강력한 IAM 및 최소 권한** : 모든 사용자에게 최소한의 접근 권한만 부여하고, 접근 시 지속적으로 검증한다.
        - **클라우드 보안 솔루션 도입 (CSPM, CWPP, CNAPP)** : 클라우드 환경의 설정 오류, 취약점을 자동 점검하고, 워크로드를 보호한다.
        - **보안 관제 및 위협 탐지 강화 (SIEM/SOAR)** : 다양한 환경의 보안 로그를 통합 분석하여 위협을 실시간으로 탐지하고 자동 대응한다.
        - **계약 및 SLA 검토 강화** : 클라우드/SaaS 도입 시 보안 책임, 데이터 처리 방식 등을 명확히 계약에 명시한다.
        - **지속적인 보안 교육** : 변화된 환경에 맞춰 사용자들의 보안 인식과 대응 능력을 높이는 교육을 정기적으로 실시한다.
