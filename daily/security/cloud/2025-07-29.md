## 🧠 주요 개념 정리

### AWS 주요 보안 서비스

#### AWS SSM (Systems Manager)
- **AWS Systems Manager (SSM)**은 AWS 클라우드 및 온프레미스에서 실행되는 인스턴스, 운영 체제, 소프트웨어에 대한 **가시성을 확보하고 제어**할 수 있도록 돕는 서비스이다. 단순히 보안 서비스로 분류되기보다는 **운영 및 관리 자동화**에 중점을 두지만, 그 과정에서 보안을 크게 향상시킨다.
- **주요 기능**
    - **패치 관리(Patch Manager)** : 운영 체제 및 애플리케이션에 대한 보안 패치를 자동으로 스캔하고 배포한다. 최신 보안 업데이트를 적용하여 취약점을 줄이는 데 핵심적이다.
    - **명령 실행(Run Command)** : 수천 개의 인스턴스에서 스크립트나 명령을 원격으로 안전하게 실행할 수 있다. 예를 들어, 보안 설정 변경 스크립트를 모든 서버에 일괄 적용할 수 있다.
    - **세션 관리자(Session Manager)** : SSH(Secure Shell)나 RDP(Remote Desktop Protocol) 포트를 열지 않고도 인스턴스에 안전하게 접속하여 명령줄 인터페이스(CLI)로 작업을 수행할 수 있다. 이는 인스턴스의 노출 영역을 줄여 보안을 강화한다.
    - **인벤토리(Inventory)** : 인스턴스에 설치된 소프트웨어, 서비스 팩, 기타 구성 정보를 자동으로 수집하고 보고한다. 보안 감사 및 규정 준수에 활용된다.
    - **구성 준수(Compliance)** : 인스턴스가 사용자가 정의한 보안 및 구성 표준을 준수하는지 모니터링하고 보고한다.
- **보안적 이점**
    - 보안 패치를 일관되고 자동화된 방식으로 적용하여 취약점 노출 시간을 최소화한다.
    - 직접적인 SSH/RDP 접근 없이 인스턴스 관리가 가능하여 인스턴스의 네트워크 노출을 줄인다.
    - 구성 관리 및 인벤토리 파악을 통해 보안 감사에 필요한 정보를 쉽게 얻을 수 있다.

#### AWS CloudFormation
**AWS CloudFormation**은 AWS 리소스 인프라를 **코드로 정의(Infrastructure as Code, IaC)** 하고 관리할 수 있게 해주는 서비스이다. 보안 표준을 준수하는 인프라를 반복적이고 일관된 방식으로 배포하는 데 매우 중요하다.
- **주요 기능**
    - **템플릿 기반 리소스 프로비저닝** : JSON 또는 YAML 형식의 템플릿 파일에 EC2 인스턴스, S3 버킷, VPC, IAM 역할 등 AWS 리소스를 정의한다.
    - **자동화된 배포** : 정의된 템플릿을 통해 리소스를 자동으로 생성, 업데이트, 삭제할 수 있다.
    - **일관성 유지** : 동일한 템플릿을 사용하여 여러 환경(개발, 스테이징, 운영)에 동일한 보안 구성을 가진 인프라를 배포할 수 있다.
    - **버전 관리** : 템플릿은 코드로 관리되므로 Git과 같은 버전 관리 시스템을 사용하여 변경 사항을 추적하고 롤백할 수 있다.
- **보안적 이점**
    - **보안 기준 적용 자동화** : 모든 리소스가 미리 정의된 보안 구성(예: 특정 보안 그룹, 특정 IAM 역할)을 따르도록 강제할 수 있다.
    - **구성 드리프트 방지** : 수동 구성 오류나 시간이 지남에 따라 발생하는 구성 변경(Drift)을 방지하여 보안 취약점 발생 가능성을 줄인다.
    - **감사 및 규정 준수** : 인프라의 모든 구성이 코드로 명확하게 문서화되므로 보안 감사 및 규정 준수 검토가 용이하다.

#### Amazon EventBridge
**Amazon EventBridge**는 AWS 서비스, SaaS 애플리케이션, 사용자 지정 애플리케이션에서 발생하는 데이터 스트림을 실시간으로 전달하는 **서버리스 이벤트 버스** 서비스이다. 보안 이벤트에 대한 **자동화된 대응**을 구현하는 데 활용된다.
- **주요 기능**
    - **이벤트 라우팅** : 다양한 소스에서 발생하는 이벤트를 수집하고, 정의된 규칙에 따라 특정 대상(Lambda 함수, SNS 토픽, SQS 큐 등)으로 라우팅한다.
    - **규칙 기반 처리** : 이벤트 패턴을 정의하여 특정 조건에 맞는 이벤트만 필터링하고 처리한다.
    - **스케줄링** : 특정 시간에 이벤트를 생성하여 자동화된 작업을 트리거할 수 있다.
- **보안적 이점**
    - **보안 이벤트 대응 자동화** : CloudTrail에서 특정 보안 이벤트(예: IAM 사용자 생성, 특정 리소스 삭제 시도)가 감지되면 EventBridge를 통해 Lambda 함수를 트리거하여 알림을 보내거나 자동 복구 작업을 수행할 수 있다.
    - **실시간 위협 탐지 및 대응** : GuardDuty나 Inspector에서 위협이 탐지되면 EventBridge를 통해 자동 격리, 차단 등의 즉각적인 조치를 취할 수 있다.

#### Amazon Inspector
**Amazon Inspector**는 EC2 인스턴스에 배포된 애플리케이션 및 운영 체제의 **보안 취약점과 규정 준수 여부를 자동으로 평가**하는 서비스이다.
- **주요 기능**
    - **자동화된 보안 평가** : 에이전트를 설치한 EC2 인스턴스에서 애플리케이션의 취약점, 비정상적인 네트워크 동작, 보안 모범 사례 위반 등을 스캔한다.
    - **취약점 보고서 생성** : 발견된 취약점의 심각도, 권장 조치, 영향을 받는 리소스 등에 대한 상세 보고서를 제공한다.
    - **규정 준수 평가** : 특정 보안 표준(예: CIS Benchmarks)에 대한 준수 여부를 평가한다.
- **보안적 이점**
    - **선제적 취약점 발견** : 서비스 배포 전 또는 운영 중에도 지속적으로 취약점을 스캔하여 잠재적인 공격 경로를 파악하고 수정할 수 있도록 돕는다.
    - **규정 준수 확보** : 조직의 보안 정책이나 외부 규제에 대한 준수 여부를 지속적으로 검증할 수 있다.

#### AWS Config
**AWS Config**는 AWS 리소스의 **구성 변경 내역을 지속적으로 기록하고, 변경 사항을 모니터링하며, 설정이 원하는 규정 준수 기준을 충족하는지 평가**하는 서비스이다.
- **주요 기능**
    - **구성 변경 기록** : 모든 AWS 리소스의 구성 변경 이력을 기록하고 S3에 저장한다. "언제 누가 무엇을 어떻게 변경했는지"를 추적할 수 있다.
    - **규칙 기반 평가** : 사용자가 정의한 규칙(Built-in 또는 Lambda 기반)에 따라 리소스 구성이 보안 및 규정 준수 기준을 충족하는지 자동으로 평가한다.
    - **변경 알림** : 리소스 구성이 변경되거나 규칙 위반이 발생하면 알림을 보낸다.
    - **시간 기반 조회** : 특정 시점의 리소스 구성을 조회할 수 있어, 문제 발생 시 복구에 활용할 수 있다.
- **보안적 이점**
    - **보안 감사 및 포렌식** : 모든 구성 변경 이력이 기록되므로 보안 사고 발생 시 원인 분석(포렌식) 및 감사에 필수적인 정보를 제공한다.
    - **보안 정책 준수 강제** : S3 버킷이 공개로 설정되거나, 보안 그룹이 너무 광범위하게 열리는 등의 보안 정책 위반을 즉시 감지하고 알림을 보낼 수 있다.
    - **규정 준수 증명** : 리소스 구성이 특정 규정(예: PCI DSS)을 준수하고 있음을 지속적으로 증명할 수 있다.

#### AWS GuardDuty
**AWS GuardDuty**는 AWS 계정 및 워크로드에서 발생하는 **악성 활동 및 비정상적인 동작을 지속적으로 모니터링하여 잠재적인 위협을 탐지**하는 지능형 위협 탐지 서비스이다.
- **주요 기능**
    - **지속적인 모니터링** : VPC Flow Logs, CloudTrail 이벤트 로그, DNS 쿼리 로그 등을 자동으로 수집하고 분석한다.
    - **위협 탐지** : 머신러닝, 이상 징후 탐지, 통합 위협 인텔리전스 등을 사용하여 악성 IP 주소, 도메인, 비정상적인 API 호출 패턴, 크립토마이닝 활동 등을 탐지한다.
    - **보안 결과 생성** : 탐지된 위협에 대한 상세 정보(심각도, 영향을 받는 리소스, 권장 조치)를 제공한다.
- **보안적 이점**
    - **능동적인 위협 탐지** : 침해 사고가 발생하기 전에 잠재적인 위협을 조기에 발견하고 대응할 수 있도록 돕는다.
    - **운영 부담 감소** : 사용자가 직접 로그를 분석하고 위협을 식별할 필요 없이, GuardDuty가 자동으로 지능적인 분석을 수행한다.

#### AWS Shield
**AWS Shield**는 **DDoS(분산 서비스 거부) 공격**으로부터 AWS에서 실행되는 애플리케이션을 보호하는 서비스이다.
- **주요 기능**
    - **Always-on 탐지 및 자동 인라인 완화** : L3/L4(네트워크/전송 계층) DDoS 공격을 자동으로 탐지하고 완화한다.
    - **통합** : Elastic Load Balancing(ELB), Amazon CloudFront, Route 53, AWS Global Accelerator 등 다양한 AWS 서비스와 통합되어 보호 기능을 제공한다.
- **종류**
    - **AWS Shield Standard** : 모든 AWS 고객에게 무료로 제공되며, 가장 일반적인 네트워크 및 전송 계층 DDoS 공격으로부터 기본적인 보호를 제공한다.
    - **AWS Shield Advanced** : 유료 서비스로, 더 높은 수준의 보호(대규모, 정교한 공격 방어), 거의 실시간에 가까운 가시성, AWS DDoS Response Team(DRT)의 24/7 지원, 추가 비용 보호(DDoS 공격으로 인한 확장 비용 보상) 등을 제공한다.
- **보안적 이점** : 서비스 가용성을 위협하는 DDoS 공격으로부터 애플리케이션을 보호하여 서비스 중단을 최소화한다.

#### AWS WAF (Web Application Firewall)
**AWS WAF (Web Application Firewall)**는 웹 애플리케이션을 **일반적인 웹 공격으로부터 보호**하는 웹 애플리케이션 방화벽 서비스이다.
- **주요 기능**
    - **웹 트래픽 필터링** : HTTP/HTTPS 트래픽을 검사하여 SQL 삽입, XSS(Cross-site Scripting), 악성 봇 활동, DoS 공격 등 일반적인 웹 취약점 공격을 탐지하고 차단한다.
    - **사용자 정의 규칙** : 특정 IP 주소 차단, 특정 URL 패턴 필터링 등 사용자 정의 보안 규칙을 생성할 수 있다.
    - **관리형 규칙** : AWS 또는 AWS 파트너가 제공하는 미리 정의된 규칙 세트를 사용하여 일반적인 위협으로부터 빠르게 보호할 수 있다.
- **통합** : Amazon CloudFront, Application Load Balancer(ALB), Amazon API Gateway, AWS AppSync와 통합하여 작동한다.
- **보안적 이점** : OWASP Top 10과 같은 일반적인 웹 애플리케이션 취약점 공격으로부터 서비스를 보호하여 애플리케이션 계층의 보안을 강화한다.

#### AWS KMS (Key Management Service)
**AWS KMS (Key Management Service)**는 **암호화 키를 생성, 관리, 보호**하는 서비스이다. 데이터를 암호화하여 보안을 강화할 때 사용되는 암호화 키를 안전하게 다루는 데 초점을 맞춘다.
- **주요 기능**
    - **암호화 키 생성 및 관리** : AWS에서 관리하는 키(AWS Managed Keys), 고객이 직접 제어하는 키(Customer Managed Keys) 등 다양한 유형의 암호화 키를 생성하고 수명 주기를 관리한다.
    - **암호화 및 복호화** : KMS에서 관리하는 키를 사용하여 데이터를 암호화하고 복호화할 수 있다.
    - **키 사용 권한 제어** : IAM과 통합하여 누가 어떤 키를 사용하여 무엇을 할 수 있는지 세분화된 권한을 제어한다.
    - **키 사용 기록** : 모든 키 사용 내역이 CloudTrail에 기록되어 감사 추적이 가능하다.
- **보안적 이점**
    - **암호화 키의 안전한 보관** : 암호화 키가 HSM(하드웨어 보안 모듈) 내에 안전하게 저장되므로, 키 유출 위험을 최소화한다.
    - **데이터 보호** : 저장된 데이터(Data-at-rest)와 전송 중인 데이터(Data-in-transit)를 암호화하여 기밀성을 확보한다.

#### AWS Network Firewall
**AWS Network Firewall**은 VPC 내에서 **네트워크 트래픽을 필터링하고 모니터링하여 악성 트래픽을 차단**하는 관리형 방화벽 서비스이다.
- **주요 기능**
    - **VPC 수준의 방화벽** : VPC 경계에서 들어오고 나가는 모든 트래픽을 검사하고 필터링한다.
    - **스테이트풀 필터링** : TCP 연결 상태를 추적하여 응답 트래픽을 자동으로 허용하는 등 더 정교한 규칙을 적용할 수 있다.
    - **위협 인텔리전스 통합** : IP 주소, 도메인, 시그니처 기반 규칙 등을 사용하여 알려진 위협을 차단할 수 있다.
    - **자동 확장** : 트래픽 증가에 따라 자동으로 확장 및 축소된다.
    - **중앙 집중식 관리** : 여러 VPC에 걸쳐 방화벽 정책을 중앙에서 관리할 수 있다.
- **보안적 이점**
    - **네트워크 계층 보안 강화** : VPC의 각 서브넷 간 또는 VPC와 외부 네트워크 간의 트래픽을 세밀하게 제어하여 악성 트래픽이 내부 네트워크로 침투하는 것을 방지한다.
    - **규정 준수** : 특정 네트워크 트래픽 패턴에 대한 규정 준수 요구 사항을 충족하는 데 도움이 된다.

## ❓ 궁금한 점

- **AWS의 '관리형 보안 서비스'를 사용하는 것이 직접 보안 솔루션을 구축하고 운영하는 것보다 갖는 가장 큰 이점은 무엇이며, 그럼에도 불구하고 고려해야 할 점은 무엇인가?**
    - AWS의 관리형 보안 서비스는 보안 운영의 복잡성과 부담을 획기적으로 줄여주는 것이 가장 큰 이점이다.
    - **주요 이점**
        - **운영 부담 및 전문성 요구 감소** : AWS가 인프라 관리 및 유지보수를 담당하여, 고객은 보안 전문가 없이도 최신 보안 기술을 활용할 수 있다.
        - **자동 확장 및 고가용성** : 트래픽 및 위협 규모에 따라 서비스가 자동으로 확장/축소되며, AWS의 글로벌 인프라를 통해 높은 가용성을 보장한다.
        - **최신 위협 인텔리전스 및 빠른 대응** : AWS는 최신 위협 정보를 서비스에 지속적으로 반영하여, 고객은 항상 최신 방어 체계를 유지할 수 있다.
        - **비용 효율성** : 초기 투자 없이 사용한 만큼만 지불하는 종량 과금 모델로, TCO(총 소유 비용)를 절감할 수 있다.
    - **고려해야 할 점**
        - **제한적인 커스터마이징** : 특정 고유 요구사항에 대한 세밀한 제어가 어려울 수 있다.
        - **벤더 종속성** : AWS 서비스에 최적화되므로, 다른 클라우드로 전환 시 추가 노력이 필요할 수 있다.
        - **비용 예측 및 최적화** : 사용량에 따라 비용이 달라지므로, 지속적인 모니터링 및 최적화가 중요하다.
        - **여전히 고객의 책임** : 공동 책임 모델에 따라 IAM 권한, 보안 그룹 설정 등 고객이 책임져야 할 보안 영역이 명확히 존재한다.

- **AWS의 다양한 보안 서비스들(예: GuardDuty, WAF, Network Firewall)이 각각 어떤 유형의 공격을 방어하며, 이들을 효과적으로 조합하여 클라우드 환경의 다계층 보안 전략을 어떻게 구축할 수 있을까?**
    - AWS 보안 서비스들은 서로 다른 계층과 공격 유형에 대응하며, 이들을 조합하여 심층 방어(Defense in Depth) 전략을 구현할 수 있다.
    - **각 서비스의 방어 유형**
        - **AWS Shield** : 네트워크/전송 계층(L3/L4)의 DDoS 공격 방어 (인프라 마비 공격)
        - **AWS WAF** : 애플리케이션 계층(L7)의 웹 애플리케이션 공격 방어 (SQL Injection, XSS 등 웹 취약점 공격)
        - **AWS Network Firewall** : VPC 내부 및 VPC 간 네트워크 트래픽 필터링 및 모니터링 (네트워크 침입, 데이터 유출 방어)
        - **AWS GuardDuty** : AWS 계정 및 워크로드의 악성 활동 및 비정상 동작 탐지 (자격 증명 탈취, 크립토마이닝 등 이상 징후)
    - **다계층 보안 전략 구축 예시**
        - **외부 방어** : AWS Shield로 DDoS 공격을 1차 방어
        - **웹 애플리케이션 보호** : AWS WAF로 웹 공격을 차단
        - **네트워크 세분화 및 제어** : AWS Network Firewall로 VPC 트래픽을 필터링하고 악성 트래픽을 차단
        - **계정 활동 모니터링** : AWS GuardDuty로 계정 내 의심스러운 활동을 탐지하고 알림
    - **보안 구성 및 패치** : AWS Config로 구성 변경을 추적하고, AWS SSM으로 패치 및 보안 설정을 자동화
