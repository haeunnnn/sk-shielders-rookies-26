## 🧠 주요 개념 정리

### 1. 서버 준비하기

#### EBS (Elastic Block Store)
**EBS (Elastic Block Store)** 는 AWS에서 제공하는 영구 블록 스토리지 서비스이다. EC2 인스턴스에 연결하여 사용할 수 있으며, 마치 물리적인 서버에 하드 드라이브를 연결하는 것과 같은 역할을 한다.

- **정의** : EC2 인스턴스에 영구적으로 연결되는 네트워크 스토리지 볼륨이다. 인스턴스가 중지되거나 종료되어도 데이터가 유지되며, 필요에 따라 인스턴스에 연결하거나 분리할 수 있다.
- **주요 특징**
    - **영구성** : EC2 인스턴스가 종료되어도 EBS 볼륨은 독립적으로 존재하며 데이터가 보존된다. (EC2 인스턴스에 기본으로 포함된 임시 스토리지인 인스턴스 스토어와 구분되는 점)
    - **고가용성 및 안정성** : 단일 가용 영역 내에서 자동으로 복제되어 데이터 손실을 방지하고 높은 가용성을 제공한다.
    - **확장성** : 필요에 따라 볼륨 크기를 쉽게 늘리거나 성능 특성(IOPS, 처리량)을 변경할 수 있다.
    - **스냅샷** : 볼륨의 특정 시점 백업인 스냅샷 기능을 제공하여 데이터를 쉽게 복구하거나 다른 볼륨으로 복제할 수 있다.
    - **성능 유형** : 범용 SSD (gp2/gp3), 프로비저닝된 IOPS SSD (io1/io2), 처리량 최적화 HDD (st1), 콜드 HDD (sc1) 등 다양한 성능 및 비용 특성을 가진 볼륨 유형을 제공하여 워크로드에 맞춰 선택할 수 있다.
- **활용** : 운영체제 부팅 드라이브, 데이터베이스 저장 공간, 로그 파일 저장, 고성능 애플리케이션의 데이터 스토리지 등으로 널리 사용된다.

#### Tagging (태깅)
**Tagging (태깅)** 은 AWS 리소스(EC2 인스턴스, S3 버킷, VPC 등)에 메타데이터를 할당하는 기능입니다. 각 태그는 **키(Key)와 값(Value)** 쌍으로 구성된다.
- **정의** : AWS 리소스에 사용자가 정의한 라벨(Key-Value 쌍)을 추가하는 기능이다.
- **주요 특징 및 장점**
    - **관리 및 구성** : 수많은 리소스를 특정 기준(예: 프로젝트, 부서, 환경)으로 그룹화하고 검색하기 용이하다.
    - **비용 할당 및 추적** : 태그를 사용하여 비용 보고서를 필터링하고 특정 팀, 프로젝트 또는 환경에 대한 비용을 할당하고 추적할 수 있다. (예: Project: A, Environment: Production)
    - **자동화** : AWS 서비스(예: AWS Lambda, AWS CloudFormation)와 연동하여 태그 기반으로 리소스 자동화 작업을 수행할 수 있다.
    - **보안 및 접근 제어** : IAM 정책에서 태그를 조건으로 사용하여 특정 태그가 있는 리소스에 대한 접근 권한을 제어할 수 있다.
- **활용**
    - **비용 관리** : "Dev 부서의 웹서버 비용은 얼마인가?", "Project X의 모든 리소스 비용은 얼마인가?" 와 같은 질문에 답하는 데 사용된다.
    - **리소스 식별** : "이 EC2 인스턴스는 어떤 애플리케이션에 사용되는가?" 와 같은 질문에 태그로 쉽게 답할 수 있다.

#### 리전과 가용 영역 (AZ)과 데이터센터, 엣지 로케이션
이 개념들은 AWS의 글로벌 인프라 아키텍처를 이해하는 데 매우 중요하다.

**리전 (Region)**
- **정의** : AWS 서비스가 호스팅되는 지리적으로 독립적인 물리적 위치이다. 전 세계 주요 대도시에 분산되어 있으며, 각 리전은 완전히 독립적이다.
- **특징** : 한 리전의 장애가 다른 리전에 영향을 미치지 않도록 설계된 완벽한 격리 환경을 제공한다. 사용자는 데이터 주권, 규정 준수, 지연 시간 등을 고려하여 리전을 선택한다.
- **예시** : 서울 리전 (ap-northeast-2), 미국 동부(버지니아 북부) 리전 (us-east-1) 등.

**가용 영역 (Availability Zone, AZ)**
- **정의** : 각 리전은 하나 이상의 **가용 영역(AZ)** 으로 구성된다. AZ는 리전 내에서 물리적으로 분리된, 독립적인 데이터센터 클러스터이다. 각 AZ는 자체적인 전력, 네트워킹, 냉각 시스템을 갖추고 있어 한 AZ의 장애가 다른 AZ에 영향을 주지 않도록 설계되었다.
- **특징** : 동일 리전 내의 AZ 간에는 매우 빠르고 저렴하며 낮은 지연 시간의 네트워크 연결이 보장된다. 고가용성 및 내결함성 아키텍처를 구축하기 위해 여러 AZ에 리소스를 분산 배치하는 것이 일반적이다.
- **예시** : 서울 리전 내의 ap-northeast-2a, ap-northeast-2b, ap-northeast-2c.

**데이터센터**
- **정의** : 실제 물리적인 서버, 스토리지, 네트워크 장비 등이 위치한 건물 또는 시설이다.
- **AWS와의 관계** : AWS의 가용 영역(AZ)은 하나 이상의 데이터센터로 구성될 수 있다. AWS는 각 AZ가 독립적인 물리적 위치를 가지며, 수 마일 떨어져 있어 자연재해 등으로부터 보호되도록 설계한다.

**엣지 로케이션 (Edge Location)**
- **정의** : AWS 리전과 별도로 전 세계에 분산되어 있는 소규모 데이터센터이다. 주로 콘텐츠 전송 네트워크(CDN) 서비스인 Amazon CloudFront와 같은 서비스에 사용된다.
- **역할** : 최종 사용자와 가장 가까운 위치에서 콘텐츠(웹사이트 이미지, 비디오 등)를 캐싱(저장)하여 전송 지연 시간을 줄이고 로딩 속도를 향상시킨다.
- **특징** : 컴퓨팅 리소스를 호스팅하는 리전이나 AZ와는 목적이 다르다. 주로 사용자에게 더 빠른 콘텐츠 전송을 제공하는 데 중점을 둔다.

### 2. 가상 네트워크 만들기: VPC와 관련 구성 요소
**가상 네트워크 (Virtual Network)** 는 AWS 클라우드에서 애플리케이션을 배포하고 실행하는 데 있어 가장 기본적인 기반이 된다. AWS에서는 이를 **VPC(Virtual Private Cloud)** 라고 부른다.

#### VPC (Virtual Private Cloud)
- **정의** : AWS 클라우드 내에 사용자가 정의하고 논리적으로 격리된 가상 네트워크이다. AWS 데이터센터 안에 나만의 독립적인 데이터센터를 만드는 것과 같다. 사용자가 IP 주소 범위, 서브넷, 라우팅 테이블, 네트워크 게이트웨이 등을 완벽하게 제어할 수 있다.
- **특징** : 다른 AWS 계정의 VPC나 인터넷으로부터 완전히 분리되어 있어 높은 보안성과 유연성을 제공한다.

#### 서브넷 (Subnet)과 가용 영역 (AZ)
- **서브넷 정의** : VPC를 논리적으로 나눈 작은 네트워크 블록이다. 각 서브넷은 VPC의 IP 주소 범위 내에서 특정 IP 주소 범위를 가진다.
- **가용 영역과의 관계** : 서브넷은 특정 가용 영역(AZ) 내에 존재해야 한다. 즉, 하나의 서브넷은 하나의 AZ에만 속하며, 여러 AZ에 걸쳐 생성될 수 없다. 이는 고가용성을 위해 여러 AZ에 리소스를 분산 배치할 때 각 AZ에 별도의 서브넷을 생성해야 함을 의미한다.
- **유형** : 인터넷 통신이 가능한 **퍼블릭 서브넷(Public Subnet)** 과 외부 통신이 불가능한 **프라이빗 서브넷(Private Subnet)** 으로 나뉜다.

#### 인터넷 게이트웨이 (Internet Gateway, IGW)
- **정의** : VPC가 인터넷과 통신할 수 있도록 하는 수평 확장형, 이중화된 VPC 구성 요소이다.
- **역할** : 퍼블릭 서브넷에 있는 EC2 인스턴스가 인터넷과 통신하기 위해 필수적이다. VPC에 연결되어야 하며, 인스턴스에 퍼블릭 IP가 할당되고 라우팅 테이블이 올바르게 설정되어야 한다.

#### NAT 게이트웨이 (NAT Gateway) / NAT 인스턴스
- **정의** : 프라이빗 서브넷에 있는 인스턴스가 인터넷으로 향하는 아웃바운드 트래픽을 시작할 수 있도록 하면서도, 외부에서 직접 인바운드 연결을 방지하는 서비스이다.
- **역할** : 데이터베이스 서버나 애플리케이션 서버와 같이 직접적인 외부 접근은 차단하고 싶지만, 업데이트를 다운로드하거나 외부 API와 통신해야 하는 경우에 사용된다. NAT 게이트웨이는 AWS에서 관리하는 고가용성 서비스이며, NAT 인스턴스는 사용자가 직접 EC2에 설치하여 관리해야 하는 방식이다.

#### 라우팅 테이블 (Route Table)
- **정의** : 서브넷에 연결되어 **네트워크 트래픽이 어디로 향해야 하는지(라우팅 규칙)** 를 정의하는 데 사용되는 규칙 집합이다.
- **역할** : 특정 IP 주소 범위에 대한 트래픽을 인터넷 게이트웨이, NAT 게이트웨이, 또는 다른 VPC 등으로 보낼지 결정한다. 예를 들어, 인터넷으로 가는 모든 트래픽(0.0.0.0/0)은 인터넷 게이트웨이를 통해 라우팅되도록 설정한다.

### 실습 주제 1: EBS 생성 및 연결 (EC2에 디스크 추가)
- 콘솔 > EC2 > EBS
- EBS 생성 (1G, gp3) : EBS > 볼륨 > 볼륨 생성
    - EC2 확인 : 만들어져 있는 EC2 존재 확인
    - EBS 연결 : 볼륨 선택 - 작업 > 볼륨 연결 (인스턴스 선택)
    - EC2 연결하여 File System으로 사용 (connect or ssh)
- `df -k` > `sudo mkfs /dev/sdf` > `sudo mkdir /appdir` > `sudo mount /dev/sdf /appdir` > `df -k` > `cd /appdir` > `sudo touch a b c d` > `sudo mkdir A B C D` > `ls`

## ❓ 궁금한 점

- **여러 프로젝트, 부서, 환경(개발/스테이징/운영)이 존재하는 복잡한 AWS 환경에서 태깅(Tagging)을 효과적으로 사용하여 리소스 관리, 비용 할당, 자동화, 그리고 보안 및 접근 제어를 어떻게 구현할 수 있을까? 태깅 표준을 수립하고 준수하는 데 있어 어떤 어려움이 있을 수 있으며, 이를 어떻게 극복할 수 있을까?**
    - AWS 환경에서 태깅은 리소스 관리, 비용 추적, 자동화, 그리고 보안 제어에 필수적이다.
    - **활용 방안**
        - `Project`, `Environment` 등 태그로 리소스를 그룹화하고 쉽게 찾을 수 있다.
        - `CostCenter`, `Application` 등 태그로 비용을 세분화하여 추적하고 분석할 수 있다.
        - 태그를 기반으로 리소스 시작/중지, 백업 등 운영 작업을 자동화할 수 있다.
        - IAM 정책에 태그를 활용하여 리소스 접근 권한을 정교하게 제어할 수 있다.
    - **어려움 및 극복 방안**
        - 어려움: 태그의 일관성 부족, 초기 적용의 번거로움, 복잡성 증가 등
        - 극복: `필수 태그`를 포함한 명확한 태깅 정책을 수립하고 문서화한다. CloudFormation, Service Catalog 등으로 태그 적용을 자동화하고, AWS Config나 SCPs로 정책 준수를 강제한다. 정기적인 감사와 교육도 중요하다.

- **고가용성, 재해 복구, 그리고 사용자 지연 시간 최소화를 목표로 AWS 아키텍처를 설계할 때 리전, 가용 영역(AZ), 엣지 로케이션을 각각 어떻게 효과적으로 활용해야 할까? 특정 서비스(예: 웹 애플리케이션, 데이터베이스, 스트리밍 서비스)를 배포할 때 이들 인프라 요소를 어떻게 배치해야 견고하고 효율적인 시스템을 구축할 수 있을까?**
    - 고가용성, 재해 복구, 사용자 지연 시간 최소화는 AWS의 리전, 가용 영역(AZ), 엣지 로케이션을 효과적으로 활용하여 달성할 수 있다.
    - **리전 (Region)**
        - **목적**: 지리적 격리 및 재해 복구 (DR) 전략의 핵심
        - **활용**: `Multi-Region` 아키텍처로 한 리전 전체 장애 시 서비스 연속성을 확보하고, 데이터 주권/규제 준수 요건을 충족한다. (예: 서울 리전에 DR 센터 구축)
    - **가용 영역 (Availability Zone, AZ)**
        - **목적**: 단일 리전 내에서 고가용성 및 내결함성 확보
        - **활용**: EC2, RDS 등을 여러 AZ에 분산 배치하고 ELB로 트래픽을 분산하여 AZ 장애에도 서비스가 중단되지 않도록 한다. (예: Multi-AZ RDS 배포)
    - **엣지 로케이션 (Edge Location)**
        - **목적**: 전 세계 최종 사용자에게 콘텐츠 전송 지연 시간을 최소화
        - **활용**: Amazon CloudFront (CDN)를 통해 S3에 저장된 웹 콘텐츠(이미지, 비디오 등)를 사용자에게 가장 가까운 엣지 로케이션에서 캐싱하여 빠르게 전송한다.
