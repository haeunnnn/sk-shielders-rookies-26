## 🧠 주요 개념 정리

### 1. OSI 7계층

|   | 계층 | 장비 | 고유 기능 | 예시 |
| - | --- | --- | -------- | ---- |
| 7 | **Application (응용)** | 방화벽, 게이트웨이, 프록시 서버 | - 사용자를 위한 서비스 UI 제공 <br/> - **데이터 생성** | HTTP, FTP, Telnet, SMTP, SNMP, NFS, ... |
| 6 | **Presentation (표현)** | 게이트웨이(일부) | - 인코딩 (이진화) <br/> - 압축화 <br/> - 암호화 | ASCII, UNICODE/jpg, bmp, png, mp4, zip/RSA, DES |
| 5 | **Session (세션)** | 방화벽(일부), 게이트웨이(일부) | - 양 단 간에 서비스 설정, 유지, 해지 <br/> - **서비스 개시** : 인증 <br/> - **서비스 유지** : 지속적 인증 <br/> - **서비스 해지** : 인증값 필요 | SSL |
| 4 | **Transport (전송)** | L4 스위치 | - 양 단 간의 가상 회선(Virtual Line) 설정, 유지, 해지 <br/> - **가상 회선 수립** : 서버 활성화 and 서비스 활성화 <br/> - **가상회선 해지** : 서버 비활성화 or 서비스 비활성화 | **TCP (3-way handshake)** |
| 3 | **Network (네트워크)** | 라우터 | - 경로 관리와 최적 경로 결정 (**Routing**) | |
| 2 | **Data Link (데이터 링크)** | 스위치 | - 포워딩 : 데이터 전송을 위해 미디어 접근 방법 제공 <br/> - **공유 매체 접근 제어(MAC)** : 충돌 제어, 전송 지연 줄임 <br/> - 오류 제어 : 무결성 점검 | **CSMA/CD**, **CSMA/CA** |
| 1 | **Physical (물리)** | 허브, 케이블 | - 물리적인 연결 설정 <br/> - 전기적, 기계적, 기능적, 절차적인 수단 제공 → 가장 통신 규격이 많다 | |

#### 세션 계층 (5계층)

- **지속적 인증**
    - **세션 설정 및 유지** : 사용자가 한 번 로그인(인증)을 하면, 응용 계층에서 이 인증 상태를 유지하기 위해 세션 계층의 기능을 활용하여 **세션 ID**를 발급하고 관리
    - **인증값**은 주로 **쿠키 ID**나 **세션 ID**의 형태로 전달되고, 이는 `ID, PW`와 같다.

> Router : 통신 장비, Routing : 최적 경로를 선정하는 작업, Route : 최적 경로

> LAN은 2계층으로 스위치나 허브를 사용한다. 스위치나 허브는 포워딩 장비로 데이터를 전달(포워딩, 플러딩)하는 역할을 한다. 라우터는 3계층 장비로 갈림길에서 최적의 경로를 결정하는 네비게이션 역할을 한다.

### 2. PDU (Protocol Data Unit)

#### PDU

``` text
                 ┌──────────────┐
Data        →    │     data     │
                 └──────────────┘

                 ┌──────────────┐─────────────────────────────────┐
Segment     →    │     data     │ ... │ 목적지 port │ 수신지 port │
                 └──────────────┘─────────────────────────────────┘

                 ┌──────────────────────────────────────────────┐──────────────────────────────────────┐
Packet      →    │                   Payload                    │ ... │ 목적지 IP 주소 │ 수신지 IP 주소 │
                 └──────────────────────────────────────────────┘──────────────────────────────────────┘

                 ┌───────────────────────────────────────────────────────────────────────────────────┐────────────────────────────────────────┐
Frame       →    │                                      Payload                                      │ ... │ 수신지 MAC 주소 │ 목적지 MAC 주소 │
                 └───────────────────────────────────────────────────────────────────────────────────┘────────────────────────────────────────┘
```                 

- **Data**(L7) : 응용 계층에서는 주소 정보가 없으며, 사용자 데이터 자체를 처리
- **Segment**(L4) : TCP/UDP에서 포트 번호로 응용 프로그램을 구분
- **Packet**(L3) : IP 주소를 사용해 호스트 간 전달 경로를 지정
- **Frame**(L2) : 동일 네트워크 내에서 MAC 주소를 이용해 장치 간 전송을 처리

#### 캡슐화와 역캡슐화
- **캡슐화** : 송신자 측에서 상위 계층에서 하위 계층으로 데이터가 이동하면서 제어 정보가 추가
- **역캡슐화** : 수신자 측에서 하위 계층에서 상위 계층으로 데이터가 이동하면서 제어 정보 제거

### 3. TCP/IP Protocol Stack

#### OSI 참조 모델과 TCP/IP 구현 모델 비교

|    | OSI 7계층 | TCP/IP 계층 | 실제 구현 사항 | 주요 기능 및 설명 |
| -- | -------- | ----------- | -------------- | ------------ |
| 7 | 응용 계층 (Application) |  |  |사용자 인터페이스, 응용 서비스 제공 |
| 6 | 표현 계층 (Presentation) | 응용 계층(Application) | 웹 브라우저 | 데이터 형식 변환, 압축, 암호화 |
| 5 | 세션 계층 (Session) |  |  | 세션 설정, 유지, 종료 (논리 연결) |
| 4 | 전송 계층 (Transport) | 전송 계층 (Transport) | TCP/IP Protocol | 종단 간 연결, 오류 제어, 흐름 제어 |
| 3 | 네트워크 계층 (Network) | 인터넷 계층 (Internet) | |  논리 주소(IP), 라우팅 |
| 2 | 데이터 링크 계층 (Data Link) | 네트워크 인터페이스 계층 (Network Access) | Ethernet | 물리 주소(MAC), 프레임 전송, 오류 검출 |
| 1 | 물리 계층 (Physical) |  | | 전기/광 신호 전송, 물리적 연결 |


#### TCP/IP Protocol Stack

``` text
┌────────────────────────────────────────────────┐
│ Application Layer                              │
│ ────────────────────────────────────────────── │
│ HTTP, FTP, SMTP, DNS, TELNET, SSH, etc.        │
│ 사용자와 가장 가까운 계층                       │
└────────────────────────────────────────────────┘
│ Transport Layer                                │
│ ────────────────────────────────────────────── │
│ TCP, UDP                                       │
│ 종단 간 연결, 흐름 제어, 오류 제어              │
└────────────────────────────────────────────────┘
│ Internet Layer                                 │
│ ────────────────────────────────────────────── │
│ IP, ICMP, IGMP, ARP                            │
│ 라우팅, 논리 주소(IP) 기반 전송                 │
└────────────────────────────────────────────────┘
│ Network Access Layer                           │
│ ────────────────────────────────────────────── │
│ Ethernet, Wi-Fi, PPP, MAC, Frame, Bits         │
│ 물리 매체, MAC 주소, 프레임 전송                │
└────────────────────────────────────────────────┘
```

#### 7계층 주요 프로토콜

| 프로토콜 | 전송 계층 | 기본 포트 | 용도 | 보안 여부 | 설명 |
|----------|------------|-----------|------|-----------|------|
| **HTTP** | TCP | 80 | 웹 문서 송수신 | X 평문 | 웹 클라이언트(WC)와 웹 서버(WS) 간 데이터 전송 |
| **HTTPS** | TCP | 443 | 웹 문서 송수신 | O SSL | HTTP + SSL, 인증서 기반 암호화 |
| **SHTTP** | TCP | 비표준 (예: 443, 80) | 웹 문서 송수신 | O SSH | HTTP + SSH, 키 기반 암호화 |
| **FTP** | TCP | 20, 21 | 파일 전송 | X 평문 | 명령/데이터 포트 분리 |
| **SFTP** | TCP | 22 | 암호화된 파일 전송 | O SSH | FTP over SSH, 단일 채널 |
| **FTPS** | TCP | 990 (Implicit), 21 (Explicit) | 암호화된 파일 전송 | O SSL | FTP over SSL, 복수 포트 사용 |
| **Telnet** | TCP | 23 | 원격 접속 | X 평문 | 터미널 세션 연결 |
| **SSH** | TCP | 22 | 원격 접속 | O 암호화 | 키 기반 인증 가능 |
| **SMTP** | TCP | 25 (기본), 587 (암호화), 465 (SSL) | 메일 송신 | X / O | 메일 서버 → 메일 서버 or 클라이언트 |
| **POP3** | TCP | 110 (기본), 995 (SSL) | 메일 수신 | X / O | 클라이언트가 메일 서버에서 메일 가져옴 |
| **IMAP** | TCP | 143 (기본), 993 (SSL) | 메일 수신 | X / O | 서버에 메일 보관, 클라이언트 동기화 방식 |
| **DNS** | UDP (기본) / TCP (Zone 전송 시) | 53 | 도메인 → IP 변환 | X | 도메인 네임 시스템 |
| **TFTP** | UDP | 69 | 단순 파일 전송 | X | FTP보다 간단한 구조, 인증 없음 |
| **SNMP** | UDP | 161 (요청), 162 (Trap) | 네트워크 장비 모니터링 | X | 중앙 관리자가 장비 상태 수집 |

### 실습 주제: Wireshark 사용법 익히기
- Wireshark 설치하기
    - **무차별 모드(Promiscuous mode)** : 데이터 링크 계층과 네트워크 계층의 주소 필터링을 해제한 모드 → 주소 지정 관계 없이 모든 패킷 수집 가능
    - Window에서 `Npcap` 설치로 무차별 모드 설정
- Wireshark에서 수집한 패킷 파일로 저장하기 (`.pcapng`)
- 수집한 패킷들 정보 읽기 (Packet List, Packet Detail, 
packet Bytes)
- Packet Detail에서 헤더 정보 읽기 (TCP/UDP 헤더, IP 헤더)
