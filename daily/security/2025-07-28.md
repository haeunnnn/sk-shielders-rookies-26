## 🧠 주요 개념 정리

### 1. VPC와 다른 네트워크 연결 심화

#### VPC 엔드포인트 (VPC Endpoint)
VPC 엔드포인트는 VPC 내에서 AWS의 다른 서비스에 프라이빗하게 연결할 수 있게 해주는 기능이다. 인터넷 게이트웨이, NAT 게이트웨이, 또는 VPN 연결을 거치지 않고 AWS 네트워크 백본을 통해 직접 통신하므로, 보안성과 성능이 향상된다.

- **VPC 엔드포인트 종류**
    - **인터페이스 엔드포인트 (Interface Endpoint)** : AWS 서비스에 대한 프라이빗 IP 주소를 가진 **Elastic Network Interface(ENI)** 를 VPC에 생성한다. 대부분의 AWS 서비스에 연결할 수 있다. 예를 들어, VPC의 EC2 인스턴스가 VPC 외부의 인터넷을 거치지 않고 S3에 접근할 수 있게 된다.
    - **게이트웨이 엔드포인트 (Gateway Endpoint)** : VPC의 라우팅 테이블에 엔트리를 추가하여 트래픽을 특정 AWS 서비스로 라우팅한다. 현재 S3와 DynamoDB에만 사용할 수 있다.

#### Bastion을 통한 프라이빗 노드 접근
클라우드 환경에서 보안은 매우 중요하다. 프라이빗 서브넷에 위치한 EC2 인스턴스(데이터베이스 서버, 애플리케이션 서버 등)는 외부에서 직접 접근할 수 없도록 설계된다. 이럴 때 Bastion(요새) 호스트를 사용한다.
- **Bastion 호스트** : 퍼블릭 서브넷에 위치하며, 외부에서 유일하게 접속할 수 있는 EC2 인스턴스다. 강력한 보안 그룹과 SSH 접속 관리를 통해 외부의 공격으로부터 안전하게 보호된다.
- **접근 방법**
    1. 사용자는 먼저 Bastion 호스트에 SSH로 접속한다.
    2. Bastion 호스트를 통해 프라이빗 서브넷에 있는 EC2 인스턴스에 다시 SSH로 접속한다.
- **장점** : 프라이빗 인스턴스를 외부에 노출하지 않고 안전하게 관리할 수 있다. 모든 원격 접속이 Bastion 호스트를 경유하므로, 접속 로그를 한 곳에서 관리하는 이점도 있다.

### 2. 서비스 모니터링하기
서비스 모니터링은 클라우드 환경에서 애플리케이션의 성능, 안정성, 가용성을 유지하기 위해 필수적인 작업이다.

#### 모니터링
시스템, 애플리케이션, 네트워크 등 IT 인프라의 상태와 성능 지표(CPU, 메모리, 트래픽 등)를 지속적으로 수집, 분석, 시각화하는 과정을 말한다. 문제가 발생했을 때 즉시 감지하고, 성능 저하의 원인을 파악하는 데 사용한다.

#### 주요 모니터링 항목
- **생사 모니터링** : 애플리케이션이나 서버가 정상적으로 동작하는지(Alive) 확인한다.
- **CPU 사용률** : 서버의 CPU 자원 사용량을 확인한다. 높을 경우 과부하가 발생했음을 의미한다.
- **메모리 사용률** : 서버의 메모리(RAM) 사용량을 확인한다.
- **디스크 용량** : 서버의 디스크 사용률을 확인한다. 용량이 부족하면 서비스에 문제가 발생할 수 있다.
- **네트워크 트래픽** : 서버로 들어오고 나가는 데이터의 양을 확인한다.

#### Amazon CloudWatch
CloudWatch는 AWS 리소스와 애플리케이션을 위한 모니터링 및 로깅 서비스다.

- **주요 기능**
    - **메트릭(Metrics)** : CPU 사용률, 네트워크 트래픽 등 리소스의 성능 지표를 수집하고 시각화한다.
    - **로그(Logs)** : EC2 인스턴스, Lambda 함수 등에서 발생하는 로그를 중앙에서 수집, 저장, 분석한다.
    - **알람(Alarms)** : 특정 메트릭이 설정한 임계값을 초과하면 SNS(Simple Notification Service) 등을 통해 알림을 보낸다. (예: CPU 사용률이 5분 동안 80%를 초과하면 관리자에게 이메일 전송)

#### AWS CloudTrail
CloudTrail은 AWS 계정에서 발생하는 모든 API 호출 및 이벤트를 기록하는 서비스다.

- **정의** : AWS 계정 내에서 발생한 모든 작업에 대한 기록을 제공하여 보안 분석, 거버넌스, 규정 준수, 운영 감사 등을 가능하게 한다.
- **활용** : "누가, 언제, 어디서, 어떤 리소스를 생성/변경/삭제했는지"를 파악할 수 있다. 이를 통해 보안 사고의 원인을 추적하거나, 규제 준수 여부를 감사할 수 있다.

### 3. 커스텀 도메인과 DNS
사용자가 웹 브라우저에서 친숙한 도메인 이름(예: `www.example.com`)을 입력하여 AWS의 리소스(EC2, S3 등)에 접근하려면 DNS 설정이 필요하다.

#### 도메인 이름
`www.example.com`과 같이, 사람이 읽기 쉬운 형태로 표현된 웹사이트의 주소다. 인터넷상의 모든 컴퓨터는 IP 주소(예: `192.0.2.1`)로 통신하는데, 도메인 이름은 이 복잡한 IP 주소를 대신하는 역할이다.

#### Amazon Route 53
Route 53은 AWS에서 제공하는 DNS(Domain Name System) 웹 서비스다.

- **기능**
    - **도메인 이름 등록** : `example.com`과 같은 도메인 이름을 취득할 수 있다.
    - **DNS 라우팅** : 도메인 이름에 대한 트래픽을 AWS의 다양한 리소스(EC2, S3, 로드 밸런서 등)로 라우팅한다.
    - **상태 확인 및 장애 조치** : 리소스의 상태를 확인하고, 장애가 발생하면 다른 리소스로 트래픽을 자동으로 전환한다.
- **퍼블릭 DNS와 프라이빗 DNS 비교**
    - **퍼블릭 DNS** : 인터넷상의 모든 사용자가 접근할 수 있는 도메인 이름을 관리한다. (예: `www.example.com`)
    - **프라이빗 DNS** : VPC 내부에 있는 리소스만 접근할 수 있는 도메인 이름을 관리한다. (예: `api.internal.example.com`)

#### Route 53 라우팅 정책
Route 53 라우팅 정책은 Route 53이 DNS 쿼리(예: `www.example.com`에 접속하려는 요청)에 대해 어떤 IP 주소를 응답으로 돌려줄지 결정하는 규칙을 의미해. 이를 통해 트래픽을 분산하거나, 사용자 위치에 따라 다른 서버로 연결하는 등 다양한 전략을 구현할 수 있다.

**주요 라우팅 정책 종류**
1. **단순 라우팅 (Simple Routing)**
- **설명** : 가장 기본적인 정책으로, 하나의 도메인 이름에 대해 하나의 IP 주소 또는 여러 개의 IP 주소를 무작위로 응답한다. 여러 IP 주소를 등록하면 DNS 쿼리가 들어올 때마다 응답 목록에서 무작위로 하나를 선택해서 돌려주는 방식이다.
- **사용 사례** : 트래픽이 많지 않은 단일 웹 서버나, 여러 서버에 트래픽을 균등하게 분산하고 싶을 때 사용한다.

2. **가중치 기반 라우팅 (Weighted Routing)**
- **설명** : 여러 리소스에 **가중치(Weight)** 를 부여하여, 가중치 비율에 따라 트래픽을 분산하는 정책이야. 가중치가 높은 리소스가 트래픽을 더 많이 받게 된다.
- **사용 사례**
    - **A/B 테스트** : 새로운 버전의 웹사이트(버전 B)를 10%의 사용자에게만 노출하고 싶을 때, 기존 버전(버전 A)에 가중치 90, 버전 B에 가중치 10을 부여한다.
    - **서버 성능 최적화** : 성능이 더 좋은 서버에 더 많은 가중치를 부여하여 트래픽을 집중시키고 싶을 때 사용한다.

3. **지연 시간 라우팅 (Latency Routing)**
- **설명** : 사용자에게 **가장 낮은 지연 시간(가장 가까운 거리)** 을 제공하는 리소스로 트래픽을 라우팅하는 정책이다. Route 53은 AWS의 전 세계 리전 간 네트워크 지연 시간을 측정해서, 사용자에게 가장 가까운 리전에 있는 서버로 연결해 준다.
- **사용 사례** : 콘텐츠 전송 네트워크(CDN)와 유사하게, 전 세계에 분산된 서버를 운영할 때 사용자 경험을 최적화하고 싶을 때 사용한다.

4. **지리 위치 라우팅 (Geolocation Routing)**
- **설명** : DNS 쿼리를 보낸 사용자의 **지리적 위치(국가, 대륙)**에 따라 트래픽을 라우팅하는 정책이다.
- **사용 사례**
    - **맞춤형 콘텐츠 제공** : 한국 사용자에게는 한국어로 된 웹사이트를 보여주고, 일본 사용자에게는 일본어로 된 웹사이트를 보여주고 싶을 때 사용한다.
    - **데이터 주권 준수** : 유럽의 사용자는 유럽 리전에 있는 서버로만 연결하여 데이터 저장 규제(GDPR)를 준수하고 싶을 때 사용한다.

5. **다중 응답 라우팅 (Multi-value Answer Routing)**
- **설명** : 하나의 도메인 이름에 대해 여러 IP 주소를 등록하고, 최대 8개의 상태가 정상(Healthy)인 IP 주소를 무작위로 응답하는 정책이다.
- **사용 사례** : DNS 수준에서 장애 조치 기능을 구현하고 싶을 때 사용한다. 응답 목록에 있는 리소스 중 하나에 장애가 발생하면, Route 53이 자동으로 해당 리소스를 제외하고 정상적인 리소스만 응답으로 돌려준다.

6. **장애 조치 라우팅 (Failover Routing)**
- **설명** : 주(Primary) 리소스와 보조(Secondary) 리소스를 지정하여, 주 리소스에 장애가 발생하면 자동으로 보조 리소스로 트래픽을 전환하는 정책이다.
- **사용 사례** : 고가용성(High Availability) 아키텍처를 구축할 때 필수적인 정책이다. 예를 들어, 한 리전에 있는 웹 서버가 다운되면 다른 리전의 웹 서버로 트래픽을 보내도록 설정할 수 있다.

#### Certificate Manager (ACM)
Certificate Manager는 AWS 서비스에서 사용할 SSL/TLS 인증서를 손쉽게 생성, 관리, 배포할 수 있게 해주는 서비스이다.

- **정의** : 웹사이트의 HTTPS 연결을 위한 보안 인증서를 발급하고 관리한다.
- **활용** : SSL 인증서를 웹사이트에 적용하여 사용자와 서버 간의 통신을 암호화하고 보안을 강화한다.

#### 도메인 이름 취득 및 설정 항목
- **도메인 이름 취득** : Route 53을 통해 원하는 도메인 이름을 검색하고 등록한다.
- **퍼블릭 DNS에 리소스 정보 추가** : 도메인 이름을 취득한 후, Route 53의 호스팅 영역에 레코드(A 레코드, CNAME 레코드 등)를 추가하여 도메인 이름과 리소스(로드 밸런서, EC2 인스턴스)를 연결한다.
- **프라이빗 DNS 준비** : VPC 내에서만 사용되는 도메인 이름을 위해 프라이빗 호스팅 영역을 생성하고, VPC를 연결한다.
- **SSL 서버 인증서 발행** : ACM에서 도메인에 대한 인증서를 요청하고 발급받는다. 발급된 인증서는 로드 밸런서와 같은 AWS 서비스에 쉽게 연결할 수 있다.

### 4. 클라우드 보안

클라우드 환경에서 보안은 가장 중요한 고려 사항 중 하나이다. 클라우드 보안은 단순히 기술적인 측면뿐만 아니라, 관리 및 운영적인 측면까지 포괄하는 광범위한 주제이다.

#### 보안의 3요소(CIA Triad)

- **기밀성 (Confidentiality)** : 허가된 사용자만 정보에 접근할 수 있도록 보장하는 것이다. 데이터가 무단으로 노출되거나 유출되는 것을 방지한다. (예: 데이터 암호화)
- **무결성 (Integrity)** : 데이터가 전송되거나 저장되는 과정에서 무단으로 변경되거나 손상되지 않았음을 보장하는 것이다. (예: 데이터 해시값 검증)
- **가용성 (Availability)** : 허가된 사용자가 필요할 때 언제든지 정보에 접근할 수 있도록 보장하는 것이다. 시스템이나 서비스가 중단 없이 지속적으로 운영되는 것을 의미한다. (예: 로드 밸런싱, 다중 AZ 배포)

#### 온프레미스 보안 vs 클라우드 보안

| 특징 | 온프레미스 보안 | 클라우드 보안 |
| --- | --- | --- |
| **책임 주체** | 모든 보안 책임이 기업에 있음 | AWS와 고객의 **공동 책임 모델** |
| **인프라 관리** | 기업이 자체적으로 물리적 보안부터 OS 패치까지 모두 담당 | AWS가 글로벌 데이터센터와 인프라를 안전하게 관리 |
| **보안 도구** | 기업이 직접 보안 솔루션을 구매, 설치, 관리 | AWS가 다양한 보안 서비스를 제공하여 쉽게 적용 가능 |
| **확장성** | 보안 솔루션 확장에 시간과 비용 소요 | 필요한 보안 서비스를 즉시 활성화하고 확장 가능 |

#### AWS 보안 혜택

- **글로벌 보안 인프라** : AWS는 전 세계에 분산된 데이터센터에 물리적, 기술적 보안을 적용하여 매우 높은 수준의 보안을 제공한다.
- **다양한 보안 서비스** : IAM, CloudTrail, GuardDuty 등 200개가 넘는 보안, 규정 준수, 거버넌스 서비스를 제공하여 쉽게 보안을 강화할 수 있다.
- **규정 준수** : HIPAA, GDPR, PCI DSS 등 다양한 국제 규제 및 표준을 준수하며, 고객의 규정 준수 요구를 충족할 수 있도록 지원한다.

#### 공동 책임 모델 (Shared Responsibility Model)

AWS 클라우드 보안의 핵심 원칙이다. AWS와 고객이 각각 다른 보안 책임 범위를 가진다.

- **AWS의 책임 (클라우드 '자체'의 보안)**
    - 글로벌 인프라 (리전, AZ, 엣지 로케이션)의 물리적 보안
    - 컴퓨팅, 스토리지, 데이터베이스 등 핵심 서비스의 소프트웨어 및 하드웨어 보안
    - 네트워크 및 방화벽 관리
- **고객의 책임 (클라우드 '내'의 보안)**
    - EC2 인스턴스의 운영체제, 애플리케이션, 데이터 관리 및 보안
    - IAM을 통한 접근 및 권한 관리
    - 네트워크 보안 (보안 그룹, NACL) 설정
    - 데이터 암호화 및 보호

#### AWS 보안을 고려한 설계 접근 방식

- **최소 권한 부여** : IAM을 통해 사용자에게 필요한 최소한의 권한만 부여한다.
- **보안 계층화** : 여러 보안 서비스를 활용하여 다중의 방어막을 구축한다. (예: VPC, 보안 그룹, WAF 등)
- **데이터 암호화** : 전송 중인 데이터와 저장된 데이터를 모두 암호화한다.
- **지속적인 모니터링** : CloudWatch, CloudTrail, GuardDuty를 활용하여 보안 이벤트를 지속적으로 감시한다.
- **자동화** : 보안 취약점 점검, 패치 적용 등을 자동화하여 관리 부담을 줄인다.

#### 보안 향상 고려 사항 및 AWS 주요 보안 서비스

- **백업** : 데이터 손실에 대비하여 정기적으로 백업을 수행한다. (예: EBS 스냅샷, RDS 자동 백업)
- **접근 및 권한 제어**
    - **IAM** : 사용자, 그룹, 역할, 정책을 통해 AWS 리소스에 대한 접근을 세분화하여 제어한다.
- **모니터링 및 로그 수집**
    - **로그 수집의 기본 원칙**
        1. **다양한 로그 활성화** : VPC, S3, ELB 등 여러 서비스의 로그를 활성화하여 종합적인 보안 정보를 확보한다.
        2. **중앙 집중식 관리** : 모든 로그를 CloudWatch Logs 또는 S3에 한데 모아 관리한다.
        3. **로그 분석** : 수집된 로그를 분석하여 비정상적인 활동을 감지한다.
    - **AWS 로그 수집**
        - **VPC 흐름 로그 (VPC Flow Logs)** : VPC 내의 ENI(Elastic Network Interface)를 오가는 IP 트래픽에 대한 정보를 기록한다.
        - **CloudWatch Logs** : EC2, Lambda 등 다양한 리소스의 로그를 수집, 저장, 모니터링한다.
        - **S3 액세스 로그 (S3 Access Logs)** : S3 버킷에 대한 모든 접근(Get, Put, Delete 등)을 기록한다.
        - **ELB 액세스 로그 (ELB Access Logs)** : 로드 밸런서를 통과하는 모든 HTTP/HTTPS 요청에 대한 상세 정보를 기록한다.
- **AMI (Amazon Machine Image)**
    - **AMI Hardening** : 보안 취약점 패치, 불필요한 서비스 비활성화 등 보안 규정을 충족하도록 AMI를 강화한다.
    - **보안 규정 준수** : 회사 내 보안 규정 및 요구 사항에 맞는 OS와 애플리케이션이 포함된 AMI를 생성하여 사용한다.
    - **민감 정보 점검** : AMI에 민감한 정보(비밀번호, 키)가 포함되어 있지 않은지 철저히 점검한다.
- **기타 주요 보안 서비스**
    - **AWS SSM (Systems Manager)** : EC2 인스턴스의 운영체제를 자동화하여 패치 적용, 설정 관리, 원격 명령 실행 등을 수행한다.
    - **CloudFormation** : AWS 리소스를 템플릿(코드로)으로 정의하고 배포하여, 일관되고 안전한 인프라를 구축할 수 있다.
    - **EventBridge** : AWS 서비스 및 SaaS 앱에서 발생하는 이벤트에 따라 규칙을 기반으로 다른 AWS 서비스를 실행하는 서버리스 이벤트 버스이다. 보안 이벤트에 대한 자동화된 대응에 활용된다.
    - **Amazon Inspector** : EC2 인스턴스의 보안 취약점과 규정 준수 여부를 자동으로 평가하는 서비스이다.
    - **AWS Config** : AWS 리소스의 구성 정보를 지속적으로 기록하고, 설정 변경 내역을 추적하며, 보안 및 규정 준수 규칙에 위배되는 변경을 감지한다.
    - **AWS GuardDuty** : 악성 활동 및 비정상적인 동작을 지속적으로 모니터링하여 잠재적인 위협을 탐지하는 지능형 위협 탐지 서비스이다.
    - **AWS Shield** : DDoS(분산 서비스 거부) 공격으로부터 애플리케이션을 보호하는 서비스이다.
    - **AWS WAF (Web Application Firewall)** : 웹 애플리케이션의 HTTP/HTTPS 트래픽을 필터링하여 SQL 삽입, XSS(Cross-site Scripting) 등 일반적인 웹 공격으로부터 보호한다.
    - **KMS (Key Management Service)** : 암호화 키를 생성, 관리, 보호하는 서비스입니다. 데이터 암호화에 사용되는 키를 안전하게 관리할 수 있다.
    - **Network Firewall** : VPC 내에서 네트워크 트래픽을 필터링하고 모니터링하여 악성 트래픽을 차단하는 관리형 방화벽 서비스이다.

## ❓ 궁금한 점

- **VPC 엔드포인트와 NAT 게이트웨이는 어떤 기준으로 선택해야 하며, S3 접근 시 VPC 엔드포인트의 이점은 무엇인가?**
    - 프라이빗 서브넷의 인스턴스가 외부 서비스에 접근할 때, AWS 서비스에만 접근한다면 VPC 엔드포인트를, 모든 인터넷 서비스에 접근해야 한다면 NAT 게이트웨이를 사용한다. S3 접근 시 VPC 엔드포인트는 인터넷을 거치지 않으므로 보안이 강화되고, 데이터 전송 요금이 없어 비용 효율적이다.

- **CloudWatch와 CloudTrail을 어떻게 통합하여 보안 위협을 탐지할 수 있나?**
    - CloudTrail의 감사 로그를 CloudWatch Logs로 보내고, 특정 보안 이벤트(예: 민감한 API 호출)를 감지하는 로그 지표 필터를 생성한다. 이 지표가 설정한 임계값을 초과하면 CloudWatch 알람이 트리거되어 관리자에게 실시간으로 알림을 보냄으로써 보안 위협을 즉시 감지하고 대응할 수 있다.
