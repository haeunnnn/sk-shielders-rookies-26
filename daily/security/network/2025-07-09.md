## 🧠 주요 개념 정리

### 1. 네트워크 주소 체계

- 네트워크 통신에서는 계층별로 주소 체계를 달리 사용
- 계층별 주소:
  - **2계층 (데이터 링크 계층)** : MAC Address
  - **3계층 (네트워크 계층)** : IP Address
  - **4계층 (전송 계층)** : Port Number
  - **7계층 (응용 계층)** : FQDN (도메인 이름)

#### 논리적 주소 – IP Address (3계층)
- 구성 : Network ID + Host ID
- Subnet Mask: IP 주소에서 Network ID와 Host ID를 구분하는 데 사용
- `IP address & Subnet mask = Network ID`

**내부망 vs 외부망**
- 내부망 : 송수신지의 네트워크 ID가 동일
- 외부망 : 송수신지의 네트워크 ID가 다름
- 송신자는 네트워크 ID를 기준으로 내부/외부망을 판단

#### 물리적 주소 – MAC Address (2계층)
- LAN 카드(NIC)에 고유하게 부여된 48비트 하드웨어 주소
- 구성 : OUI(제조사 식별자) + 일련 번호
- 표기 : 16진수 12자리 (`FF:FF:FF:FF:FF:FF`)
- 관리 기관: IEEE

#### 문자 주소 – FQDN (7계층)
- FQDN = Host Name + Domain Name
- 예 : `www.test.com`
- 프로토콜을 통해 제공 서비스 유형 추정 가능 (예: https → 웹)

#### 주소 매핑 프로토콜
- **DNS** : FQDN ↔ IP 주소 (조회)
- **ARP** : IP 주소 → MAC 주소 (해결)
- **RARP** : MAC 주소 → IP 주소

#### 포트 번호 – Port Number (4계층)
- 범위 : 0 ~ 65535 (0은 예약됨)
- 구분
  - **Well-Known Port** (0~1023): 대표 애플리케이션에 예약됨 (예: HTTP 80, HTTPS 443)
  - **Registered Port** (1024~49151): 등록된 애플리케이션
  - **Dynamic/Private Port** (49152~65535): 임시로 할당되며 재사용 가능
- 예: 클라이언트용 브라우저(Chrome) / 서버용 웹 서버(Apache)

#### 정리표 (요약)

| 주소 종류 | 계층 | 예시 | 특징 | 관리 기관 |
|-----------|------|------|------|------------|
| MAC | 2계층 | `00:1A:2B:3C:4D:5E` | 물리적 주소, NIC 고유 | IEEE |
| IP | 3계층 | `192.168.0.1` | 논리 주소, 네트워크 ID 포함 | IANA |
| Port | 4계층 | `80`, `443` | 애플리케이션 식별 | IANA |
| FQDN | 7계층 | `www.google.com` | 사람이 읽을 수 있는 도메인 이름 | ICANN |

### 2. 전송 모드

#### Unicast (1:1 통신)
- 단일 송신자와 단일 수신자 간 통신
- 예 : A → B에게 메일 전송

#### Broadcast (1:다수, 전체 대상)
- 네트워크 내 모든 장비에 데이터 전송
- IP Broadcast
  - **Limited Broadcast**: `255.255.255.255` (내부망 전용)
  - **Directed Broadcast**: 예) `192.168.1.255/24`
- MAC Broadcast
  - `FF:FF:FF:FF:FF:FF`

#### Multicast (1:특정 다수)
- 특정 그룹에만 전송
- Multicast IP 범위 : `224.0.0.0` ~ `239.255.255.255`
- Multicast MAC 주소
  - `01:00:5E`로 시작
  - IP 주소 기반으로 자동 생성, ARP 필요 없음

#### 전송 방식 비교

| 기준 | Unicast | Broadcast | Multicast |
|------|---------|-----------|-----------|
| 대상 | 1:1 | 1:모두 | 1:그룹 |
| 목적지 IP | 특정 호스트 IP | 브로드캐스트 IP | 224.0.0.0 ~ 239.255.255.255 |
| 목적지 MAC | 특정 NIC MAC 주소 | `FF:FF:FF:FF:FF:FF` | `01:00:5E:xx:xx:xx` |
| 처리 방식 | 대상에게만 수신 | 모든 장비가 수신 및 처리 | 그룹 가입한 장비만 처리 |
| 성능 영향 | 낮음 | 전체 네트워크 트래픽 증가 | 효율적 (그룹 대상 전송) |

### 3. ARP와 계층별 장비 이해

#### ARP (Address Resolution Protocol)

- IP 주소에 대응되는 MAC 주소를 조회하고 변환해주는 프로토콜
- 네트워크 계층(3계층)의 IP 주소를 데이터 링크 계층(2계층)의 MAC 주소로 매핑

**ARP 패킷 종류**
- **ARP Request**
  - 송신자가 수신자의 MAC 주소를 알기 위해 네트워크 전체에 브로드캐스트로 전송
  - 목적지 MAC: `FF:FF:FF:FF:FF:FF`
- **ARP Reply**
  - 수신자가 자신의 MAC 주소를 알려주는 응답 패킷
  - 유니캐스트 방식으로 송신자에게만 전송

**ARP Cache Table**
- IP ↔ MAC 대응 정보를 일시적으로 저장하는 테이블
- OS에 따라 일정 시간 후 만료됨
- 확인 명령어: `arp -a`

### 4. 계층별 장비 역할과 전송 방식

#### 장비별 역할 요약

| 장비 | 계층 | 주요 기준 | 경로 DB | 전송 방식 | 특징 |
|------|------|------------|---------|------------|------|
| Hub | L1 | 없음 | X | Flooding(항상) | 모든 포트로 전송 |
| Switch | L2 | MAC 주소 | MAC Address Table | Forwarding / Flooding | MAC 기반 전송 |
| Router | L3 | IP 주소 | Routing Table | Forwarding / Drop | 네트워크 간 연결 |

#### Forwarding vs Flooding

- **Forwarding**: 목적지 주소를 알고 있을 때, 해당 포트로만 전송
- **Flooding**: 목적지 주소를 모를 때, 송신 포트를 제외한 모든 포트로 전송
> 여기서 '포트'는 L4 포트번호가 아니라 물리적 네트워크 인터페이스를 의미

#### Hub (1계층 장비)

- 경로 데이터베이스: 없음
- 모든 수신 패킷을 전 포트로 전달 (Flooding only)
- 네트워크 트래픽이 증가하고 보안에 취약
- MAC 학습 불가능

#### Switch (2계층 장비)

- 경로 DB: MAC Address Table (형식: MAC 주소 → 출구 포트)
- 전송 방식:
  - **Forwarding**: MAC 주소가 테이블에 있으면 해당 포트로 전송
  - **Flooding**: MAC 주소가 없으면 모든 포트로 전송
- 브로드캐스트/멀티캐스트 패킷도 Flooding으로 처리 (제어 불가)
- MAC 학습 기능을 통해 지속적으로 테이블을 갱신

**동작 순서 예시**
1. 목적지 MAC 주소 확인
2. MAC Address Table 조회
3. 있으면 Forwarding, 없으면 Flooding

#### Router (3계층 장비)

- 경로 DB: Routing Table (형식: Network ID → 출구 포트)
- 전송 방식:
  - **Forwarding**: IP 주소가 테이블에 있으면 해당 네트워크로 전송
  - **Drop**: 없으면 폐기 (브로드캐스트/멀티캐스트 포함)
- 상위 계층일수록 트래픽 필터링 및 보안성 강화

**동작 순서 예시**
1. 목적지 IP 주소 확인
2. Routing Table 조회
3. 있으면 Forwarding, 없으면 Drop

#### 장비 계층별 비교

| 기능 | Hub | Switch | Router |
|------|-----|--------|--------|
| 계층 | L1 | L2 | L3 |
| 기준 주소 | 없음 | MAC | IP |
| 주소 테이블 | X | MAC Address Table | Routing Table |
| 트래픽 처리 | 모두 Flooding | Flooding / Forwarding | Forwarding / Drop |
| 브로드캐스트 처리 | 전달 | 전달 | 폐기 |
| MAC 학습 | X | 가능 | N/A |
| 대표 기능 | 단순 중계 | LAN 스위칭 | 네트워크 간 라우팅 |

#### 게이트웨이

- 서로 다른 네트워크(망)를 연결하는 장비
- 장비 예: 라우터, 멀티레이어 스위치, 방화벽
- 내부망 IP를 사용해야 하며 외부 통신을 위해 존재
- 일반적으로 라우터가 게이트웨이 역할 수행

### 5. Ping 동작 흐름

1. ARP Cache Table에서 대상 MAC 조회
2. 없다면 ARP Request 브로드캐스트
3. ARP Reply 수신 후 Cache Table에 등록
4. ICMP Echo Request 패킷 전송
5. ICMP Echo Reply 수신

- **RTT (Round Trip Time)**: Echo Request → Reply까지 걸린 시간

### 6. Media Translation (미디어 변환)

- 수행 계층: **3계층 이상 장비(Router 등)**
- 역할: 서로 다른 네트워크 간의 **프레임 헤더(L2)**를 변환
- IP 주소는 그대로 유지되지만, **MAC 주소는 경로를 거칠 때마다 변경됨**
  - 이유: 각 네트워크의 송수신 장비(NIC)가 다르기 때문
- Switch는 단순히 MAC 기반 전송, Router는 MAC 재작성 포함

**예시**:
- 출발지 → 목적지까지 중간에 Router가 있을 경우
  - 매 홉(Hop)마다 L2 헤더가 바뀜 (출발지/목적지 MAC이 중간 장비로 갱신)

### 7. 트래픽 흐름

#### 내부망
1. **DNS**를 이용하여 **수신지 IP 주소** 조회
  ① DNS 캐시 테이블 조회 (ipconfig /displaydns)
  ② Hosts.txt 파일 조회 (C:\Windows\System32\drivers\etc\hosts)
  ③ DNS 서버 (DNS Request/Response)

2. 송신지의 서브넷마스크를 이용하여 수신자 **내부망**/외부망 확인 → 송신지와 수신지의 네트워크 id가 동일한 경우 내부망

3. **ARP**를 이용하여 **수신자 MAC 주소** 조회 (내부망일 경우, 수신지의 MAC 주소를 알아내어 그대로 사용)
  ① ARP 캐시 테이블 조회
  ② ARP Request/Reply를 이용

4. 수신지로 트래픽 전송

#### 외부망
1. **DNS**를 이용하여 **수신지 IP 주소** 조회
  ① DNS 캐시 테이블 조회 (ipconfig /displaydns)
  ② Hosts.txt 파일 조회 (C:\Windows\System32\drivers\etc\hosts)
  ③ DNS 서버 (DNS Request/Response)

2. 송신지의 서브넷마스크를 이용하여 수신자 내부망/**외부망** 확인 → 송신지와 수신지의 네트워크 id가 다른 경우 외부망

3. ARP를 이용하여 **게이트웨이 MAC 주소** 조회
  ① ARP 캐시 테이블 조회
  ② ARP Request/Reply를 이용

4. **Media Translation** 방법으로 수신지로 트래픽 전송

## ❓ 궁금한 점

- **라우터를 거칠 때마다 MAC 주소가 변하는 구조로 설계한 이유는 무엇일까?**
  - MAC 주소가 변하는 구조는 일부러 그렇게 만든 설계가 아니라, **그럴 수밖에 없는 구조**이다. MAC 주소는 2계층(데이터 링크 계층)에서만 유효한 로컬 주소로, 네트워크가 라우터를 기준으로 분리되기 때문에 **각 네트워크 구간마다 새로운 MAC 주소가 필요**하다.

  - 라우터는 IP 주소를 기준으로 다음 홉을 결정한 뒤, 그 홉까지 도달하기 위해 **프레임을 새로 만들어 전송**한다. 이 과정에서 **자신의 MAC 주소를 출발지로**, **다음 홉의 MAC 주소를 목적지로** 설정하기 때문에 매 홉마다 MAC 주소가 변경된다.

  - 이 구조는 OSI 계층 모델의 **역할 분리**, **스케일 확장성**, **보안성**, **유지보수성**을 확보하기 위해 **필연적으로 도입된 설계 방식**이다.
  - 이처럼 2계층과 3계층을 명확히 분리함으로써, 네트워크의 성능·보안·관리 효율성이 높아진다.
