## 🧠 주요 개념 정리

### 1. 웹 애플리케이션 기술

#### 프론트엔드 관련

**ActiveX**
- **개념** : 마이크로소프트의 독점적인 웹 기술로, 과거 인터넷 익스플로러(IE) 환경에서 동적인 기능을 구현하기 위해 사용되었다. `ActiveX Control(.ocx)`이라는 작은 프로그램 형태로 배포된다.
- **보안 문제** : ActiveX는 OS의 커널에 직접 접근할 수 있어, 악의적인 ActiveX Control이 설치될 경우 시스템 전체에 대한 통제권을 탈취할 수 있는 심각한 보안 취약점이 있었다.
- **암호화된 첨부파일(.ocx)의 위험성**
    - **이메일 보안 솔루션의 한계** : 대부분의 이메일 보안 솔루션(수신 스캔)은 압축 파일, 첨부 파일, 링크 등을 스캔하여 악성코드를 탐지한다.
    - **탐지 우회 기법** : 하지만 **암호화된 압축 파일, 오피스 문서 암호화, 분할 압축, 이미지 파일 내 악성코드 은닉(스테가노그래피)** 등은 내용물을 스캔하기 어렵기 때문에 보안 솔루션의 탐지를 우회할 수 있다.
    - **'Un-Known' / 'Abnormal' 이벤트** : 이러한 탐지 우회 시도는 보안 관제 시스템에서 **'미확인(Un-Known)' 이벤트 또는 '비정상(Abnormal)' 이벤트**로 분류될 가능성이 높아 보안 담당자는 이러한 알람을 면밀히 확인하고, 해당 첨부파일의 발신자, 내용 등을 분석하여 위협 여부를 판단해야 한다.

**HTML5**
- **개념** : 웹 페이지를 만드는 표준 언어인 HTML의 최신 버전이다. **ActiveX와 같은 플러그인 없이** 동영상 재생, 그래픽 처리, 데이터 저장 등 다양한 기능을 웹 브라우저 자체적으로 구현할 수 있게 해준다.
- **보안 측면** : 웹 표준을 준수하기 때문에 특정 브라우저에 종속되지 않고, 액티브X와 같은 커널 접근 권한이 없어 **상대적으로 안전한 웹 환경**을 구축할 수 있다. 현재 대부분의 웹 서비스는 HTML5를 기반으로 하고 있다.

#### 백엔드 관련
**백엔드**
- **개념** : 웹 애플리케이션의 뒷단에서 사용자가 눈으로 보지 못하는 부분을 처리하는 영역이다. **사용자 요청 처리, 데이터베이스 연동, 비즈니스 로직 실행** 등을 담당한다.
- **주요 언어** : PHP, JSP(Java), NodeJS(JavaScript), ASP.NET(C#), Python 등이 주로 사용된다.
- **보안 관점** : 백엔드 시스템은 민감한 데이터와 핵심 비즈니스 로직을 다루므로, **백엔드 코드의 취약점(SQL Injection, XSS, API 취약점 등) 진단 및 보안 설정 강화**가 매우 중요하다.

**WEB 서버 vs. WAS 서버**
- **WEB 서버 (Web Server)**
    - **역할** : 주로 **정적인 콘텐츠(HTML, CSS, JavaScript, 이미지 등)** 를 사용자에게 전달하는 역할을 한다.
    - **주요 제품** : Apache, Microsoft IIS, NGINX, WebtoB 등
    - **특징** : 요청에 대한 빠른 응답이 가능하고, 부하 분산을 위한 **캐싱(Caching)** 기술(CDN, Redis 등)이 주로 활용된다.
- **WAS 서버 (Web Application Server)**
    - **역할** : 웹 애플리케이션의 **동적인 콘텐츠(데이터베이스 조회, 로그인 처리 등)를 처리**하고, 웹 서버와 데이터베이스 사이에서 비즈니스 로직을 수행한다.
    - **주요 제품** : Apache Tomcat, Oracle WebLogic, IBM WebSphere, Tmax JEUS 등
    - **차이점** : 웹 서버는 정적인 요청을 처리하는 반면, WAS는 동적인 요청을 처리하는 데 특화되어 있다. 일반적인 웹 서비스는 **웹 서버(정적 콘텐츠 처리)와 WAS 서버(동적 콘텐츠 처리)를 함께 사용**하여 효율성을 높인다.

**데이터베이스 (DB)**
- **개념** : 구조화된 데이터를 저장하고 관리하는 시스템이다.
- **애플리케이션 보안의 타겟** : 데이터베이스는 **개인정보, 고객 정보, 기업의 핵심 자산** 등 가장 중요한 정보가 저장되는 곳이므로, **애플리케이션 보안의 최우선 보호 대상**이다.
- **DB의 변천사**
    - **RDB (Relational Database)** : MySQL, Oracle, MS-SQL 등. **정형화된 데이터**를 테이블 형태로 저장하며, **안정성, 데이터 무결성, 표준화된 SQL** 언어가 강점이다. 오랫동안 사용되어 온 만큼 **'Legacy(구세대)'** DB이다.
    - **NoSQL (Not Only SQL)** : MongoDB, Cassandra, Neo4j 등. **비정형, 반정형 데이터를 대용량으로 빠르게 처리**하는 데 특화되어 있다.
        - **4가지 타입**
            - **키-밸류(Key-Value)** : Redis, DynamoDB. 키-값 쌍으로 데이터를 저장.
            - **도큐먼트(Document)** : MongoDB. JSON, XML과 같은 문서 형태로 데이터를 저장.
            - **컬럼스토어(Column-Store)** : Cassandra. 행이 아닌 열 단위로 데이터를 저장하여 대용량 분석에 유리.
            - **그래프(Graph)** : Neo4j. 데이터 간의 관계를 그래프 형태로 저장하여 복잡한 관계 분석에 유리.
    - **RDB vs NoSQL**
        - **RDB** : 안정성(ACID 트랜잭션 보장), 표준화된 SQL, 구조화된 데이터에 적합.
        - **NoSQL** : 대용량 데이터 처리 속도, 유연한 스키마, 수평적 확장 용이.
    - **블록체인과 NoSQL** : 블록체인은 모든 노드가 원장 데이터를 동일하게 가져야 하므로, **대용량 데이터를 모든 노드에 빠르게 전파**하는 능력이 중요하다. 이 때문에 NoSQL의 대용량/고속 데이터 처리 능력이 블록체인 시스템에 적합하다.
    - **최근 환경 변화** : 실시간, 대용량 스트리밍 데이터, VR/AR, NFT, 웹3.0, 5G/7G 네트워크 등 데이터의 양은 기하급수적으로 늘어나고 처리 속도는 빨라지고 있다. 이에 따라 NoSQL DB의 중요성이 더욱 커지고 있다.

#### 애플리케이션 구동 및 DB 시스템 구동
컴퓨터 시스템의 계층적 구조를 이해하면 애플리케이션과 데이터베이스가 어떻게 동작하는지 명확하게 알 수 있다.

- **최하단 (물리적 하드웨어)** : CPU, 메모리, 디스크 등 물리적인 장비가 있다.
- **클러스터링** : 여러 개의 물리적 하드웨어를 묶어서 하나의 시스템처럼 동작하게 하는 기술이다. **RAID(Redundant Array of Independent Disks)** 는 여러 디스크를 묶어 성능 및 안정성을 높이는 대표적인 클러스터링 기술이다.
- **OS (운영체제)** : 하드웨어(커널)와 직접 통신하며, 애플리케이션이 하드웨어 자원을 사용할 수 있도록 **쉘 환경**을 제공한다.
- **논리적 볼륨** : OS 위에서 하드웨어 자원을 가상화하여 C: 드라이브, D: 드라이브와 같은 논리적인 공간으로 관리한다.
- **파일 시스템** : NTFS, exFAT 등 OS가 파일을 저장하고 관리하는 방식을 규정하는 시스템이다.
- **PE (Portable Executable)** : .exe와 같은 실행 파일의 구조를 정의하는 형식이다.
- **DBMS (Database Management System)** : DB를 관리하는 소프트웨어로, DB 서버, 클라이언트, 실제 데이터베이스로 구성된다. DBMS는 OS와 통신하여 하드웨어 자원을 활용한다.

이러한 계층 구조를 이해하면, 특정 계층의 취약점(예: OS 취약점, DBMS 취약점)이 애플리케이션 전체에 어떤 영향을 미치는지 파악하기 쉽다.

#### 호스팅과 코로케이션: 인프라 서비스
- **호스팅 (Hosting)** : 서버 자원(CPU, 메모리, 디스크 등)을 임대하는 서비스이다.
    - **웹 호스팅** : 하나의 물리적 서버를 **여러 회사(Multi-Tenancy)** 가 공유하여 사용한다. 클라우드 서비스의 기본 형태와 유사하다.
    - **서버 호스팅** : 하나의 물리적 서버를 **하나의 회사(Single-Tenancy)** 가 단독으로 사용한다. 물리적 서버의 제어권을 온전히 가질 수 있어 높은 보안성과 성능이 필요할 때 사용된다.
    - **컨테이너 호스팅** : 하나의 서버에서 여러 개의 **컨테이너를 생성하여 여러 회사에 임대**하는 방식이다. 가상화보다 가볍고 빠르지만, 커널을 공유하므로 보안 취약점이 발생할 경우 더 큰 위험이 있을 수 있다.
- **코로케이션 (Colocation)** : 서버가 위치할 수 있는 **물리적 공간을 임대**하는 서비스이다. **서버 호텔(IDC, Internet Data Center)** 에 내 서버를 가져다 놓고, 그 공간(서버 랙)과 인프라(전원, 냉각, 네트워크 등)를 사용하는 것이다.
    - **제공 인프라** : 항온항습, UPS, 소화 시스템, 이중 바닥, 물리적 보안(CCTV, 경비원, 생체인증) 등 안정적인 서버 운영을 위한 모든 환경을 제공한다.

#### 온프레미스 vs. 클라우드 vs. 컨테이너: 인프라 보안의 변화
- **온프레미스 (On-Premise)** : 자체적으로 구축한 데이터센터에 서버를 두고 운영하는 방식이다.
    - **보안** : **겹겹이 방어(Defense in Depth)**와 **다중 계층 보안(Layered-Security)** 이 핵심이다. 외부에서 DB에 접속하려면 방화벽, 네트워크, 서버 등 여러 계층의 보안을 거쳐야 한다.
- **클라우드 (Cloud)** : 인터넷을 통해 컴퓨팅 자원을 빌려 쓰는 방식이다.
    - **보안** : 온프레미스처럼 겹겹이 방어 대신, **ID/PW와 같은 접근 통제**가 최우선 보안 수단이 된다. 클라우드 환경에서는 잘못된 설정 하나만으로도 데이터가 외부에 노출될 수 있어, **랜딩존(Landing Zone)** 과 같은 체계적인 보안 설계가 중요하다.
- **컨테이너** : 가상화보다 가볍고 빠른 컨테이너(Docker, Kubernetes)를 사용하는 환경이다.
    - **보안** : **프라이빗 클라우드** 형태로 내부망에 도커/K8S를 구축하여 **특정 사용자만 접속(컨소시엄)** 하도록 설정하면, 보안상 이점이 있을 수 있다. 컨테이너는 OS 커널을 공유하므로, 보안 취약점이 발생하면 여러 컨테이너에 영향을 줄 수 있어 가상화보다 보안성이 낮다는 지적도 있지만, 최근에는 컨테이너 보안 기술이 발전하면서 이 문제를 해결하고 있다.

#### 인프라와 가상화: 기반 기술의 이해
- **인프라** : 애플리케이션을 구동하기 위한 모든 기반(서버, DB, 스토리지, 네트워크, 물리적 환경 등)을 의미한다.
- **IaC (Infrastructure as Code)** : 인프라를 코드로 관리하는 기술이다. Terraform, Ansible과 같은 도구를 사용하여 인프라를 자동으로 배포하고 관리함으로써, 수동 설정으로 인한 휴먼 에러를 줄이고 효율성을 높인다.
- **서버 가상화**
    - **베어메탈 (Bare Metal)** : 물리적 서버에 OS 하나만 설치하고 애플리케이션을 구동하는 전통적인 방식이다. 성능이 가장 뛰어나지만, 자원 활용 효율이 낮다. 네이버의 **뉴로클라우드**와 같은 고성능 컴퓨팅 환경에서 사용된다.
    - **가상화** : **하이퍼바이저**를 통해 하나의 물리적 서버에 **여러 개의 OS를 설치**하여 독립적인 가상 머신(VM)을 만드는 방식이다. **독립성과 격리성**이 높아 보안성이 우수하지만, 하이퍼바이저의 오버헤드로 인해 성능 부담이 있다.
    - **컨테이너** : **도커 엔진**을 통해 하나의 OS 위에 **여러 개의 컨테이너를 생성**하여 애플리케이션을 격리한다. OS 커널을 공유하기 때문에 가볍고 빠르지만, 보안 취약점이 발생하면 다른 컨테이너에 영향을 줄 수 있다는 단점이 있다.

#### 웹 프레임워크와 웹 크롤러
- **IDE (통합 개발 환경)** : 코딩, 디버깅, 컴파일 등 개발에 필요한 모든 기능을 제공하는 소프트웨어이다.
- **웹 프레임워크** : 웹 개발에 필요한 구조와 라이브러리를 미리 만들어 놓은 것이다. 개발자는 프레임워크가 제공하는 규칙에 따라 코딩함으로써 개발 시간을 단축하고 일관성을 확보할 수 있다.
- **웹 크롤러 (Web Crawler)** : 웹 페이지를 자동으로 돌아다니며 정보를 수집하는 프로그램이다.
    - **크롤링** : 일반적으로 **정보 수집**을 의미하며, 정보의 신뢰성은 낮을 수 있다. 과거에는 무분별한 크롤링을 차단하는 것이 일반적이었지만, 최근에는 클라우드플레어와 같이 **유료로 AI 크롤러에게 데이터를 제공**하여 상호 이익을 얻는 비즈니스 모델도 등장하고 있다.
- **웹 스크래핑 (Web Scraping)** : 웹페이지의 특정 데이터를 추출하여 가공하는 기술이다.
    - **OCR (Optical Character Recognition)** : 이미지에서 문자를 추출하는 기술이다. 비대면 신분증 확인 시, 신분증 사진에서 문자를 추출하는 데 사용된다.
    - **보안 사고 예방** : OCR과 딥러닝 기술을 활용하여 **신분증 원본과 사본을 구분**함으로써, 신분증 사본을 이용한 금융 사기 등 보안 사고를 예방하는 데 활용될 수 있다.

## ❓ 궁금한 점

- **RDB와 NoSQL이 공존하는 하이브리드 데이터베이스 환경이 확산되고 있다. 이러한 환경에서 SQL Injection과 같은 전통적인 DB 취약점 외에 NoSQL 데이터베이스만의 고유한 보안 취약점에는 어떤 것들이 있으며, 각기 다른 DB에 대한 보안을 통합적으로 관리하기 위한 전략에는 무엇이 있을까?**
    - **NoSQL 데이터베이스의 고유한 취약점**
        - **NoSQL Injection** : SQL Injection과 유사하게 NoSQL의 쿼리 언어(JSON, BSON) 특성을 악용하여, 악성 코드를 삽입하거나 인증을 우회한다.
        - **스키마 없는(Schema-less) 구조** : 유연한 데이터 구조가 오히려 예외적인 데이터를 삽입하여 시스템에 오작동을 유발할 위험을 만든다.
        - **부족한 접근 제어** : RDB에 비해 초기 보안 설정이 취약한 경우가 많아, 인증 없이 외부에 노출되는 사례가 빈번하다.
    - **통합 보안 관리 전략**
        - **DB 보안 솔루션** : RDB와 NoSQL 모두에 대해 접근 제어, MFA 적용, 최소 권한 원칙을 지키고, 모든 활동을 통합 감사 로그로 기록한다.
        - **애플리케이션 계층 보안** : NoSQL Injection 방어를 위해 입력값 검증을 철저히 하고, 파라미터화된 쿼리 방식을 사용한다.
        - **데이터 암호화** : DB와 애플리케이션 간 **통신을 암호화(SSL/TLS)** 하고, DB에 저장된 민감 정보도 암호화한다.
        - **정기적 진단** : 모든 DB 시스템에 대해 주기적으로 취약점을 진단하고, 보안 설정을 최신 상태로 유지한다.

- **컨테이너 환경의 보안 취약점 (예: OS 커널 공유)을 보완하기 위해 가상화(VM) 기술을 컨테이너와 결합하는 하이브리드 접근 방식이 도입되고 있다. 이 방식은 구체적으로 어떻게 작동하며, 어떤 보안적 이점과 기술적 도전 과제를 가져올까?**
    - **하이브리드 접근 방식의 작동 원리**
        - 컨테이너의 OS 커널 공유 문제를 해결하기 위해, 가상 머신(VM)의 강력한 격리 환경 위에 컨테이너를 실행하는 방식이다.
        - Kata Containers와 같은 기술은 컨테이너마다 가볍고 빠르게 시작되는 **마이크로 VM(Micro-VM)**을 생성하여, 컨테이너의 속도를 유지하면서 VM의 격리성을 확보한다.
    - **보안적 이점**
        - **향상된 격리성** : 한 컨테이너의 취약점이 호스트 OS를 공격해도, VM 격리 덕분에 다른 컨테이너로 전파되는 것을 효과적으로 막을 수 있다.
        - **멀티테넌시 보안** : 클라우드 환경에서 여러 사용자의 컨테이너를 VM으로 분리하여, '이웃 컨테이너'의 위협으로부터 안전하게 보호한다.
    - **기술적 도전 과제**
        - **성능 저하** : 컨테이너만 사용하는 것보다 VM의 오버헤드가 추가되어 성능이 일부 떨어질 수 있다.
        - **복잡한 관리** : VM과 컨테이너를 모두 관리해야 하므로 인프라 관리의 복잡성이 증가한다. 쿠버네티스(Kubernetes) 같은 오케스트레이션 도구의 역할이 중요해진다.
        - **자원 소모 증가** : 컨테이너 실행마다 VM이 생성되어 메모리, 스토리지 등 자원 소모가 늘어날 수 있다.
