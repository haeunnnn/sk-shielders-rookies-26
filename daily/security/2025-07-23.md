## 🧠 주요 개념 정리

### 1. 이미지 저장 장소 준비하기: 스토리지, S3, S3 버킷, S3 접근 제어

데이터를 저장하는 것은 클라우드 컴퓨팅의 핵심 기능 중 하나이다. AWS에서는 다양한 스토리지 서비스를 제공하지만, 특히 **S3**는 웹에서 이미지나 파일 같은 비정형 데이터를 저장하는 데 사용될 수 있다.

#### 스토리지 (Storage)

**스토리지**는 디지털 데이터를 저장하고 보존하는 모든 형태의 장치 또는 서비스를 의미한다. 컴퓨터의 하드 드라이브부터 USB 메모리, 클라우드 공간까지 모두 스토리지에 해당한다. AWS에서는 사용 목적과 특성에 따라 다양한 스토리지 서비스를 제공한다. 예를 들어, EC2 인스턴스에 연결되는 영구적인 블록 스토리지인 **EBS**와, 여기서 설명할 객체 스토리지인 **S3**가 대표적이다.

#### Amazon S3 (Simple Storage Service)

**Amazon S3**는 인터넷 기반의 **객체(Object) 스토리지 서비스**이다. "객체"란 파일 자체와 그 파일에 대한 메타데이터(파일 이름, 크기, 생성 날짜 등)를 합쳐서 부르는 말이다. S3는 단순하면서도 강력한 웹 스토리지 서비스로 설계되었다.

- **정의** : 확장 가능하고, 저렴하며, 빠르고, 안정적이고, 사용하기 쉬운 웹 스토리지 인터페이스를 제공하는 서비스이다. 데이터를 객체 형태로 저장하며, 파일 크기 제한이 거의 없고 무제한으로 저장할 수 있다.
- **주요 특징**
    - **무제한 확장성** : 이론상 저장할 수 있는 데이터의 양에 제한이 없다. 필요한 만큼 데이터를 저장하고 검색할 수 있다.
    - **높은 내구성** : 여러 시설에 데이터를 자동으로 복제하여 99.999999999%(11-9s)의 매우 높은 내구성을 제공한다. 이는 데이터 손실 위험이 거의 없다는 의미이다.
    - **고가용성** : 데이터를 여러 가용 영역에 분산 저장하여 장애 발생 시에도 데이터에 접근할 수 있도록 한다.
    - **보안** : 강력한 접근 제어 기능과 암호화 옵션을 제공하여 데이터를 안전하게 보호한다.
    - **다양한 스토리지 클래스** : Standard, Infrequent Access, Glacier 등 데이터 접근 빈도에 따라 비용 효율적인 다양한 스토리지 클래스를 제공한다.

#### S3 버킷 (S3 Bucket)

S3는 데이터를 **버킷(Bucket)**이라는 논리적인 컨테이너에 저장한다. 버킷은 S3에 데이터를 저장하기 위한 최상위 디렉토리 또는 폴더라고 생각하면 쉽다.

- **정의** : Amazon S3에 객체를 저장하기 위한 기본 스토리지 단위이다. 모든 객체는 특정 버킷 안에 저장된다.
- **주요 특징**:
    - **고유한 이름** : 모든 S3 버킷은 AWS 내에서 **글로벌하게 고유한 이름**을 가져야 한다. 즉, 전 세계 모든 AWS 사용자가 같은 이름의 버킷을 만들 수 없다.
    - **리전 종속** : 버킷은 특정 AWS **리전**에 생성된다. 일단 생성된 버킷의 리전은 변경할 수 없다.
    - **접근 제어** : 버킷 수준에서 접근 권한을 설정할 수 있다.
    - **버전 관리** : 객체의 다양한 버전을 보존하여 실수로 삭제하거나 덮어쓴 파일을 복구할 수 있다.
- **활용** : 웹사이트 정적 콘텐츠 호스팅, 백업 및 아카이빙, 빅데이터 분석을 위한 데이터 레이크, 모바일/웹 애플리케이션의 사용자 업로드 파일 저장 등 매우 광범위하게 활용된다.

#### S3 접근 제어

S3에 저장된 데이터는 기본적으로 비공개 상태이며, 소유자만이 접근할 수 있다. 이 데이터에 대한 접근을 안전하게 관리하는 것이 매우 중요하다.

- **정의** : S3 버킷과 객체에 누가, 어떤 방식으로 접근할 수 있는지 제어하는 메커니즘이다.
- **주요 방법**
    1. **IAM (Identity and Access Management) 정책** : AWS 계정 내의 사용자, 그룹, 역할에게 S3 버킷 및 객체에 대한 세분화된 권한을 부여하는 가장 강력하고 권장되는 방법이다.
    2. **버킷 정책 (Bucket Policy)** : 특정 버킷과 그 안에 있는 모든 객체에 적용되는 JSON 기반 정책이다. 익명 사용자(Public) 접근을 허용하거나 특정 IP 주소 범위에서만 접근을 허용하는 등 복잡한 접근 규칙을 설정할 수 있다.
    3. **ACL (Access Control List)** : 버킷과 객체 수준에서 개별적인 접근 권한을 부여하는 오래된 방식이다. 간단한 접근 제어에 사용되지만, IAM 정책이 더 유연하고 강력하여 일반적으로 IAM 정책 사용이 권장된다.
    4. **S3 Pre-signed URL** : 특정 객체에 대해 짧은 시간 동안만 유효한 임시 접근 권한을 부여하는 URL을 생성하여 공유하는 방법이다.

### 2. 안전한 조작 준비하기: IAM (Identity and Access Management)

클라우드 환경에서는 누가 어떤 리소스에 접근할 수 있는지 명확히 정의하고 제어하는 것이 보안의 핵심이다. **IAM**은 이 역할을 담당하는 AWS의 핵심 보안 서비스이다.

#### IAM (Identity and Access Management)

**IAM**은 AWS 리소스에 대한 접근을 안전하게 관리하는 데 도움이 되는 웹 서비스이다. 즉, "누가(Who) 무엇을(What) 할 수 있는가(Can do)?"를 정의하는 서비스이다.

- **정의** : AWS 리소스에 대한 접근을 안전하게 제어할 수 있도록 도와주는 서비스이다. 사용자와 권한을 관리한다.
- **주요 특징**
    - **무료 서비스** : IAM 자체는 AWS 사용 비용이 발생하지 않는다.
    - **글로벌 서비스** : 특정 리전에 종속되지 않고 전역적으로 적용되는 서비스이다.
    - **최소 권한 원칙** : 사용자나 역할에게 필요한 최소한의 권한만을 부여하는 것을 강력히 권장한다.

#### IAM의 주요 구성 요소: User, Group, Role, Policy

IAM은 주로 **사용자(User)**, **그룹(Group)**, **역할(Role)**이라는 "주체"에게 **정책(Policy)**을 할당하여 권한을 부여한다.

1. **IAM User (사용자)**
    - **정의** : AWS 계정 내에서 특정 개인(개발자, 관리자 등) 또는 애플리케이션에 할당되는 영구적인 자격 증명이다.
    - **특징** : 각 사용자는 고유한 사용자 이름과 암호 또는 접근 키(Access Key)를 가질 수 있다. 기본적으로 어떤 권한도 없으며, 권한은 IAM 정책을 통해 부여된다.
    - **활용** : 특정 개발자나 운영자에게 AWS 콘솔 접근 권한이나 API 접근 권한을 부여할 때 사용한다.
2. **IAM Group (그룹)**
    - **정의** : 여러 IAM User를 묶어서 관리하기 위한 컬렉션이다.
    - **특징** : 그룹 자체에는 권한이 없으며, 그룹에 정책을 연결하면 그룹에 속한 모든 사용자에게 해당 정책의 권한이 자동으로 부여된다.
    - **활용** : "개발팀", "운영팀", "보안팀"과 같이 역할이 유사한 사용자들을 그룹으로 묶어서 권한을 일괄적으로 관리할 때 편리하다. 이렇게 하면 각 사용자에게 개별적으로 권한을 부여할 필요가 없어 관리 효율성이 높아진다.
3. **IAM Role (역할)**
    - **정의** : AWS 서비스(예: EC2, Lambda)나 외부 사용자에게 특정 AWS 리소스에 대한 임시적인 권한을 부여하는 데 사용되는 자격 증명이다. 특정 AWS 서비스나 사용자가 다른 AWS 리소스에 접근할 필요가 있을 때 "가정(Assume)"할 수 있는 권한 집합이다.
    - **특징** : 사용자에게 직접 할당되는 것이 아니라, 특정 엔티티(EC2 인스턴스, Lambda 함수, 다른 AWS 계정의 사용자 등)가 **일시적으로 해당 역할을 가정**하여 권한을 얻는 방식이다. 보안 자격 증명(비밀번호, 액세스 키)을 공유할 필요 없이 안전하게 권한을 위임할 수 있다.
    - **활용**
        - **EC2 인스턴스에 S3 접근 권한 부여** : EC2 인스턴스가 S3 버킷에 파일을 업로드해야 할 때, EC2 인스턴스에 S3 업로드 권한을 가진 IAM Role을 할당한다.
        - **Lambda 함수가 DynamoDB에 접근** : Lambda 함수가 DynamoDB 테이블에서 데이터를 읽고 써야 할 때, 해당 Lambda 함수에 DynamoDB 접근 권한을 가진 IAM Role을 연결한다.
        - **교차 계정(Cross-Account) 접근** : 다른 AWS 계정의 사용자에게 내 계정의 리소스에 접근할 수 있는 권한을 부여할 때.
4. **IAM Policy (정책)**
    - **정의** : AWS 리소스에 대한 권한을 정의하는 문서이다. JSON 형식으로 작성되며, 어떤 **액션(Action)**을 어떤 **리소스(Resource)**에 대해 **허용(Allow)**하거나 **거부(Deny)**할지 명시한다.
    - **특징**
        - **Action** : `s3:GetObject` (S3 객체 가져오기), `ec2:RunInstances` (EC2 인스턴스 시작) 등 특정 서비스의 특정 API 작업을 의미한다.
        - **Resource** : `arn:aws:s3:::my-bucket/*` (my-bucket 버킷 내의 모든 객체) 등 권한이 적용될 대상을 의미한다.
        - **Effect** : `Allow` 또는 `Deny`로, 권한을 허용할지 거부할지 정의한다.
    - **유형**
        - **관리형 정책 (Managed Policies)** : AWS에서 미리 정의해둔 정책(예: `AmazonS3ReadOnlyAccess`, `AdministratorAccess`)
        - **고객 관리형 정책 (Customer Managed Policies)** : 사용자가 직접 생성하고 관리하는 정책
        - **인라인 정책 (Inline Policies)** : 특정 IAM User, Group, Role에 직접 임베드되는 정책

IAM은 AWS 클라우드 환경에서 **"누가 무엇을 할 수 있는가"**에 대한 근본적인 보안을 제공한다. 최소 권한 원칙을 준수하여 필요한 권한만 부여하는 것이 보안 사고를 예방하는 가장 좋은 방법이다.

## ❓ 궁금한 점

- AWS에서 S3를 제공하는 핵심적인 이유가 무엇인가?
    - AWS가 S3를 제공하는 주된 이유는 무제한의 확장성과 높은 내구성 및 가용성을 가진 객체 스토리지를 비용 효율적으로 제공하기 위함이다. 이를 통해 고객은 대규모 비정형 데이터를 저장하고, 온프레미스 스토리지 관리 부담을 덜며, 다른 AWS 서비스와 쉽게 연동하여 안정적인 클라우드 애플리케이션을 구축할 수 있다.
- AM 역할(Role)이 AWS 보안 아키텍처에서 갖는 핵심적인 이점은 무엇이며, 어떤 시나리오에서 IAM 역할을 사용하는 것이 User/Group에 직접 정책을 부여하는 것보다 더 안전하고 효율적인가?
    - IAM 역할의 핵심 이점은 **"자격 증명 공유 없이 권한을 안전하게 위임"** 할 수 있다는 점이다.
    - **핵심 이점**
        - 보안 강화 : 장기적인 액세스 키 없이 임시 자격 증명을 사용하여 키 유출 위험을 줄인다.
        - 최소 권한 원칙 준수 : 필요한 권한만 역할에 부여하고, 필요할 때만 가정을 통해 얻게 한다.
        - 관리 용이성 : 한 번 정의된 역할을 여러 서비스나 주체가 재사용하여 권한 관리의 복잡성을 줄인다.
    - **더 안전하고 효율적인 시나리오**
        - **AWS 서비스 간 권한 위임** : EC2 인스턴스가 S3에 접근하거나 Lambda 함수가 DynamoDB에 접근할 때, 인스턴스/함수에 IAM 역할을 할당하여 자격 증명 관리가 필요 없도록 한다.
        - **다른 AWS 계정 간 권한 위임 (교차 계정 접근)** : 다른 계정의 사용자나 서비스가 내 계정 리소스에 접근할 필요가 있을 때, 역할의 신뢰 정책을 통해 안전하게 권한을 위임하여 자격 증명 공유 없이 접근하게 한다.
