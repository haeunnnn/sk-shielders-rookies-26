## 🧠 주요 개념 정리

### 1. 개인정보 보호법

### 1-1. 개인정보 정의 및 유형

#### 개념 설명
‘개인정보’는 **살아있는 사람을 알아볼 수 있는 모든 정보**이다. 이름, 주민등록번호처럼 직접적인 정보뿐만 아니라, 다른 정보와 결합해서 특정 개인을 식별할 수 있는 정보도 포함된다.

**예시**
- **직접 식별**: `김철수, 010-1234-5678`
- **간접 식별**: `OO아파트 101동 1202호에 사는 35세 남성, 개발자` → 다른 정보와 합치면 특정 가능

#### 하위 개념
| 구분       | 설명 | 예시 |
|------------|------|------|
| **가명정보** | 원래 정보 대신 다른 값으로 바꾸되, 필요 시 복원 가능 | 이름 ‘홍길동’을 ‘A123’로 변경하여 연구·통계 활용 |
| **익명정보** | 어떤 방법으로도 다시 식별 불가 | 설문 조사 결과에서 나이·성별·지역 제거 |

#### 쉬운 예시
- 개인정보: 학교 생활기록부, 병원 진료 기록, 쇼핑몰 구매 내역  
- 가명정보: 고객 이름을 코드로 바꾸고 구매 패턴 분석  
- 익명정보: 설문 응답에서 개인 식별 가능 요소 모두 제거  

### 1-2. 개인정보 처리 절차와 원칙

#### 개념 설명
개인정보는 **수집 → 이용 → 제공 → 보관 → 파기** 단계로 흐른다.  
각 단계에서 반드시 지켜야 할 법적 규칙이 있으며, 핵심은  
> **"필요할 때, 필요한 만큼만, 안전하게"**  

#### 핵심 원칙
1. **목적을 미리 알리고 최소한만 수집** → 이벤트 참여 목적이면 이름·연락처만 수집  
2. **목적 외 사용 금지** → 경품 응모 정보를 광고에 사용 시 위법  
3. **정확하고 최신 정보 유지** → 잘못된 주소로 배송 시 관리 부실  
4. **안전하게 관리** → 비밀번호 암호화, CCTV 접근 제한  
5. **정보주체 권리 보장** → 열람·삭제 요청 시 거부 없이 처리  

#### 생활 속 예시
- 택배사 : 배송 후 일정 기간이 지나면 주소·연락처 삭제  
- 병원 : 법정 보관 기간이 지나면 진료 기록 파쇄  
- 쇼핑몰 : 주문 처리용 정보로 마케팅하면 불법  

### 1-3. 정보주체 권리와 최신 개정사항

#### 개념 설명
‘정보주체’는 **개인정보의 주인**인 나를 뜻한다. 법은 내 개인정보를 관리·통제할 권리를 보장한다.

#### 주요 권리
| 권리 | 설명 | 쉬운 예시 |
|------|------|-----------|
| **열람권** | 내 정보 확인·사본 발급 | 은행에 신용평가 점수·산정 방식 요청 |
| **정정·삭제권** | 오류 수정·삭제 요청 | 택배사에 잘못된 주소 수정 요청 |
| **처리정지권** | 개인정보 사용 중단 요청 | 마케팅 정보 제공 중단 요청 |
| **동의철회권** | 동의 철회 | 뉴스레터 수신 거부 |
| **전송요구권** *(신설)* | 다른 기관·서비스로 내 데이터 이동 | 음악 서비스 A의 재생목록을 서비스 B로 이전 |
| **자동화 결정 대응권** *(신설)* | AI·자동시스템 결정 거부·설명 요구 | AI 면접 탈락 사유 설명 요청 |

### 1-4. 개인정보 처리 단계별 체크리스트

#### 1. 수집
- [ ] **목적 명확히 고지** (배송, 회원가입, 계약 이행 등)  
- [ ] **최소한의 정보만 수집** (불필요한 정보 요구 금지)  
- [ ] **동의서 작성** (목적·항목·보유기간·거부 시 불이익 안내)  
- [ ] **아동 정보 수집 시** 만 14세 미만은 법정대리인 동의 필수  
예시: 쇼핑몰 주문 시 이름·연락처·주소만 받고, 나이·취미는 선택사항  

#### 2. 이용
- [ ] 목적 내에서만 사용  
- [ ] 정확성 유지 (변경 즉시 수정)  
- [ ] 안전조치 적용 (접근권한·암호화·로그 기록)  
예시: 포인트 지급 명목으로 받은 정보로 광고 발송 시 위법  

#### 3. 제공(제3자)
- [ ] 사전 동의 확보 (제공자·목적·항목·기간 안내)  
- [ ] 법적 근거 없는 목적 외 제공 금지  
- [ ] 긴급 상황 예외 (생명·신체 보호 등)  
예시: 배송 목적의 정보 제공은 가능, 마케팅 업체 제공은 불법  

#### 4. 보관·관리
- [ ] 보관 기간 준수  
- [ ] 접근 제한 (필요 인원만)  
- [ ] 안전조치 (백신, 방화벽, 암호화, 물리적 잠금)  
예시: 은행이 보관기간(5년) 지난 고객 기록 계속 보관 시 과태료 대상  

#### 5. 파기
- [ ] 목적 달성·기간 만료 시 5일 이내 파기  
- [ ] 복구 불가능하게 삭제 (파일 영구삭제, 종이 파쇄·소각)  
- [ ] 법정 보존 필요 시 분리 보관  
예시: 행사 종료 후 응모자 명단 복구 불가하게 삭제  

### 2. 개인정보의 안전한 관리

### 2-1. 개인정보 안전성 확보조치

#### 개념 설명
개인정보를 다루는 기관·회사(개인정보처리자)는 정보가 **분실·도난·유출·위조·변조·훼손되지 않도록** 기술적·관리적·물리적 보안 조치를 해야 한다. → 쉽게 말해, **“내부 규칙 + 시스템 보안 + 물리적 장치”**로 3중 보호가 필요하다.

**예시**
- PC에 비밀번호 걸기, 외부 접근 차단
- 서버·DB 암호화
- 출입문 잠금, CCTV 설치

#### 주요 조치 항목
| 항목 | 설명 | 예시 |
|------|------|------|
| 내부 관리계획 | 처리 절차·책임자 지정, 정기 점검 | 연 1회 권한 점검·보안 교육 |
| 접근권한 관리 | 최소 권한, 변경 시 즉시 수정 | 퇴사자 계정 즉시 삭제 |
| 접근통제 | IP·계정 인증, VPN 사용 | 사무실 밖 DB 접근 차단 |
| 암호화 | 중요정보 암호화 저장·전송 | 비밀번호 단방향 암호화(SHA-256) |
| 접속기록 보관 | 1~2년 이상 기록·점검 | 대량 다운로드 탐지 |
| 물리적 보안 | 시설·문서 보관 잠금 | 서버실 외부인 출입 통제 |

### 2-2. 접근권한·접근통제·암호화

#### 접근권한
- “1인 1계정” 원칙, 공유 금지
- 권한 변경·말소 내역 3년 이상 보관  
**예시**: 마케팅팀은 연락처만, 회계팀은 결제정보만 접근 가능

#### 접근통제
- 외부 접속 원칙적 차단
- VPN·OTP 등 안전 인증 사용
- 장시간 미사용 시 자동 로그아웃  
**예시**: 고객센터 PC는 업무망과 인터넷망 분리

#### 암호화
- 전송 시 SSL/TLS 적용
- 저장 시 DB·이동식 매체 암호화
- 암호키 안전 생성·보관·파기  
**예시**: USB에 고객정보 저장 시 암호화 필수

### 2-3. 개인정보 유출 통지와 대응

#### 개념 설명
개인정보가 유출·분실·도난되면 **72시간 이내** 통지·신고.

- **통지 대상**: 정보주체(개인)
- **신고 대상**: 개인정보보호위원회 또는 KISA

**통지 내용**
- 유출 항목
- 유출 시점·경위
- 피해 최소화 방법
- 대응·구제 절차
- 담당 부서 연락처

**예시**
- 1,000명 이상 정보 유출 → 신고 의무
- 주민번호·민감정보 유출 → 신고 의무
- 해킹으로 인한 유출 → 신고 의무

### 2-4. 개인정보 파기

#### 개념 설명
보유기간 경과·목적 달성 시 **5일 이내** 복구 불가하게 파기해야 한다. 법정 보존 의무 시 분리 보관한다.

**생활 예시**
- 회원 탈퇴 시 이름·연락처 즉시 삭제
- 결제 기록 5년 보관 후 파기

**잘못된 사례**
- ‘영구 보관’ 동의는 위법
- 추가 보관 시 별도 동의 필요

### 2-5. 기타 주요 사항
- **개인정보 처리방침**: 처리 목적, 항목, 보유기간, 안전조치, 권리 행사 방법 공개
- **CCTV 관리**: 설치 목적 법적 정당성 필요, 열람·제공 시 동의 또는 법적 근거 필요
- **위수탁 관리**: 업무 위탁 시 계약·감독 필수

#### 정리 포인트
- 안전성 확보조치 = **내부 관리 + 시스템 보안 + 물리적 보안**
- 접근권한·암호화는 기술적 보호의 핵심
- 유출 시 **72시간 내 통지·신고**
- 파기는 기한 준수·동의 절차 필수

### 2-6. 개인정보의 안전한 관리 체크리스트

#### 1. 내부 관리계획
- [ ] 절차·책임자·점검 주기 문서화
- [ ] 연 1회 이상 보안 교육
- [ ] 권한 변경·말소 이력 관리  
예시: 매년 1월 절차 문서 갱신 + 전 직원 교육

#### 2. 접근권한 관리
- [ ] 최소 권한 원칙
- [ ] 1인 1계정, 공유 금지
- [ ] 퇴직·이동 시 권한 회수
- [ ] 권한 변경 기록 3년 보관  
예시: 마케팅팀은 연락처만, 결제정보 접근 불가

#### 3. 접근통제
- [ ] 외부 접속 차단
- [ ] VPN·OTP 등 인증 적용
- [ ] 장시간 미사용 자동 로그아웃
- [ ] 허가된 IP만 접근 허용  
예시: 고객센터 PC 업무망 전용

#### 4. 암호화
- [ ] 중요정보 저장 시 암호화
- [ ] 전송 구간 SSL/TLS 적용
- [ ] 암호키 안전 관리
- [ ] 이동식 매체 암호화 필수  
예시: USB 고객명단 암호화 프로그램 사용

#### 5. 접속기록 관리
- [ ] 1~2년 이상 기록 보관
- [ ] 월 1회 이상 점검
- [ ] 대량 다운로드·이상 접속 알림 설정  
예시: 월말 DB 접근 로그 점검 후 보고

#### 6. 물리적 보안
- [ ] 서버실·문서보관실 잠금·출입기록 관리
- [ ] 외부인 출입 제한
- [ ] CCTV 설치 시 법 준수  
예시: 서버실 출입 승인자만 가능, 출입카드 기록 6개월 보관

#### 7. 유출 대응
- [ ] 유출 시 72시간 이내 통지·신고
- [ ] 통지: 항목·시점·경위·대응 안내
- [ ] 신고: 개인정보보호위원회 또는 KISA  
예시: 1,000명 이상 유출 시 전원 이메일·문자 통보 + KISA 신고

#### 8. 파기
- [ ] 목적 달성·기간 만료 시 5일 이내 파기
- [ ] 복구 불가능하게 삭제
- [ ] 법정 보존 시 분리 보관  
예시: 탈퇴 시 즉시 삭제, 결제기록 5년 보관 후 삭제

### 3.개인정보 유출·노출 예방 정리 노트

### 3-1. 개인정보 유출·노출 개념

#### 개념 설명
- **유출**: 법적 근거 없이 또는 동의 없이 개인정보가 **내부 통제 범위를 벗어나 제3자에게 넘어간 상태** → 해킹, 계정 탈취, 내부자 무단 반출 등
- **노출**: 개인정보가 **인터넷이나 게시물 등에 공개되어 누구나 볼 수 있는 상태** → 게시판, 댓글, 첨부파일, 이미지 등에 포함된 개인정보가 그대로 보이는 경우

#### 중요성
- 주민번호, 여권번호, 운전면허번호, 카드번호, 계좌번호, 지문·얼굴 등 **민감정보 노출 시 2차 범죄**(명의도용·보이스피싱 등)로 이어질 가능성 크다

**생활 예시**
- 유출: 병원 직원이 USB에 환자 정보 담아 집으로 가져갔다가 분실
- 노출: 동호회 홈페이지에 회원 이름·전화번호 포함 파일 업로드

### 3-2. 유출·노출 시 필수 대응

#### 72시간 내 통지·신고
- 정보주체(개인)에게 알리고, **1,000명 이상** 또는 **민감/고유식별정보 유출** 시 **KISA·개인정보보호위** 신고

#### 노출 즉시 조치
- 페이지 비공개·삭제
- 검색엔진 삭제 요청, 로봇배제 규칙 적용
- 서버·PC 백신 최신화, 계정·로그 점검, 접속경로 차단

#### 필수 안내 내용
- 유출 항목, 시점·경위, 피해 최소화 방법, 대응 절차, 담당 부서 연락처
- **예시**: 해킹으로 고객 이름·연락처 5천 건 유출 → 문자·이메일 통보, KISA 신고, 홈페이지 30일 공지

### 3-3. 유출·노출 원인과 사례

| 원인 | 사례 | 예방 방법 |
|------|------|----------|
| 외부 공격 | DB 관리자 페이지 공격, APT, 피싱 | 관리자 페이지 IP 제한, VPN·OTP, 강력 비밀번호 |
| 내부자 고의 | 지인 부탁으로 유출, 퇴사자 계정 사용 | 최소권한 부여, 퇴사 시 계정 말소, 다운로드 사유 점검 |
| 과실 | 단체 메일 주소 전체 공개, 첨부파일 개인정보 포함 | 메일 개별 발송, 첨부파일 사전 점검·마스킹 처리 |
| 기술 설정 미흡 | 인증 없이 관리자 페이지 접근, URL 값 변경 시 타인 정보 조회, 디렉토리 리스팅 | 접근제어 강화, URL 개인정보 사용 금지, 디렉토리 리스팅 차단 |

### 3-4. 개인정보 노출 예방 수칙

#### 운영자 5계명
1. 게시판 운영 시 개인정보 노출 주의 안내
2. 개인정보 포함 글·댓글은 비공개
3. 불가피 시 마스킹(이름 일부, 전화번호 뒷자리 `***` 등)
4. 첨부파일 게시 전 개인정보 포함 여부 확인 (숨겨진 시트, 메모, 이미지 등)
5. 정기적으로 노출 여부 점검 (검색어: "주민", "전화", "여권" 등)

#### 개발자 6계명
1. 관리자 페이지 내부망·VPN·OTP 보호
2. 게시판 비공개/비밀글 기능 적용
3. URL·소스코드에 개인정보 사용 금지
4. URL 식별자 숨김 처리 (GET → POST)
5. 홈페이지 개편 시 소스코드 취약점 점검
6. 디렉토리 리스팅 차단

#### 정리 포인트
- **유출** = 통제권 상실 / **노출** = 공개 상태
- 내부자 고의·실수도 주요 위험
- 예방 = 기술(접근제어·암호화) + 관리(권한·교육) + 점검(모니터링)
- 신고·통지·삭제는 **72시간 이내**

## 💻 실습 내용

### 실습 주제 1: Security for AI를 주제로 AI와 개인정보 처리 관련 조별 토론
- "자동처리되는 개인정보 보호 가이드라인 (2020. 12월)" 을 읽고 내용 정리
    - 문서 개요
        - **발행 목적**
            - IoT, AI, 빅데이터 환경에서 개인정보가 **실시간으로 자동처리**되는 경우 흐름 파악이 어렵고, 침해 발생 시 피해가 크므로 **사전예방**이 필요하다.
            - 이를 위해 기획 단계부터 **Privacy by Design(PbD)**을 적용하여 개인정보 보호를 강화하는 방안을 제시.
        - **주요 내용**
            - 자동처리 개인정보 보호 **10대 수칙**
            - 각 수칙별 **적용 사례**
            - **PbD 개념**과 **국내·외 정책사례**
    - **개인정보 보호 10대 수칙**
        1. 필요한 개인정보인지 확인 : 목적·범위 정의, 불필요한 수집 방지
        2. 수집 시 법적 준수사항 확인 : 동의 의무·법적 근거 확보
        3. 최소한의 개인정보 처리 : 익명·가명 처리, 정기 점검
        4. 안전조치 적용 : 접근권한 최소화, 암호화
        5. 절차·방법 투명 공개 : 처리방침, 시각 자료 제공
        6. 권리행사 보장 : 열람·정정·삭제 요청 용이
        7. 제3자 제공·위탁 안내 : 항목·목적·제공자 명확 고지 후 동의
        8. 해지 시 파기·추가수집 방지 : 장치 회수·작동 중지
        9. 종료 시 권리 보장 : 이전 통지, 백업 기능 제공
        10. 출시 전 위험요소 점검 : 변경 시 추가 점검 포함
    - **PbD (Privacy by Design)** : '프라이버시를 고려한 설계’로, 침해 발생 후 조치하는 것이 아니라 **사전에 예방**하는 개념. 서비스 기획·설계 단계에서부터 프라이버시 위협을 예측·방지. → 기능성과 편리성을 해치지 않으면서 전 과정에서 개인정보 보호 내재화.
        - Privacy by Design 7대 기본 원칙
            1. 사전예방 (Proactive not Reactive) : 침해 발생 후 조치가 아니라 사전에 위험을 예측·방지
            2. 기본설정 보호 (Privacy as the Default) : 시스템 기본값에서 최대한 개인정보 보호
            3. 설계 내재화 (Embedded Privacy into Design) : 설계 단계에서 프라이버시를 구조적으로 포함
            4. 기능·보호 균형 (Positive-Sum) : 기능성과 프라이버시 보호를 동시에 만족
            5. 전 생애주기 보호 (End-to-End Security) : 수집~파기 전 단계까지 보호
            6. 투명성 (Visibility and Transparency) : 처리 과정·정책을 명확히 공개
            7. 이용자 중심 (Respect for User Privacy) : 이용자가 자신의 정보에 대한 통제권 보유

## ❓ 궁금한 점

- **개인정보의 안전성 확보 조치인 접근권한(최소 권한 원칙)과 접근통제(IP 제한, VPN 등)를 기업은 어떻게 기술적으로 구현하고 관리하는가? 특히, 퇴사자 계정 삭제나 권한 변경 이력 보관은 어떻게 이루어지나?**
    - 기업은 **Active Directory(AD)**와 같은 중앙 집중형 시스템을 이용해 접근권한을 관리한다. 이 시스템은 사용자의 직무와 직급에 따라 권한을 그룹화하고, 인사 시스템과 연동하여 직원의 입·퇴사나 부서 이동 시 권한을 자동으로 부여하거나 회수한다. 퇴사자 계정은 인사 시스템에서 퇴사 처리 시점에 맞춰 자동으로 비활성화되거나 삭제된다. 모든 권한 변경 이력은 **접근 관리 시스템(IAM)**에 로그 형태로 기록되어 3년 이상 보관되며, 이는 내부 감사의 중요한 근거 자료가 된다.
    - 접근통제는 방화벽, VPN 등의 네트워크 보안 기술로 구현한다. 방화벽을 이용해 허가되지 않은 IP의 접근을 차단하고, 외부 접속이 필요할 경우 VPN을 통해 암호화된 통신 터널을 만들어 안전하게 접속하도록 한다.
- **정보주체의 권리가 확대되면서 기업은 기술적·관리적 부담을 안게 되는데, **'전송요구권'**이나 **'자동화 결정 대응권'**을 보장하기 위해 어떤 시스템을 구축해야 하나요?**
    1. **전송요구권 보장**
    기업은 사용자의 데이터를 안전하고 효율적으로 전송하기 위해 표준화된 **API(Application Programming Interface)**를 구축해야 한다. 이 API는 금융, 의료 등 마이데이터 생태계에서 사용되는 표준 형식에 맞춰 데이터를 제공하며, 사용자가 어떤 데이터를 누구에게 전송할지 동의했는지 관리하는 시스템도 필수적이다.
    2. **자동화 결정 대응권 보장**
    AI나 알고리즘에 의한 결정에 대해 소명하려면 설명 가능한 AI(XAI) 기술을 도입해야 한다. 이를 통해 AI가 특정 결정을 내린 이유와 영향을 준 주요 데이터를 구체적으로 설명할 수 있어야 한다. 또한, AI가 내린 결정의 주요 변수와 데이터를 기록하고 보관하는 시스템을 마련하여, 사용자의 소명 요청에 논리적이고 구체적인 설명을 제공할 수 있도록 준비해야 한다.
