## 🧠 주요 개념 정리

### 오전 워밍업: 보안 커리어 만들기

#### 해킹 공부와 어필 방법
- **CTF (Capture The Flag)** : 해킹 실력을 겨루는 대회로, 웹, 시스템, 리버싱 등 특정 분야의 취약점을 찾아 깃발(Flag)을 획득하는 게임 형식
    - **스페셜리스트 지향** : CTF는 특정 분야의 깊이 있는 기술을 요구하기 때문에, **'이거 하나를 엄청 잘하고 싶다'**는 목표를 가진 **스페셜리스트(Specialist)**에게 적합한 공부 방법이다.
    - **공부 분야** : 리눅스/윈도우 OS, 리버스 엔지니어링, 모바일/클라우드/IoT 해킹 등 다양한 분야를 다룬다.
    - **리버스 엔지니어링** : 역공학이라고도 하며, 컴파일된 프로그램의 원본 소스 코드를 분석하고 동작 원리를 파악하는 기술이다.
- **해킹 방어 대회 (블루팀)** : 공격(레드팀)에 대응하여 시스템, 네트워크, DB 등을 방어하고 침해사고를 분석, 대응하는 능력을 겨루는 대회이다.
    - **제너럴리스트 지향** : 다양한 시스템과 솔루션을 다루며, 침해사고 대응, 재발 방지 대책 수립 등 **보안 전문가(제너럴리스트)**가 알아야 할 전반적인 지식을 습득하는 데 도움이 된다.
    - **'주특기(하나)'** : 제너럴리스트로서 넓은 지식을 갖추되, 특정 분야(예: 웹 해킹, 악성코드 분석)에 대한 **자신만의 강점(주특기)**을 만드는 것이 좋다.
    - **'책걸이'** : 어떤 분야든 꾸준히 파고들어 한 권의 책이라도 끝까지 보는 것이 중요하다는 의미로, 깊이 있는 학습을 강조하는 표현이다.
- **포트폴리오** : 취업 시 자신의 역량을 보여주는 문서이다.
    - **Worst** : 단순히 사용 가능한 기술 스택을 나열하는 방식이다. AI 이력서 필터링에 걸릴 확률이 높다.
    - **Best** : **'기획-실행-결과-배움'**의 과정을 담아내는 것이다. 'IoT CCTV 해킹을 시도하다 실패했지만, 이 과정에서 어떤 기술을 배우고 어떤 역할을 했는지'를 구체적으로 서술하면, **기획력, 추진력, 협업 능력, 문제 해결 능력**을 어필할 수 있어 면접관의 관심을 끌 확률이 높다.
- **버그바운티 (Bug Bounty)** : 기업이 외부 해커에게 자사 시스템의 취약점을 찾아달라고 의뢰하고, 발견 시 포상금을 지급하는 제도이다.
    - **모의 해킹과의 차이점**
        - **모의 해킹** : 계약된 전문가가 정해진 기간 내에 특정 범위의 시스템을 진단한다. 정보 수집 시간을 줄이기 위해 내부 정보(네트워크 구성도, 주요 자산 등)를 제공받는 경우가 많다.
        - **버그바운티** : 불특정 다수의 화이트 해커가 참여하며, 정보 수집부터 취약점 발견까지 모든 과정을 스스로 진행해야 한다. 따라서 정보 수집에 가장 많은 시간이 소요된다.
- **해킹 실력 증폭** :
    - **기본기** : OS 및 시스템 기본 지식, 악성코드 동작 원리, 침투 시나리오 개발 능력 등이 중요하다.
    - **침해사고 분석 환경** : 현장에서 주로 사용하는 `Sysinternals` 도구나 웹 프록시 도구인 `Burp Suite` 등을 활용하여 실제 침해사고를 분석하는 연습을 하는 것이 좋다.
    - **침해사고 사례 분석** : **KISA(한국인터넷진흥원) CERT, 금융보안원 CERT** 등에서 발행하는 침해사고 분석 보고서를 꾸준히 읽어보며, 신입으로서 간접 경험을 쌓는 것이 매우 중요하다.
- **공격자와 방어자의 비대칭성**
    - **공격자** : '골대가 매우 넓고, 시간과 자원이 풍족한 상황'에서 공격을 한다. 다양한 공격 방법 중 성공 가능성이 높은 하나의 취약점만 찾아내면 된다.
    - **방어자** : '골대가 넓고, 시간과 자원(사람, 솔루션)이 부족한 상황'에서 방어를 한다. 모든 공격 경로를 막아야 하므로, 방어에 훨씬 많은 노력이 필요하다.
    - **방어 전략** : 이러한 비대칭성을 극복하기 위해 **자동화, 화이트리스트(허용된 것만 통과), 보안 솔루션 도입, 보안 인식 개선** 등이 중요하다.
- **보안의 역할**
    - **일반** : '우리 회사만 안전하면 돼'라는 폐쇄적인 목표를 가질 수 있다.
    - **보안** : '우리 국가 전체가 안전해야 해'라는 거시적인 관점을 가져야 한다. 외주 위수탁, 보안 교육, 오픈소스 등 **이해관계자 전체의 보안 수준을 함께 높여야**만 진정한 안전을 확보할 수 있다.

### 1. 침해사고 분석: 사이버 킬체인
- **침해사고 결과 보고서** : 해킹 사고가 발생하면 발행되는 보고서로, **사고의 원인, 공격 흐름, 대응 과정, 재발 방지 대책**이 담겨 있다.
    - **케이스 스터디** : 이 보고서들은 '케이스 스터디'의 좋은 자료가 됩니다. 해커들의 공격 흐름에 **공통점**이 있기 때문이다.
- **사이버 킬체인(Cyber Kill Chain)** : 록히드 마틴이 제안한 해킹 공격의 7단계 모델이다.
    1. **Reconnaissance (정찰)** : 공격 대상에 대한 정보 수집
    2. **Weaponization (무기화)** : Exploit(취약점 공격 코드)과 백도어를 결합
    3. **Delivery (전달)** : 무기화된 파일을 피해자에게 전달
    4. **Exploitation (공격)** : 취약점을 이용해 악성코드 실행
    5. **Installation (설치)** : 악성 프로그램 설치
    6. **Command & Control (C&C)** : 원격 조작 채널 확보
    7. **Actions on Objectives (목표 달성)** : 최종 목적(정보 탈취, 시스템 파괴 등) 달성
    - **활용** : 해킹 사고 분석 시, 해당 공격이 킬체인의 어느 단계에 해당하는지 파악하고, **어느 단계의 체인을 끊어야 가장 효과적으로 방어할 수 있는지**를 분석하는 데 활용된다.
- **공격 흐름의 특징**
    1. **최초 침투 경로** : 대부분의 해킹 사고는 **사람(일반 임직원)**의 PC에서 시작된다. IT/보안팀보다 보안 인식이 낮은 일반 직원을 대상으로 한 피싱, 악성코드 유포가 주요 침투 경로이다.
    2. **계정 탈취** : 과거의 `Brute Forcing(무차별 대입)` 방식 대신, **`Credential Stuffing(크리덴셜 스터핑)`**이 대세이다. 다크웹 등에서 유출된 계정 정보를 이용해 다른 서비스에 로그인하는 방식이다. 이는 **다크웹이 우리 삶 깊숙이 자리 잡고 있음을 의미**하며, `전국민이 해커가 되는 길`이라는 표현은 누구나 쉽게 해킹 정보를 접할 수 있는 현 상황을 경고한다.
    3. **공격 그룹의 문화** : 해킹 코드에는 해커의 국적, 문화, 습관 등이 담겨 있다. **악성코드 코드의 유사도, 함수 선언 방식, 언어 인코딩 타입** 등을 분석하면 공격 그룹을 추정할 수 있다. 이를 통해 **공급망 보안(Supply Chain Security)**에도 활용될 수 있다. `IoCs(Indicators of Compromise)`를 공유하고, 특정 그룹의 공격 패턴을 미리 파악하여 방어하는 방식이다.
    4. **'중이 제 머리 못 깎는다'** : 보안 솔루션 업체가 오히려 내부 보안에 취약한 경우가 많다. 이는 외부 비즈니스에만 집중하고, 내부 보안 관리에 소홀하기 때문이다. 이러한 취약점을 노린 공급망 공격(Supply Chain Attack)이 증가하면서 **ISMS 의무화** 등 외주 업체의 보안 관리 기준이 강화되고 있다.
- **추가 단어**
    - **C&C (Command & Control)** : 악성코드가 설치된 좀비 PC를 원격에서 조종하기 위한 통신 채널
    - **.scr (스크린세이버 파일)** : 실행 가능한 파일의 확장자로, 악성코드를 숨기는 데 자주 사용됨
    - **살라미 어택 (Salami Attack)** : 아주 작은 금액을 여러 계좌에서 조금씩 빼내어 모으는 해킹 수법. 마치 햄을 얇게 써는 것 같다고 해서 붙여진 이름
    - **소버린 AI (Sovereign AI)** : 특정 국가나 기업이 독자적으로 주권을 가지고 개발하고 통제하는 AI
    - **'쉘을 딴다'** : 운영체제에 대한 명령어를 내릴 수 있는 권한을 획득하는 것을 의미
    - **SSL-VPN** : SSL/TLS 암호화 기술을 사용하는 원격 접속 방식
    - **쉘 히스토리(Shell History)** : 사용자가 터미널에 입력한 명령어 기록. 해킹 시 공격자의 흔적을 찾는 중요한 단서.
    - **WORM (Write Once, Read Many)** : 한 번 기록하면 수정이나 삭제가 불가능한 저장 매체.
- **전자금융감독규정 해설서** : 금융권 보안의 핵심 법규인 '전자금융감독규정'에 대한 상세한 설명서이다. 금융 보안 전문가라면 **반드시 숙지해야 할 내용**이므로, **출력해서 암기 수준**으로 공부하라는 조언이 있었다.

## 💻 실습 내용

### 실습 주제 1: LM Studio(LLM) 실습
- **LM Studio(LLM)** : PC 로컬 환경에서 대규모 언어 모델(LLM)을 구동할 수 있게 해주는 소프트웨어입니다.
- **RAG (Retrieval-Augmented Generation)** : 외부 지식(문서, DB 등)을 검색(Retrieval)하여 LLM의 답변을 보강(Augmented)하는 기술입니다.
- **실습 환경 구성** :
    - **목표** : 외부(코랩)에서 내부 로컬(LM Studio)의 LLM에 접근하여 인터페이스를 구성하는 것.
    - **문제점** : 코랩은 외부 클라우드 환경이므로, 내부 PC의 `localhost` 주소를 직접 인식할 수 없습니다.
    - **해결책** : `ngrok`과 같은 **터널링(Tunneling)** 서비스를 사용합니다. `ngrok`은 로컬 서버(LM Studio)를 외부에서 접근할 수 있는 공개 URL로 연결해주는 역할을 합니다.
    - **프롬프트 분석** :
        1. **LM Studio를 로컬 LLM으로 지정** : 로컬 PC에 LM Studio를 설치하고 모델을 구동합니다.
        2. **Colab을 개발 환경으로 지정** : 코랩에서 파이썬 코드를 작성하고 실행합니다.
        3. **ngrok 터널링 연결** : `ngrok`을 사용하여 LM Studio의 로컬 서버를 코랩이 접근할 수 있도록 공개 URL로 노출합니다.
        4. **화면 인터페이스 구현** : `Gradio`나 `Streamlit`과 같은 시각화 라이브러리를 사용하여 LLM과의 대화가 가능한 웹 기반 인터페이스를 코랩에 구성합니다.
- **보안적 관점** :
    - **망분리 환경 RAG** : 금융회사와 같이 망분리된 환경에서는, 외부 인터넷과 분리된 내부망에서 RAG를 구축해야 합니다. 이 실습은 이러한 **'Mini RAG' 프로젝트**의 원리를 이해하는 데 도움이 됩니다.
    - **ngrok의 보안성** : `ngrok`은 로컬 서버를 외부에 노출시키므로, 보안에 주의해야 합니다. 공개 URL을 통해 외부 공격자가 로컬 서버에 접근할 수 있기 때문입니다.
