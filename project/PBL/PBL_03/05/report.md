# 사내망 구성도 분석 및 설명 보고서

## 1. 과제 개요 및 목표
본 과제는 제시된 사내망 구성도를 상세히 분석하여 **인터넷존(Internet Zone), DMZ(Demilitarized Zone), 인트라넷존(Intranet Zone)**의 세 가지 주요 영역을 명확히 구분하고, 각 영역에 배치된 네트워크 장비들의 특징과 역할, 그리고 해당 장비들이 그 위치에 배치된 이유를 설명하는 데에 중점을 둔다. 더 나아가, 현 구성도를 바탕으로 내가 네트워크를 구성한다면 어떤 장비를 추가하거나 제거할지 합리적인 근거와 함께 제시하여 네트워크 설계 및 보안에 대한 이해도를 심화하고자 한다.

## 2. 문제 상황 및 요구사항 재확인
- **문제 상황** : 제시된 사내망 구성도를 세부적으로 분석한다.
- **요구사항**
    - 인트라넷존, 인터넷존, DMZ의 영역으로 나누어 망 구성도를 설명한다.
    - 각 영역에 배치된 장비들의 특징과 해당 장비들을 배치한 이유를 설명한다.
    - 본인이 망을 구성한다면 어떠한 장비를 추가 또는 제거할 것인지를 이유를 붙여 설명한다.

## 3. 사내망 구성도 분석 및 설명
제시된 사내망 구성도를 바탕으로 각 영역을 구분하고 장비들의 역할을 분석했다.

### 3.1. 영역별 망 구성 및 장비 배치
사내망은 크게 **인터넷존(Internet Zone), DMZ(Demilitarized Zone), 인트라넷존(Intranet Zone)** 의 세 가지 영역으로 구성되어 있으며, 각 영역은 보안 수준과 역할에 따라 분리된다. 핵심 경계에는 **방화벽(Firewall)**이 위치하여 트래픽을 제어한다. 특히, 이 사내망은 주요 장비 및 연결 경로가 **이중화 구조**로 구성되어 있어 **고가용성(High Availability)**을 확보하고 있다.

#### 3.1.1. 인터넷존 (Internet Zone)
- **정의** : 기업의 통제 범위 밖에 있는 공공 네트워크인 인터넷 영역이다. 직접적인 보안 위협에 노출되는 최전방 구간이다.
- **주요 장비**
    - **인터넷** : 불특정 다수와 연결되는 광역 네트워크.
    - **라우터(Router)** : 외부 인터넷과 사내 네트워크(방화벽 앞단)를 연결하는 관문 역할. IP 패킷의 경로를 결정하고 전달한다. (이중화 구성)

#### 3.1.2. DMZ (Demilitarized Zone)
- **정의** : 인터넷존과 인트라넷존 사이에 위치한 완충 지대이다. 외부 사용자에게 웹 서비스 등 공개 서비스를 제공하지만, 인트라넷존의 보안을 위해 별도로 분리된 영역이다. DMZ 내 시스템이 침해되더라도 인트라넷존으로의 직접적인 접근은 어렵도록 설계된다.
- **주요 장비**
    - **웹 방화벽(WAF - Web Application Firewall)** : 웹 서버로 향하는 트래픽을 전문적으로 검사하여 SQL Injection, XSS(Cross-Site Scripting) 등 웹 애플리케이션 계층 공격을 탐지하고 차단한다. 일반 방화벽이 막지 못하는 공격 유형에 특화되어 웹 서비스의 보안을 강화한다.
    - **DMZ 스위치** : DMZ 영역 내의 서버와 L4 스위치 등 장비들 간의 통신을 담당하는 스위치이다. 인트라넷존 스위치와는 논리적 또는 물리적으로 분리되어 트래픽 격리 및 보안을 유지한다.
    - **L4 스위치(Load Balancer)** : 여러 웹 서버나 파일 전송 서버로 외부 트래픽을 효율적으로 분산하여 특정 서버에 부하가 집중되는 것을 방지한다. 또한, 서버 장애 시 트래픽을 자동으로 우회시켜 서비스의 **고가용성(High Availability)**을 보장한다.
    - **웹 서버(Web Server)** : 기업의 웹사이트를 호스팅하며 외부 사용자에게 웹 서비스를 제공한다.
    - **파일 전송 서버(File Transfer Server)** : 외부 사용자와의 파일 업로드/다운로드 서비스를 제공한다. (FTP 서버 등)
    - **NAS 스토리지(Network Attached Storage)** : 웹 서버나 파일 전송 서버에서 사용하는 비정형 데이터나 파일을 저장하고 공유하는 네트워크 스토리지 장비이다.

#### 3.1.3. 인트라넷존 (Intranet Zone)
- **정의** : 기업 내부 사용자들만 접근할 수 있으며, 기업의 핵심 자산과 민감한 정보가 보관되는 가장 보안이 중요한 영역입니다. 외부로부터 철저히 격리되고 보호됩니다.
- **주요 장비**
    - **IDS(Intrusion Detection System)** : 네트워크 트래픽을 실시간으로 감시하여 비정상적인 활동이나 알려진 공격 패턴을 탐지하고, 관리자에게 경고를 보낸다.
    **IPS(Intrusion Prevention System)** : IDS와 유사하게 공격을 탐지할 뿐만 아니라, 이를 자동으로 차단하는 능동적인 방어 시스템이다. 인트라넷존으로의 침투를 1차적으로 막는 데 중요한 역할을 한다.
    - **백본 스위치** : 인트라넷존의 중심 스위치로, 고속의 대용량 트래픽을 처리하며 여러 하위 스위치(L3, L2 스위치)들을 연결하여 네트워크의 전반적인 성능과 연결성을 보장한다.
    - **L3 스위치** : 백본 스위치 하단에 연결되어 있으며, IP 주소를 기반으로 라우팅 기능을 수행한다. 주로 각 부서(영업지원팀, 정보기획팀)별로 네트워크를 **논리적으로 분리(VLAN)**하고, VLAN 간의 트래픽 라우팅 및 보안 정책 적용을 담당한다.
        - **L2 스위치** : L3 스위치 하위에 연결되어 각 팀의 최종 사용자 장비(PC, 프린터 등)를 직접 연결하는 액세스 스위치이다. MAC 주소를 기반으로 프레임을 전달한다.
            - **영업지원팀 L2 스위치** : 영업지원팀 사용자들의 네트워크 접근을 담당한다.
            - **정보기획팀 L2 스위치** : 정보기획팀 사용자들의 네트워크 접근을 담당한다.
    - **내부 서비스 서버** : 그룹웨어, ERP, 인트라넷 등 내부 직원들의 업무에 필요한 다양한 서비스를 제공하는 서버이다. 외부에서는 직접 접근할 수 없다.
    - **DB 서버** : 기업의 가장 중요한 핵심 데이터를 저장하고 관리하는 서버이다. 최고 수준의 보안과 접근 제어가 요구된다.
    - **SAN 스위치(Storage Area Network Switch)** : DB 서버와 SAN 스토리지를 연결하는 전용 고속 스위치이다. 이를 통해 데이터 전송의 효율성과 안정성을 극대화한다.
    - **SAN 스토리지(Storage Area Network Storage)** : DB 서버와 같이 블록 레벨 액세스가 필요한 고성능 애플리케이션을 위한 중앙 집중식 스토리지 시스템이다. 대량의 데이터를 빠르고 안정적으로 처리하는 데 특화되어 있다.

#### 3.1.4. 방화벽 (Firewall)
- **위치 및 역할** : 인터넷 라우터 바로 밑에 위치하며, 인터넷존과 DMZ/인트라넷존의 경계에서 모든 인바운드/아웃바운드 트래픽을 제어하고 보안 정책을 적용하는 핵심 장비이다. 허용된 트래픽만 통과시키고, 불필요하거나 악의적인 트래픽을 차단하여 네트워크를 보호한다. 이 구성도에서는 DMZ 영역과 인트라넷존 영역으로 트래픽을 안전하게 분기하는 역할을 수행하고 있다.

### 3.2. 각 영역에 장비 배치 이유 및 특징
각 네트워크 장비는 해당 영역의 특성과 보안 요구사항, 성능, 가용성, 관리 효율성 등을 종합적으로 고려하여 배치된다.

- **라우터** : 외부 인터넷과의 연결 지점인 동시에 네트워크 최상단에서 IP 기반의 경로를 결정하는 게이트웨이 역할을 수행하므로 인터넷존에 배치된다.
- **방화벽** : 네트워크의 모든 트래픽을 검사하고 제어하는 '보안 관문' 역할을 한다. 외부 위협으로부터 DMZ와 인트라넷존을 보호하고, 인트라넷존의 중요한 자산을 보호하기 위해 가장 중요한 경계 구간에 위치하게 된다. 이와 같은 방식을 다층 방어(Defense in Depth) 전략이라고 한다.
- **DMZ 장비 (웹 방화벽, L4 스위치, 웹 서버, 파일 전송 서버, NAS 스토리지)** : 이 장비들은 외부 사용자에게 직접 서비스를 제공해야 하므로 DMZ에 배치된다. DMZ는 외부 공격에 직접 노출될 수 있으므로, 해당 서버들이 침해되더라도 인트라넷존으로의 확산을 방지하기 위해 인트라넷존과 철저히 분리된다. 웹 방화벽과 L4 스위치는 웹 서비스의 보안과 가용성을 극대화하기 위해 웹 서버 앞에 배치된다.
- **IDS/IPS (인트라넷존 입구)** : 방화벽을 통과한 트래픽 중에서도 잠재적인 위협을 탐지하고 능동적으로 차단함으로써, 인트라넷존으로의 최종적인 침투를 막는 2차 방어선 역할을 한다.
- **백본 스위치, L3/L2 스위치 (인트라넷존)** : 인트라넷존의 대량 트래픽을 고속으로 처리하고, 각 부서별 네트워크를 논리적으로 분리(VLAN)하여 트래픽 관리의 효율성과 보안을 높인다. 계층적 스위치 구조는 네트워크의 확장성과 관리 용이성을 제공한다.
- **내부 서비스 서버, DB 서버, SAN 스위치, SAN 스토리지 (인트라넷존)** : 기업의 핵심 업무 시스템과 가장 민감한 데이터가 위치하는 장비들이다. 따라서 외부로부터의 직접적인 접근이 불가능하도록 최고 수준의 보안이 적용되는 인트라넷존에 배치되게 된다. DB 서버는 특히 중요하여 전용 SAN 스위치와 SAN 스토리지를 통해 고성능과 안정적인 데이터 접근을 보장받는다.

### 3.3. 영역별 장비 요약 표

| 영역 | 장비 | 주요 특징 / 배치 이유 |
| ---- | ---- | ------------------- |
| 인터넷존 | 라우터 | 인터넷 연결, 경로 결정, 이중화 |
| DMZ | 웹 방화벽 | 웹 공격 방어 |
| DMZ | L4 스위치 | 트래픽 분산, 고가용성 제공 |
| DMZ | 웹 서버 | 웹 서비스 제공 |
| 인트라넷존 | IDS/IPS | 침입 탐지/차단 |
| 인트라넷존 | 백본 스위치 | 인트라넷존 중심, 고성능 트래픽 처리 |
| 인트라넷존 | DB 서버 | 핵심 데이터 보관, 최고 보안 요구 |
| 인트라넷존 | SAN 스토리지 | 고성능 데이터 저장, DB와 연결 |
| 공통 | 방화벽 | 영역 간 트래픽 제어, 보안 정책 적용 |
| 공통 | 이중화 | 단일 장애 제거, 서비스 연속성 확보 |

### 3.4. 이중화(Redundancy) 구성
제시된 사내망 구성도는 주요 장비 간의 연결이 두 갈래로 되어 있으며, 같은 장비들이 중복으로 배치되어 있다. 이는 **이중화 구성**을 의미하며, 네트워크의 **고가용성(High Availability)**과 **안정성(Reliability)**을 확보하기 위한 핵심적인 설계 원칙이다.
- **목적**
    - **단일 장애 지점 제거** : 네트워크 내 한 장비나 링크에 장애가 발생하더라도 전체 서비스가 중단되는 것을 방지할 수 있다.
    - **서비스 연속성 확보** : 장애 발생 시 자동으로 다른 경로 또는 다른 장비로 트래픽이 우회되어 서비스 중단 없이 계속 운영될 수 있도록 한다. 이는 기업의 비즈니스 연속성(Business Continuity)에 매우 중요하다.
    - **부하 분산 및 성능 향상** : 경우에 따라서는 두 경로를 동시에 사용하여 트래픽을 분산함으로써 네트워크 처리량을 높이고 성능을 향상시키는 효과도 있을 수 있다.
- **적용 장비** : 구성도에서 라우터, 방화벽, 백본 스위치, SAN 스위치 등 네트워크의 핵심 경로에 위치하는 장비들이 이중화되어 있다. 이러한 장비들은 장애 발생 시 서비스에 치명적인 영향을 줄 수 있으므로, 중복 구성이 필수적이라고 볼 수 있다.
    - **라우터 이중화** : 외부 인터넷과의 연결이 끊어지는 것을 방지하여 인터넷 접속 가용성을 높인다.
    - **방화벽 이중화** : 외부 공격으로부터의 방어선 역할을 하는 방화벽이 단일 지점이 되어 전체 네트워크의 보안이 취약해지는 것을 막고, 방화벽 자체의 장애 시에도 보안 정책이 계속 적용되도록 한다.
    - **백본 스위치 이중화** : 인트라넷존의 핵심 트래픽 경로가 되는 백본 스위치의 장애는 내부 서비스 전체에 영향을 줄 수 있으므로, 이중화를 통해 내부 통신의 안정성을 보장한다.
    - **SAN 스위치 이중화** : DB 서버와 스토리지 간의 데이터 경로를 이중화하여, 대량의 데이터 I/O 작업 중 발생할 수 있는 스위치 장애로부터 핵심 데이터베이스의 가용성을 보호한다.
- **작동 방식** : 일반적으로 액티브-스탠바이(Active-Standby) 방식 또는 액티브-액티브(Active-Active) 방식으로 작동한다. 액티브-스탠바이는 평소 하나의 장비만 작동하고 다른 하나는 대기 상태에 있다가, 장애 시 대기 장비가 활성화되는 방식이다. 액티브-액티브는 두 장비가 동시에 트래픽을 처리하며 부하 분산과 동시에 장애 대응을 하는 방식이다. 이중화된 연결은 이러한 방식들이 원활하게 작동할 수 있도록 물리적인 경로를 제공한다.

## 4. 망 구성 시 추가 또는 제거할 장비
제시된 구성도는 견고한 사내망의 기반을 제공하지만, 보안 동향과 네트워크 효율성, 관리 편의성 측면을 고려하여 다음과 같은 장비의 추가 또는 통합을 제안하고자 한다.

### 4.1. 추가할 장비 및 이유
#### 1. 차세대 방화벽 (Next-Generation Firewall, NGFW) 도입
- **위치** : 현재 방화벽 역할을 대체하거나 보강하는 역할로, 라우터와 DMZ/인트라넷존 사이
- **이유** : 기존 방화벽은 주로 IP 주소와 포트 번호 기반의 패킷 필터링에 중점을 두지만 최신 공격은 애플리케이션 계층에서 이루어지거나, 정상 트래픽으로 위장하는 경우가 많다. **NGFW**는 애플리케이션 인식 및 제어, 사용자 기반 정책 적용, 통합 위협 관리(IDS/IPS, 안티바이러스, 웹 필터링, VPN 등 기능 통합) 등 훨씬 고도화된 보안 기능을 제공한다. 이를 통해 지능형 지속 위협(APT)이나 제로데이 공격에 대한 방어 능력을 강화하고, 복잡한 보안 위협에 대한 가시성과 제어력을 향상시킬 수 있을 것이다. 현재 IDS/IPS가 별도로 있지만, NGFW는 이들을 통합하여 관리 편의성과 보안 효율성을 높일 수 있다.

#### 2. 보안 정보 및 이벤트 관리 시스템 (SIEM - Security Information and Event Management)
- **위치** : 인트라넷존 내 별도의 보안 관리 서버 영역
- **이유** : 네트워크 내 모든 장비(방화벽, IDS/IPS, 서버, 스위치, 애플리케이션 등)에서 발생하는 수많은 보안 로그 및 이벤트를 중앙에서 수집, 정규화, 분석, 상관관계 분석하도록 한다. 이를 통해 실시간으로 보안 위협을 탐지하고, 분산된 로그들 간의 패턴을 분석하여 공격의 전체적인 흐름을 파악하며, 이상 징후 발생 시 관리자에게 신속하게 경고하여 즉각적인 대응이 가능하도록 도울 수 있다. 현재 구성도에서는 로그 통합 관리 및 분석 시스템이 명시되어 있지 않아 보안 가시성이 제한될 수 있을 것 같다.

#### 3. 중앙 집중식 백업 및 재해 복구 시스템 (Centralized Backup & DR System)
- **위치** : 인트라넷존 내 별도의 백업 서버 및 스토리지 영역, 그리고 DR(재해 복구)을 위한 외부 백업 사이트
- **이유** : 현재 NAS 스토리지와 SAN 스토리지가 데이터를 저장하지만, 이들은 주 운영 스토리지이다. 데이터 유실, 랜섬웨어 공격, 자연재해, 시스템 전면 장애 등 심각한 상황에 대비하여 정기적이고 자동화된 백업 및 복구 시스템을 구축하는 것은 비즈니스 연속성 확보에 필수적이다. 이는 핵심 데이터를 보호하고, 최악의 시나리오에서도 서비스를 빠르게 복구할 수 있는 능력을 제공할 것이다.

### 4.2. 제거 또는 통합을 고려할 장비 및 이유
#### 1. 개별 IDS 및 IPS 장비의 통합 (NGFW 도입 시)
- **이유** : 만약 앞서 제안한 **차세대 방화벽(NGFW)**을 도입하여 보안 기능을 통합한다면, 기존의 개별 IDS 및 IPS 장비는 제거하거나, 특정 고도화된 분석을 위한 보조적인 역할로 축소할 수 있다. 이는 네트워크 장비의 수를 줄여 관리 복잡성을 대폭 감소시키고, 유지보수 비용을 절감하며, 보안 정책을 단일 지점에서 일관되게 적용할 수 있게 한다.

#### 2. NAS 스토리지 (DMZ)의 역할 재조정 또는 통합
- **이유** : DMZ 내 NAS 스토리지의 역할과 필요한 성능을 다시 생각해볼 필요가 있다. 만약 웹 서버나 파일 전송 서버가 대규모의 고성능 데이터 액세스를 필요로 하거나, 데이터의 중요도가 매우 높다면, 인트라넷존의 SAN 스토리지 시스템을 DMZ로 안전하게 확장하거나, DMZ 내에 별도의 고성능 SAN 스토리지를 구축하는 것을 고려할 수 있다. 이를 통해 스토리지 아키텍처를 단순화하고, 데이터 액세스 성능 및 확장성, 데이터 무결성 보호 측면에서 더 효율적인 구성을 확보할 수 있을 것이다. (하지만 웹/파일 서버의 특성상 NAS가 더 적절할 수도 있으므로, 이는 데이터의 특성과 요구 성능에 따라 유연하게 결정해야 한다.)

### 4.3. 추가 및 제거 제안 장비 비교표

| 구분 | 장비 | 현재 구성과의 차이점/개선점 | 기대 효과 (보안, 성능, 관리) |
| ---- | --- | ------------------------- | -------------------------- |
| 추가 | 차세대 방화벽  | 애플리케이션/사용자 기반 제어 | 지능형 위협 방어, 관리 효율 |
| 추가 | SIEM | 통합 로그 분석 부재 | 실시간 위협 탐지, 가시성 확보 |
| 추가 | 백업/DR 시스템 | 주 스토리지의 단점 보완 | 데이터 보호, 비즈니스 연속성 |
| 통합/제거 | 개별 IDS/IPS | 통합 관리의 어려움 | 관리 복잡성 감소, 비용 절감 |
| 통합/제거 | NAS (DMZ) | 고성능 필요 시 부족  | 스토리지 아키텍처 최적화 |

## 5. 결론
제시된 사내망 구성도는 인터넷존-DMZ-인트라넷존의 3계층 아키텍처와 주요 장비의 **이중화 구조**를 통해 기본적인 네트워크 보안 및 고가용성을 잘 확보하고 있다고 볼 수 있다. 특히, 방화벽을 통한 경계 제어, 웹 방화벽을 통한 웹 서비스 보호, IDS/IPS를 통한 인트라넷존 침입 방지 부분은 잘 설계된 부분이라고 생각한다.

하지만, 급변하는 사이버 위협 환경과 효율적인 네트워크 관리를 고려할 때, **차세대 방화벽 도입**을 통한 통합 보안 기능 강화, **SIEM 시스템 구축**을 통한 보안 가시성 확보, 그리고 **중앙 집중식 백업 시스템 구축**을 통한 비즈니스 연속성 강화는 필수적인 개선 사항이라고 생각된다. 이러한 추가/개선을 통해 해당 기업의 네트워크는 더욱 안전하고 지능적인 위협에 효과적으로 대응하고, 안정적인 IT 서비스 운영을 보장할 수 있을 것이다.
